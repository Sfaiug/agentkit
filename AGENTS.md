# agentkit, for an agent working on it

## What ak is for

ak builds whatever you want, with AI models doing the work. You state an intent and get the finished result, live, for any project, on any machine, with any model. It always takes one path: intent → alignment → build → review → live, and what breaks live comes back in as a new intent. Alignment is the only part done with you: from 0 to 1 together, until the goal is clear and checkable; from 1 to 100 alone, asking only what only you can answer. One model builds, another reviews, round after round until the work passes, and nothing ever gets stuck: whatever fails recovers by itself.

Every change to ak is judged by what it does for what you build with it, and by these four rules:

1. **Less.** Use the fewest features, steps, options and concepts that reach the goal. The best part is no part, and the best process is no process. ak decides everything it can and never offers a choice it could make itself. It explains itself in plain words, so nobody needs a manual. If an addition is not a clear yes, it is a no.
2. **Quality, then speed, then cost.** Quality is the result doing what you asked and staying that way. The ideal is the best result, instantly, for nothing. When two of these pull apart, the one earlier in this list wins.
3. **Models are fuel; ak is the car.** ak stays the same while models and the programs that run them come and go. It runs whichever is best at the time and depends on none. Swapping one changes quality, speed and cost, never whether the intent gets delivered.
4. **ak enforces; words only explain.** Nothing depends on a model remembering an instruction or judging well on its own. A rule that can be a check, gate or hook is one, and it holds whatever model runs. A rule that lives only in text is unfinished.

This section changes only with the owner's yes. Every other line has one home, and ak's instruction files a word maximum that only goes down; ak's orchestrators improve the rest on their own.

## Working here

- Python 3.11 standard library and bash. No dependency is added, ever.
- One test file per behaviour: `python3 tests/test_<name>.py`, run straight, no runner.
- The `tests:` gate (`tests/landing.py`) runs `bash tests/smoke.sh` beside `tests/every_file.py` (remaining `tests/test_*.py`; see its docstring). Either failure fails it. `AK_SHARD=k/N` selects both parts' k-th share (1-based); unset or `1/1` runs all. It refuses Python that 3.11's grammar refuses, f-strings aside: a newer `python3` accepts f-strings 3.11 rejects (`f"{data["key"]}"`), so `python3.11 -m py_compile` what you touch that holds one. Dependent checks stay together; each piece has a tmux safety guard and sandbox. `AGENTKIT_ACCEPTANCE_REQUIRED=1` makes skips fail; supported network namespaces allow only loopback.
- Match the file's style. Read `ARCHITECTURE.md` first; a change that adds, removes, renames or moves a module updates the map. Any task may lower a `max` in `tests/test_boundaries.py` in the area it touches, and no task raises one.
- `docs/guide.md` follows code changes. `README.md` holds only what ak is, installation and starting.
- `orchestrator.md` is the rulebook an agentkit session is launched with, not a file for here.

## Lessons

Mistakes earlier work here made that no check catches and no one area of the code holds. One that becomes a check, or a comment at the code it is about, leaves this list.

- Never start the landing suite (`tests/landing.py`, `tests/smoke.sh`, `tests/every_file.py`). When wording changes, grep tests/ and fix assertions pinning it.
- Comments say why. Listing screens go through `agentkit/terminal.py` (`docs/cli-design.md`).
- Each run has a memory cap (exit 137). Commit before a test sweep; run only the files your change touches, three at most at once; background one only under `timeout -k 30 20m`, read before your turn ends.
- Tests never touch real processes, units, seats, transcripts or state: fake process tables and tmux, injected kill/systemctl (`_proc_table()`, `AK_HOST_READINGS`), a temporary HOME. A test calling `run.review`, `run.execute` or a sweep in-process clears `AGENTKIT_RUN`, `AK_PARENT_RUN`, `AK_RUN_LOG` and sets `AK_RUN_DEPTH=0`, `AK_MAX_RUNS=0`, or a refusal SIGTERMs your own run.
- Commands call `bin/ak`, never bare `ak`. A changed signature: update every mock and fake of it in tests/; a fake takes `**_kw` for what it ignores.
- agentkit is public: tests, docs and commits use invented names (`acme`, `fix-api`), never a real checkout, product or seat.
- A final check stopped for silence names the hung process after `still running:`: fix the hang on your branch, or hand in blocked if origin/main hangs too; gate changes are their own task.
- Decide from exit codes and files, never another program's output text, except the stop hook's `?` at a turn's end.
- Never re-create another system's semantics for an input nobody uses (Linux's path walk inside Git trees, for a linked AGENTS.md): every review round found one more difference. Refuse the input plainly instead.
- A test never asserts a plain word is absent from output that prints paths: worktree paths carry the run's title. A test never asserts a wall-clock duration (under 100 ms, say): host load breaks it at landing. Inject the clock and assert what it read: `tests/fixtures/sandbox.py` and `tests/fixtures/clock.py` say how.
- When review keeps finding races or recovery paths, delete state or simplify the design.
- A task or PR promises only what its code decides, in the code's own terms ("has read or write access", not "can open"): a reviewer measures every word, and each wider one costs findings.
- A module removed from agentkit ends every run still on the old install at its next lazy import (`ImportError`, seen when `tell.py` went): keep the module whole until no run of the old install is left, then delete it.

## Owner rules

- A turn whose last message ends in `?`, with nothing asked through the question prompt, is sent back once; no model reads prose. Reason: the best part is no part. [19 Oct 2026]
- Terminal input and output keep moving when both fill at once, for every model and harness, in the shared transport. Held by `tests/test_seat_transport.py`. [8 Oct 2026]
- A Muse seat keeps its own question tool: its question pages the owner and the seat waits for the answer, until a Muse version lets a hook catch that tool, as Codex's does. Reason: Muse 1.4.7 runs the tool past every PreToolUse hook, and the only way to remove it is a launch allowlist of every tool, which stops a seat from opening once Muse renames one and drops its todos and skills. [13 Oct 2026]
- Codex pairing is optional and requested when the owner wants app access; opening or resuming a seat sends no setup alert. Optional access does not need the owner or block terminal work. [7 Oct 2026]
- Models are plugins the owner marks: adding a model or harness is an adapter, its toml and a `models.toml` entry, never a name hard-coded in code, and `n` keeps the orchestrator question so the owner can switch freely. ak scores every model and effort the installed harnesses offer per role on quality and cost alone, from the public boards whose numbers export (Artificial Analysis, Arena Agent, LiveBench): a row within `within` points of the best counts as as good, the cheapest of those is recommended, the rest beside it, and the owner marks; speed is ak's to fix and subscriptions follow the choice. Among the marks ak picks in that order, across every account of its provider, the seat's own last, the next once it is spent or cannot run; the model that wrote the work reviews it only when no other marked reviewer has room, and a reviewer from the same company counts as any other. ak's own run numbers show beside the rank and never rank; there is no `ak trial` or in-house skill test: a suite of our own would spend quota on a small, noisy sample and go stale with every release. Reason: the marks were intuition; ranked on quality alone, the smartest row took every role at twelve times the cost of one the boards cannot tell from it; a stronger reviewer catches more than a different company does while its separate turn already gives the fresh context. [18 Sep, 28 Sep, 29 Sep, 14 Oct, 18 Oct]
- ak is measured by what it delivers in every project: `ak run status --history` shows quality, speed, cost and size week by week, work on ak itself counts as cost, and these numbers never pick a model; what the board measures is pinned by `tests/test_scoreboard_measures.py`, so it changes only with the owner's yes and a visible test change. [2 Oct, 14 Oct]
- No fixed capacity numbers: every limit (runs at once, gate turns, memory) is derived from the machine ak runs on, for any user; correctness locks (one merge per repository) are not capacity and stay. [23 Sep, 28 Sep]
- Only a person opens a seat, and a seat keeps its conversation: `ak orch` with no terminal opens none; Claude seats run with `/background`'s daemon off. Stray seats paged the owner; the daemon mixed them up. The one exception is the `audit` seat, which the tick opens with `[audit]`'s models for the week's largest loss or a stall it found, so ak improves itself without the owner; the owner closing it keeps it closed. [4 Oct, 14 Oct, 17 Oct]
- After a reboot only seats owing work come back. Reason: after the 17 Oct reboot the owner closed by hand those owing nothing. [17 Oct 2026]
- Done means live: a project's `health:` line says how to tell its live product works, and a merged change counts as done once that passes with the change deployed; what breaks live comes back in by itself. [2 Oct]
- The owner sees only what needs them or a finished job, and is paged only for an unanswered question (never while in that seat), a failure only they can fix (an expired login, a seat ak cannot reopen, a run nothing else can move), a login ending within 3 days (daily) or the whole finished job, once, for every harness and model; the page carries the question or the result itself, its first sentence first. Internal probes and late news of finished jobs never page. Of every line on a screen ask "what would the owner do with it?"; if nothing, it goes. The system cleans up after itself. Reason: probe setup and repeated completion cards interrupted the owner with nothing new; idle prompts, unsent drafts and stuck runs paged them, and the card said only `Needs you · seat`. [15 Sep, 18 Sep, 7 Oct, 14 Oct 2026]
- A seat shows one of four words: `working` (something moves without the owner: a turn, its runs, a wait, a retry, a spent usage window ak resumes), `needs you` (only the owner can unblock it: a question or permission on its screen, its own `ak notify needs`, an expired login, a failure no seat handles), `done` (its whole job is finished and live, until the owner has been in the seat since) and `idle` (nothing running, asked or owed: a new seat, a conversation that ended, a turn the owner stopped, a seat they closed). Text in the composer never changes the word; once the owner has left the seat the reason adds `unsent: …`. A worker token expiring soon is a line on the ak screen, not a word. The word follows the real change within about 2 seconds, on every harness. Reason: seats read `needs you` for idle prompts, drafts and answered questions, and stale for minutes. [14 Oct 2026]
- The ak screen is the one the owner approved on 14 Oct 2026 (the live mock at https://claude.ai/artifact/GmF6YMPHJtN3Z2mggbumGt, version 6): one row per seat with its word, its own model and, while it has a plan, a smooth line of how much is done with `N of M`. No screen names a task, and no row names who builds or reviews. The row the owner points at, with the pointer or ↑/↓, opens one line under itself: the question for `needs you`, what got done for `done`, otherwise who builds and who reviews and each task in flight as three squares (build, review, land: blue while a model works on it, gray while it waits, with no mark). No tip replaces the key line. A seat's own bar is that row with its line always open, and it stays still. Colour says where a thing stands; a company's colour shows only while the pointer is on its subscription's meter, filling it and lighting every model on screen that runs on it. Something moves only while a model works on it, once when it changes, or under the pointer. The usage stays at the top and the keys at the bottom; more seats than fit turn pages with ←/→, and a project with no seat shown has no heading. Reason: a selected question filled the screen and pushed the usage off it, the tips at the bottom only repeated the row, who builds, who reviews and each task's step crowded the row, and ended runs stayed as red squares. [14 Oct, 19 Oct 2026]
- Every screen follows `docs/cli-design.md`: plain words that explain themselves, every glyph followed by its word (⚒ builds and ◎ reviews excepted), nothing cut mid-sentence, the same back, forward and exit keys everywhere. [15 Sep, 16 Sep, 18 Oct]
- Landing: each repository declares its own suite, and ak runs it once, at landing, for the passed changes landing together, each tested on top of those ahead; a round runs only the task's own checks, and there is no test-selection engine. The suite reaches nothing beyond loopback; checks needing the outside world (`LIVE_CHECKS` in `tests/suite_shares.py`, run by `tests/live.sh`) run before the host takes new code and when a harness upgrades. Finished work waiting to land goes first, and landing takes about one suite time. Held by `tests/test_repo_suite.py`, `test_suite_in_round.py`, `test_landing_suite_offline.py`, `test_merge_train.py` and `test_gate_landers.py`. [16 Sep, 25 Sep, 1 Oct, 2 Oct, 3 Oct, 5 Oct]
- The orchestrator builds, by the who-does-the-work cases in `orchestrator.md`; marked executors take only independent pieces sharing no file with its work, and ak moves no work for quota. Every change lands through the one path, the orchestrator's own included: review rounds, its tests and the landing line; only a diff of documents alone skips review. A behaviour change needs a test that fails on the old code, which ak proves where it can and never fails a round for. A FAIL is fixed by a fresh fixer session on the model that wrote the PR, never by the seat, whose conversation is the owner's. Held by `tests/test_own_pr_line.py`, `test_own_pr_fixer.py`, `test_regression_fails_before.py`, `test_followup_runs.py` and `test_review_own_pr.py`. [1 Oct, 2 Oct, 3 Oct, 4 Oct, 7 Oct, 13 Oct, 14 Oct, 16 Oct]
- A change's first review takes at most 400 added lines, a seat's own pull request's and a task's alike (deletions and unchanged moves never count), and a task at most three checks a round runs: past either, ak refuses with `split it`. Reason: 81% of 201-400-line changes merged, 67% of larger ones (1-16 Oct); it is looked at again in early November on first-review sizes recorded since. Review rounds stay three, and a pull request mostly re-adding a failed one's lines inherits its rounds. No cap on task points or words or the docs' words: size is recorded and shown. Nothing ak hands a model is cut. Held by `tests/test_size_gate.py`, `test_own_pr_rounds.py`, `test_replacement_pr_rounds.py`, `test_task_size.py` and `test_rules_cap_told.py`. [3 Oct, 4 Oct, 9 Oct, 11 Oct, 13 Oct, 15 Oct, 16 Oct]
- A harness's settings are its own, changed in any of its sessions (its settings screen, or by asking its model): every login of a harness reads one settings file (not yet Antigravity's: 1.3.5 replaces links), so the change reaches every session and worker of that harness. ak has no settings screen for them and no setting shared across harnesses. Reason: rebuilding each harness's options in ak is work the harness already did, and an edit made on one Claude login was reverted by the next launch. [15 Oct 2026]
- The owner's own words are what a job is measured against: the orchestrator holds them whole and writes its checks from them; ak keeps no copy. Reason: handed to each task's reviewer, they would breed false findings and carry pasted keys. Held by `tests/test_owner_words_forgotten.py`. [2 Oct, 17 Oct, 18 Oct 2026]
- The normal way in is a session: open it, pick who orchestrates, executes and reviews, type the prompt. A notes intake, if built, is an optional add-on on top of ak, on the ak screen, using the providers ak already has. [1 Oct]
- Every provider takes more than one subscription. A subscription is always shown by its provider's name, with a roman numeral as its number when there are several (Claude I, Claude II), never by its account name. [29 Sep]
- The features screen has only `you` and `everyone`; grants for specific users live on the project's own owner page, never in ak. [23 Sep]
- Instructions have four homes: `orchestrator.md` and the worker rules (ak's), the host's `~/.agentkit/rules.md` (the owner's), and a project's `AGENTS.md` (its knowledge and the owner's product rules), each handed whole to every session and worker it concerns; nothing else instructs a model ak runs, no harness memory and no lessons file. `AGENTS.md` and `orchestrator.md` each have a word maximum that only goes down (`tests/test_boundaries.py`), raised only by the owner merging that change by hand; in each, a line explains something ak checks or a judgement no check can make, and a rule ak comes to enforce shrinks to a mention. [1 Oct, 4 Oct, 16 Oct]
- Credits a provider account still holds (ChatGPT credits first, any provider that reports a balance) count as usage left; ak never spends a usage-limit reset on its own: the owner spends one by hand, from the Providers row of `c`. [2 Oct]
- No screen estimates when work will finish; a seat's progress is its tasks bar and its count, never a percentage. [2 Oct]
- Every project meets one contract, enforced by checks and scaled by what is at stake: its suite runs every test file, its front matter holds only lines ak reads, and a live project proves it is live with a real `health:`, deploys only code ak tested, and puts the previous release back by itself when health breaks. How each project deploys stays its own; a ready-made deploy kit covers the common case. [5 Oct]
- Seats never message one another and nothing one seat writes is typed into another; a seat waits only on a pull request or a run (`ak wait`), and ak ends the wait when that merges, closes or ends. [4 Oct, 9 Oct]
- `~/code` holds only the owner's checkouts: a seat builds under `~/.agentkit/wt/`, and ak removes a seat's checkout a day after it last changed unless it holds uncommitted work or is a clone. Held by `tests/test_git_shim.py`, `test_gc_sweep.py` and `test_checkout_removal_keeps_work.py`. [5 Oct, 6 Oct]
- The landing gate changes only with the owner's yes. [2 Oct]
- Quality, then speed, then cost, in that order, is how ak judges a week, a change and a seat's work: the weekly audit names a quality loss before any gain in speed or cost (`scoreboard.loss`), a week with a quality measure worse is a loss whatever speed did, and nothing ak shows or picks credits speed or cost while the result got worse. [14 Oct]
- ak compacts no seat itself: each harness's own compaction does (Claude's idle compaction, its minimum set in the login's settings). Reason: Claude Code compacts an idle seat itself, and two compactors on one seat can only clash. [16 Oct 2026]
