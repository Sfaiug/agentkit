# How agentkit works

One interactive orchestrator plans with you and builds, whatever the size (its PRs go through `ak run --review-pr`); it writes
task files only for independent pieces that share no file with its work, when its session has workers. Headless workers execute, another model reviews where the workers allow one, else the executor's own, and a script keeps going until the checks pass and the reviewer says PASS; then the run joins its repository’s landing line to merge its own PR. Wired in:
Claude Code, Codex CLI, Muse Code, Grok Build, OpenCode and Antigravity CLI. Standard library Python 3.11 and bash only.

## The session

A session is a tmux session on agentkit's own server (`tmux -L agentkit`), so it outlives the connection that made it
and the orchestrator's process too. A bare `ak` is the menu on the server, on a client (over the ssh alias `install.sh
--client` recorded) and as the phone key's forced command `ak attach`. A tmux session there that agentkit did not start
and that runs no interactive agent in its panes, such as a watcher loop, is not a session: no row, no card, no count.
Ak workers (`AK_RUN_ROLE=worker`) and their descendants do not count; any old card closes on the next tick.

New seats and respawned panes receive the caller's `HOME`, harness state-root overrides declared by adapter manifests, notification sink and sink log, webhook override and owner mention. The session's environment is refreshed too, so its menu and future panes use the same state and delivery. A failed respawn keeps the old harness's environment for its menu and future panes. Absent overrides are removed: a sandbox probe keeps its state and delivery destination, and a normal seat clears an inherited test sink.

The key line explains what the pointer rests on, and the keys return when it leaves. A usage row glints once
and shows a tick at the share that would remain if usage kept pace with time; the `i` page is gone.

`n` first asks `Name:` with `auto` dim in the field, bare `ak orch` `Name (Enter: auto):`; a taken name asks again, Esc goes back. Enter (or pipe EOF) leaves `new`, then `new-2`, unnamed until its orchestrator knows the job and names it as briefly as possible in at most three words. Any rename ends auto naming; an unnamed seat gets the rule again on resume. `n` then shows every model with `orch` (one choice), `exec` and `review` marks. ↑↓ move between models, ←→ between roles, space flips the selected mark, a click flips the mark clicked, Enter starts, Esc goes back. The role headings stay visible while rows scroll. Both role groups are saved in the session. Reviewers keep at least one model; executors may be left empty, the orchestrator's own `exec` mark then drawn filled and dim: it builds everything, and `ak run <task.md>` from that session is refused in one line before any run exists, while its own `ak run --review-pr` still runs. Only a choice or start no run could start from is refused in one line. Chosen already, the last created session's: `[defaults]
orchestrator` (shipped `opus`), or while it is spent the first model in config order that is not, and the `[defaults] workers` (`opus astra`) and `reviewers` (workers when omitted) not spent; a group whose defaults are all spent falls back to another company's fresh model before the executor's company's, before the executor itself. From a pipe the name, orchestrator and workers read one line each, Enter taking each default; reviewers inherit the defaults, and
`--dry-run` starts no session. The seat opens in `~/code`; `ak orch <name>` keeps the shell's directory and reopens an existing seat; a new seat opens only from a terminal, so an agent's `ak orch <word>` opens nothing and prints the commands. As soon as the project is known, `ak orch project [<seat>] <checkout>` files this seat (or the named one) by checkout name or path; only known checkouts are accepted, and it stays there until filed again. It then lists what the project's other sessions have in flight: each one's open plan lines and the files its going runs change against their base, or a queued run's `files:`; sessions with neither are left out. A seat never filed so is refiled by each launched run under the project most of its runs belong to,
counting a run from its launch, still queued for a slot or not, for the checkout under `~/code` or `~/agentkit`
(agentkit's own; a second clone at `~/code/agentkit` counts as it) its task's `repo:` names, else for the one its task's `~/.agentkit/tasks/<project>/` is named for, never
one it merely inherits, and a worktree, sandbox or scratch workspace for nothing; a tie keeps its project. A seat with no
project is filed at the next menu draw or `ak watch` tick once one of its runs counts. `c` on its row opens the config with that session's orchestrator, executors and reviewers as its marks (on a heading only efforts): the arrow keys move, Enter, space or a click on the orchestrator moves the seat to that model at once under the same name, its runs, plan and record staying with a handover as the new one's first prompt, and on a role flips a mark and saves it to the session's record at once for the runs it launches next, Esc goes back; reviewers keep one model and executors may go to none, a choice leaving no allowed pair is refused in one line, and so is a model whose harness is not installed or not logged in, or whose meter is spent.


At launch, the rulebook reads `What ak is for` from the agentkit checkout's `AGENTS.md`, where present, then `orchestrator.md`,
this host's `~/.agentkit/rules.md` where you wrote one, and the body of the `AGENTS.md` on the default branch of the project the seat is filed under, as its workers get it; each `ak watch` tick fetches it from origin, so a merge there reaches the seat as a rulebook change, and a launch fetches nothing of a project that has been fetched: it reads the rules as last fetched, and fetches first only a project nothing has fetched yet. Its adapter hands it over
for that launch only (Antigravity's as an `--agent` definition in `~/.agentkit/state/antigravity`), never writing into your
own `~/.claude`, `~/.codex` or `~/.gemini`. A seat left open across a change to its rulebook is told with its next prompt, where its harness's prompt hook carries context: its current rulebook is written to a file of its own, and every prompt of its own conversation names that file until the seat runs the `ak orch rules CODE` the notice gives, saying it read that one; the code is that conversation's for those rules, so no other client and no older rules can say it. A seat opened before ak recorded which rulebook it was handed is told once the same way. Any other seat reads the new one at its next launch. A project's own `AGENTS.md` or `CLAUDE.md` holds its conventions and is never the place for agentkit's rules.

At every turn's end `hooks/orchestrator-stop.sh` sends the turn back with *Continue: decide the next step and do it*
unless the harness's question prompt is still unanswered (input in the owner's words answers it, never the harness's own bookkeeping) or this turn recorded `ak notify needs`, or one it asked before still stands unanswered; an answer to a prompt that asked something, a run of this seat's going, its job with a live launcher and an unsettled task (even before any run starts, following seat renames), `ak notify done`,
or its `ak wait <session>` naming a session that is working, or waits on the owner's answer to a question it asked, ends the turn only while none of its runs sits parked and
undecided (a run a later merged run replaced is settled), which names each run with its parked reason and the commands its state takes, and is looked at, resumed, relaunched split or on another model, stopped, or asked of the owner; it blocks at most twice a turn. A question mark in prose ends nothing: the block names the question prompt and `ak notify needs` (required without a question prompt). On Claude Code, background work the seat started counts as a run until it reports
back, and a stop sent back reads `working`. A harness
with no blocking end-of-turn hook declares `[stop] enforce = "nudge"`, and the tick types `continue` instead (a question mark on its screen ends nothing there either; `ak notify needs` this turn does, and so does one still unanswered from before it, as on a hooked harness, since a hand-back or a told line opens turns while a question stands), never ahead of the line telling a waiting seat its session stopped, and at most twice for the same parked run until the seat has a newer notice.

Every line ak types shares a check of the pane's own terminal and, when named, its wrapper's inner terminal: each tty reports how many input bytes wait unread. Before starting the harness, the wrapper names its inner tty once in the pane's `@ak_input_tty` option; it follows pane renames. A successful respawn clears the old name in the same tmux command list, before a new wrapper's publishing client can run; a failed respawn keeps the old guard. Older wrappers and harnesses without a wrapper keep the pane-only check, including after switching from a wrapped harness. Each relay poll writes newly read input in that same poll, retrying interrupted and partial writes until the terminal stops accepting bytes. When a non-reading harness backs up the relay, the inner tty holds unread input for the guard to see. While either tty holds any, no further line begins, even over a screen showing an empty composer; peer messages, notices and nudges wait for the harness to read them. The check also holds confirmation of a typed notice while input is unread; its Enter keeps the existing composer checks. Unread-input deferrals spend none of the retries for reboot or account-switch notices. A terminal that cannot be asked keeps the previous typing behavior. Delivery stays at least once: a crash after Enter but before recording delivery can repeat a line.

Inside a seat `Ctrl-b m` opens the same menu as a popup: a number switches to that session, `n`
starts one, `c` opens this one's models as `c` does on the menu, `x` stops it -- or, done, closes it at once -- and Esc closes the popup. A seat is renamed with `ak orch rename` or by renaming its conversation: Claude's Remote Control title, Codex's thread name, Grok Build's manual session title and OpenCode's session title follow the seat's name. Muse sessions keep their own name: the installed Muse refuses `/rename` even after a turn and rejects `--name`, so ak never types a rename into Muse. Codex's index and database do not distinguish generated names from `/rename`, so Codex titles never rename the seat, even after an owner's `/rename`; use ak to rename it. ak confirms its name from the owned thread's login index and restores it if Codex replaces it after the first prompt, stopping after three unconfirmed tries until the seat's name changes; an acknowledged name is not retyped, and a mid-turn attempt without a receipt waits for the prompt before retrying. Grok waits for an empty prompt and confirms only the manual title in its own conversation; automatic titles never rename the seat. OpenCode's seat plugin sets and reads back its own session's title through the API, including new seats, ak renames and auto naming, without typing or touching drafts. OpenCode 2.0.14 gives owner and automatic titles the same field and event, so neither renames the seat; the plugin restores ak's name when either changes it. All four leave owner drafts alone. Claude waits past dialogs and drafts and counts only once it records the title (or the composer clears if its transcript is unreadable); it gives its held line Enter even when wrapped, after the third typing or a later rename, and types each name at most three times before giving up until the name changes. Superseded pending titles stay recorded as agentkit's within that conversation until the name is explicitly retaken, so a delayed title cannot rename the seat back; owner drafts are never touched. Each typed line, its brief pause and its first Enter share the seat's lock so senders cannot merge lines; confirmation waits release it. A manual rename in Claude or Grok Build renames the seat too, taking a free variant if the name is held (even its own former name); Claude's title readings resume after the last complete line, with one note that moves and is removed with its seat; title errors are logged for their seat without stopping health checks. The seat's status bar is
two lines, the same values as its menu row: line one is the state as a chip, the name, `<orchestrator> orchestrates` in its company's colour and, while working, the tasks bar as its row draws it, in 36 cells, with your other seats at its right end: each that needs you by name (`! fix-api needs you`; a click switches to it), then `● 3 working` and `✓ 1 done`; where they do not fit, the bar narrows to 24 and then 12 cells, then the names fold to `! 2 need you`, then only that stays, and only then is the rest cut; line two is why it needs you or is done, or a working seat's live line: each run by its task id (a PR review by its number, `#2157`), a cell per step, the model doing it, what it is doing (building, checking, reviewing, the seat fixing what its own PR's review found, landing), its round past the first and its time on the step (`lg1 ■■■□ astra reviewing · round 2 of 3 · 11m`), more than two runs doing one thing and those queued for a slot as counts (`landing 8 · longest 2h`, `waiting 2`), whole groups folding into counts where a client is short of room, with `Ctrl-b m  menu` at its right end (`Ctrl-b m  x close` once it is done). Each line is cut with one `…` where it would run off any client, a phone included, and the
window title is `<name> · <state>`. Agentkit's tmux config is `~/.agentkit/state/tmux.conf`; `~/.tmux.conf` is never read or written.

Terminal input and screen output flow independently for every wrapped harness. A burst of typing,
pointer events or redraws cannot make the bridge wait on itself; slow readers apply bounded
backpressure without dropping bytes. Compaction keys use the same transport. Existing seats take
a transport update on their next natural restart, keeping their conversation.

Every seat compacts alike, whatever its harness: 55 minutes after the last turn on Claude Code (its prompt cache lasts an
hour), 30 on the others, with the context at or above 40,000 tokens, the harness's own compact command is typed once at a
quiet prompt: never while the seat's own hooks say a turn is running or a question is up, or its record reads a question, however old the last turn's end. Only a new turn resets that clock, never a key, click, pointer motion, focus, attach or resize. Claude's draft
is stashed (Ctrl+S) first and comes back after; with no stash key, a seat whose record reads a draft is not typed into.
Workers never compact, nor does a harness with no compact command or no reported context size; `ak orch list --why` says why.

Any harness can hold the seat: `--model astra` opens Codex, `--model spark` opens Muse. A Claude seat owns its
conversation from launch by a uuid; its launched pane's `/clear` hook keeps reopening and titles on the new conversation,
using its recorded login. The watch tick binds older running seats to their own client pane without restarting them; if that pane is removed, restarting uses the session's current pane. Other panes and in-session `/resume` never transfer seat ownership.
A Codex seat trusts only agentkit's hooks; other hooks still need Codex's review. It proves its thread through a launch receipt. An OpenCode seat's plugin
writes its session into one, and Muse and Antigravity open a new conversation each time. A seat whose harness exited
keeps its window. A dead, detached seat nobody has opened for seven days is retired, and a record seven days gone from
tmux is swept, unless a run of the seat's is unfinished or a question in it is unread; then the name is free again. A Codex seat's conversations are its own, under `~/.codex/agentkit-seats/<id>` whichever subscription it runs on, where they stay after the seat is removed and a switch's handover still reads them, so its server never imports the host's other Codex history; startup waits as long as the server needs while the seat is open, and closing it meanwhile leaves the next start working.

Codex seats have Remote Control enabled, but connecting the ChatGPT app is optional. Opening, resuming or changing a seat's subscription sends no pairing alert. Request a fresh code on the host with `python3 ~/agentkit/tools/codex-seat.py --pair <seat-name>`, then pair the app with that code. Each seat has its own connection and must be paired separately; terminal work continues without pairing. Old pairing cards close as `Pairing optional` when their seat next checks its connection.

Stopping a session (`x` on its highlighted row, after its one question under the row, `Keep` or `Stop`; `x` on a done session and `ak orch stop <name>` ask
nothing, so a finished session closes with one `x`) stops every run it launched, removes each run's worktree and local branch, deletes every
state file named for the seat or for a name it had before a rename except its locks, rulebook and idle-compact stamps included, edits its open Discord card to `Answered`, and closes the tabs the seat or its
runs opened; the collector takes the stop mark and unused locks a day later. The remote branch stays for the PR, and the run directory for its result. Leaving the menu with Esc leaves a seat running and is not a stop. From a seat, `ak run stop` and `ak orch stop` refuse another seat's work and name the seat to message instead; own runs and runs without a seat still stop. Without `AGENTKIT_SESSION`, the owner can stop any run or seat. A seat's `tmux` is `tools/tmux-shim`, first on the seat's PATH (`orch.start` puts `~/.agentkit/bin` there and links it; a running seat gets it at its next start): it reads the final argv bash built and refuses a kill that would end another seat (`kill-server`/`kill-session`/`kill-window`/`kill-pane`) or a type into one (`send-keys`, `paste-buffer`, `send-prefix`, `pipe-pane -I`), then execs the real tmux. Which seat a `-t` names is answered by the real tmux, with a read-only command of the same target type as the one guarded — `list-windows -t` for a session target, `list-panes -t` for a window, `display-message -t` for a pane — so the guard's answer is the command's own, not a hand-made copy of tmux's lookup, and a current-relative target resolves to the seat's own session. A worker, a shell with no seat, and every failure run the real tmux. Out of reach, by design: a tmux reached by an absolute path, one started before the shim was on PATH, tmux's own `run-shell`/`if-shell`, a login subshell that rebuilds PATH, a `-t` left off or on another server, and the commands that move, replace or respawn a pane or window; the bypass-proof form is a separate `tmux -L <seat>` socket per seat. A `gh` shim sits beside it (every `tools/<name>-shim` is linked as `~/.agentkit/bin/<name>`, so a new one needs no change): it refuses a seat's `gh pr merge`, because merging is ak's job once a PR passes review with green checks and the seat lets it land through the line. The one seat that may run it by hand is the inbox, which `ak watch` asks before it merges someone else's PR; ak's own merges (the lander, a review run) run seatless, so the shim passes them. Like the tmux guard it catches the merge a seat reflexively types, not a determined bypass; out of reach, by design: merging through gh's API (`gh api ... pulls/N/merge`) or a GraphQL `mergePullRequest`, a gh alias for `pr merge`, and gh reached by an absolute path. A `git` shim refuses a seat's `git worktree add` whose checkout would land in `~/code`, which holds only the owner's checkouts, and names `~/.agentkit/wt/` instead; every shim is one sh body (`tools/shim`), so a worker's call and whatever runs seatless (ak itself, a test's sandbox) run the real binary at once with no Python start, which git, run all the time, needs; only a seat's own call asks the guard. The real binary is the first on PATH after the shim's own, so a wrapper ahead of it never loops. A git alias for `worktree add`, or a git reached by its absolute path, is beyond it. The `scp`, `rsync` and `sftp` shims refuse a transfer that writes to the live host — the ssh alias the owner set as `live_host` in `~/.agentkit/config.toml` (`config.live_host`); the deploy host is each owner's own, so ak ships with none and guards no transfer until you name yours. scp and rsync write to an operand after the first (the first operand is a download's source, which runs); a `live:` operand after it is a write and is refused, tested by position so a trailing `--exclude x` or `-e ssh` (rsync permutes its options) can't hide it, and with no list of each tool's value-taking options — parsing those out only re-derives their grammars. sftp connects to its host operand, so a live host there is refused. A read from live, a transfer to any other host, and any transfer when no live host is set, all run; beyond the shim, named: a download whose first operand is a value-option's argument (`scp -i key live:/x .`), and a write made inside `ssh live "…"`, whose remote shell the shim never sees.

## The run

`ak run task.md --bg` is one job: a task file, a worktree, an executor, the checks, a reviewer, fix rounds and a merge.
The orchestrator writes the task from `templates/task.md`: a title, `## Goal`, `## Constraints`, and a `bash` block
under `## Done when` whose every command must exit 0. Optional front matter: `repo` (the launching checkout, else the one its
`~/.agentkit/tasks/<project>/` folder is named for; `none` is a scratch workspace), `base` (the repo's default branch), `target` (the branch the PR merges into, default `base`), `from`
(a local branch to cut from), `merge` (`squash`, `merge` or `rebase`), `rounds` (3, the most). A task with `after:` is
refused at launch: a job's tasks are independent pieces; a run saved earlier that was to start from, or still
stands on, a dependency's passed tip ends blocked before any work, and `ak run merge` refuses it, any branch kept. A fresh `from:` run merges its fetched or local target before round 1, aborting conflicts and leaving them or missing targets for landing; a resumed run never repeats it. A check ending in `# once` runs once at landing on the commit to be merged; the executor is told not to run it,
its absence from the reviewer's input by design. Scratch and `--no-merge` runs execute every task check in each round, including `# once` and explicit suite lines; the declared suite is not added. The full suite declared as `tests:` in the target's `AGENTS.md` at its checked tip runs once at landing; the checkout's declaration applies only when the target has none. A changed line judges later changes after it merges. A matching done-when command runs with it, so a task lists only its own checks.
`files:` (repeatable, comma-separated Git pathspecs) limits the branch's own changed paths after rebasing; an unmatched path fails the gate with `outside files: <paths>`, goes to the fixer and overrides reviewer PASS. Without it there is no limit.
An unknown task front-matter key refuses launch before any receipt, naming it and the accepted keys in one line. Retired `done_when_minutes`, `turn_hours` and `stall_minutes` keys stay accepted with a warning.
A command that fails runs once more at once, within the same ceiling, and passes if the re-run does: `flaky:` keeps at most 20 lines absent from the passing re-run after masking numbers, hex ids and absolute paths for comparison. It names a file in the run directory holding the whole failed output, and joins the run's follow-ups as evidence. In agentkit's own suite a failed test file runs once more alone inside its piece, after the piece's other files, before the piece itself would be re-run.
Every prompt carries the whole body of the repository's `AGENTS.md` as on the base commit, front matter removed; a linked `AGENTS.md` gives nothing, and a round that adds or changes one fails its checks, asking for the file itself. A round that changes `AGENTS.md`, a PR review round that runs no suite included, fails its checks if the file, as a checkout holds it (line-end conversion included), is then past the most a harness reads of it on its own: the smallest `[instructions] read_limit` an adapter declares (Codex reads 32 KiB). The same round fails if the committed file goes through a Git filter or its front matter holds a line whose name ak does not read (it reads `tests`, `health`, `cleanup`, `users` and `features`), so a misspelled `tests:` never silently drops the suite. Leaving the file alone passes this check even when it is already larger. The lander measures it again on the tree each change would land as, before any suite or earlier green result answers that tree, so changes that fit one by one cannot land together past it. One past it behind changes still in the line waits for their verdicts, since they can lengthen or shorten the file; with none ahead, it goes back to be tightened. A worker's harness, and a seat's, loads no instruction file or memory of its own where it has a switch for that (a seat's rulebook carries its project's `AGENTS.md`); its adapter's manifest says in one line what no switch reaches.

One behaviour per task; size never refuses one. A launch is refused when `rounds` is more than three, or a done-when line opens a heredoc (each line runs as a command of its own; bash's own parser decides, as `bash -n` reads the line, so shifts, comments, quotes and `<<<` pass), whatever `--anyway` says;
and when a run under way in the same repository names the same test file (glob patterns do not count; a general check -- one three other jobs there ran without naming it in their titles -- counts only when both titles name it) or shares four title words, which `--anyway` starts
regardless. Runs have no count cap and wait FIFO while free memory is under the larger of 3 GB and 20% of RAM, ak's own
slice CPU pressure is above 40%, or the nearest limited cgroup is past 75% of its `memory.high` outside reclaimable
file cache; a pinned `max_load` restores the host-load check instead, each run the host has frozen counting 1 while held; a
worker's own test runs share the parent's slot, and a third level is refused. Past its own memory cap, the 40% of the
slice ceiling, 4 GB where there is no ceiling, unless `run_memory_max_mb` sets it, a run loses only the process that grew:
its command exits 137, the log says `memory cap N GB hit`, and the run goes on as after any failed command or killed worker.
Under a systemd older than 253 the whole run ends `fail` with `killed: memory cap` instead.
`ak run --first` admits a loop repair ahead of ordinary queued runs, skipping the count cap and CPU gate while keeping memory gates; status marks it `first`. A member holding a lander verdict gets the same admission, `land` ahead of `fix`. A heavy suite turn goes to a landing run before a round check, and within each to whoever waited longest, `--first` or not. Finished work goes first: the line's checker outweighs every run for the CPU, so its suite's pieces count the CPU lower-weighted runs use now as its own, read with the slice's use in one sample; and from a landing suite's first look at the turns until it holds them, while the line still holds the member it checks, no round check takes a turn and no run is admitted but a `--first` one or a woken member (`waiting for a landing suite's turn`).
A job started with `--bg` or relaunched by the tick gives each task, its resume and delivery retry included, its own run scope and cap; one run from a terminal runs its tasks in its own process.

The worktree is `~/.agentkit/wt/<id>` on branch `ak/<slug>`, the first name free locally and on `origin`. The executor
writes the change; ak commits uncommitted work before checks and review. Worker rules are marked `[checked by ak: <test file>]` with what ak does, or `[worker judgement]`. Every executor and fixer turn closes with `ak hand-in done`, `blocked "<why>"` or `not-needed "<why>"`. The closing record decides the outcome regardless of final text; without one the worker is asked once more in its session, then proceeds as done to checks and review if that turn also leaves no closing. The work summary is kept for result.md, including after a closing ask or restart. Later records are refused. Review turns refuse blocked and not-needed; other turns refuse finding and follow-up. Every turn, proof replay and check runs in a bubblewrap box: GitHub token variables are unset and gh login files, Git credential stores and SSH keys look empty; the SSH agent is unreachable; a directory on the way to any of them that is closed to you refuses the box with the fix, and a key kept outside `~/.ssh`, not linked from it, stays readable where it is. A proof or check has the same filesystem walls, with throwaway overlays for the account's home and `$HOME` so caches and tool config work while it runs and every HOME write outside its writable places disappears when it ends; a home with a mount beneath it, as inside another box, stays read-only. Each box, including one inside a box, has its own empty `/tmp`, `/var/tmp` and `/dev/shm` and a copy of the host's readable `/run` directories, symlinks and regular files on disk in its out dir, excluding masked credentials, `/run/user`, sockets, FIFOs and device nodes; it sets `TMPDIR=/var/tmp` and an empty `XDG_RUNTIME_DIR=/run/user/<uid>` of mode 0700, covers an existing host runtime directory outside those places with an empty directory, and refuses if any of the four host directories is missing, preserving resolver paths while keeping host services there unreachable; a socket elsewhere (under HOME, for instance) or an abstract socket stays reachable, and the box's own network will close the abstract ones. ak's own `git`, the first in a directory ak's own `PATH` names in full, tells a box which credential stores to hide and where the workspace's Git storage is. A `git` that only the turn's `PATH`, a relative `PATH` entry or the current directory names is never asked; with no other, the box refuses. A turn's filesystem is read-only except its workspace and Git storage, out dir and manifest-declared harness state; the devices its account has read or write access to stay available. Writes elsewhere are refused. Network access stays the same. Its PID namespace ends every child when the turn or command ends, even after detaching or clearing its environment; ak logs turn leftovers' command lines and asks once to finish in the foreground. The installer adds bubblewrap; launch probes nested boxes and refuses with a remedy if they cannot start. Loop helpers keep their directory markers and cleanup, so separate ak homes cannot end each other's processes. The loop runs the checks itself and hands the diff and their output
to the reviewer, another model where the workers allow one, else the executor's own. Task reviewers may run whatever is needed to prove or dismiss a finding, except done-when commands, the repository's `tests:` suite, and checks marked deferred, which run at landing.
Probes leave nothing behind outside a temporary directory. Scratch reviewers keep the deliverable workspace read-only. Repository reviewers, including reviewers of others' PRs, use a temporary copy with separate Git refs and no push remote, so their files and branch switches cannot disturb the suite or task branch. Reviewers of others' PRs may run tests and commands. Only regular files and links are copied, into writable directories. Cleanup repairs read-only directories in that copy. Unreadable paths and other file types are skipped with a WARN naming the path; snapshot errors are also recorded in the patch. Before every reviewer turn, retries and the extra hand-in ask included, ak records HEAD, the branch and the dirty paths. Afterwards it saves any edits, new files or commits to `round-N/reviewer-changes.patch`, restores the recorded checkout and logs a WARN naming what it undid; files already present stay, and reviewer changes never reach the next round.
A reviewer uses `ak hand-in finding path:line "what" "why it matters" --run 'command'` or `--quote 'lines'`, and `ak hand-in follow-up` with a one-line `--run` (no backticks or checkout path: it becomes a plan check) plus `--before 'base or ancestor commit, or verbatim lines from the named file at base'`. The loop names the turn's record file in `AK_HAND_IN`; outside a worker turn hand-in is refused. Missing files, invalid lines, quotes absent from the file and missing evidence are refused in one sentence so the reviewer can correct the call. A finding’s `--run` command must fail while the defect exists; exit 0 is refused with instructions to fix it or use `--quote`. After the turn ak replays each finding’s command on its own clean checkout of the reviewed commit, then on base with changed tests overlaid. A passing or unfinished proof on the commit is a note, as are exits 126/127. Other non-zero exits count as failures regardless of output, including missing scripts or data files. A proven defect on an added or changed line, or beside a removal, blocks; elsewhere it blocks only if the proof passes on base, otherwise it is a follow-up only if its proof runs and fails on base; an unfinished or unexecutable base proof makes a note. Quoted findings are checked again against the reviewed commit (the workspace for scratch): a missing file, invalid line or absent verbatim quote makes a note. Valid quotes block on changed lines and become notes elsewhere; scratch runs block every proven finding. Replays restore the branch head, clean, including after interruption. Command evidence keeps bounded excerpts of ak’s own output and exit status on both commits; a truncation notice tells the reviewer to rerun it for full evidence. Only hand-in records decide a review: `ak hand-in done` completes it with FAIL for any blocking finding, otherwise PASS. Records survive every retry, park and host interruption on the same session; run.json keeps the weighed records for FAIL hand-backs. A turn without done is asked once more in its session, carrying earlier records forward, then falls back to another reviewer, whatever its text says. PR descriptions and posted reviews are bounded, with a notice naming the run that holds the complete records. A round runs only the task's done-when commands and review, passing when both pass. A change needs a check that fails on the old code, and ak proves it wherever it can, never failing a round for a missing proof (the owner's rule, 7 Oct). Once a round's checks pass, ak runs them -- the per-round ones, less a suite split into shards -- on the base commit with the branch's test files overlaid (test-shaped paths only: under `tests/`, `test/`, `spec/`, `specs/` or `__tests__/`, or named `test_*`, `*_test.*`, `*_spec.*`, `*.test.*` or `*.spec.*`; never a file a check merely names), through the gate's own runner and environment, in order. When one does not pass there, ak runs them once more on base with every file the branch changed laid over, run alike, and a check that finished failing on the first and passes on the second proves the change. A check finishes failing as a reviewer's proof does: one killed at the limit, never run or never started (126, 127) shows nothing. Each exit is the runner's, never what a check printed. Each replay gets a checkout of its own made from git alone, a clone at a commit on base made the same way every time, so nothing but the branch's files between them can turn a check, and neither sees what the other's checks wrote; the run's own checkout is never touched. A proof is recorded once per run. Until there is one, each round's gate output, the run's result and its PR say `base proof: none shown` and why: every check passes on base, or its test lives where ak does not look for one (Go's testdata, Django's tests.py, a test inside a code file); a check needs what git does not hold, such as an installed dependency; the branch changes nothing but tests; or the task has no check of its own. A fix run proves its `regression.sh` on base in its own checkout instead, as below. Scratch runs and PR reviews have no such check: an orchestrator's own PR is proven by its plan's check lines, which must fail on the default branch when written. The full suite runs once at landing; a failure goes to the landing fixers. A round is FAIL only for a blocking finding: a correctness defect, a safety
or data-loss risk, a weakened check, work outside the task, or complexity the diff adds (a second home for a piece of knowledge, a special case inside general code, work pushed onto callers, a function that only forwards), with evidence: a command that fails, a reproduction, or quoted file lines showing the defect. A follow-up needs the same evidence and severity, plus proof it existed before
the task: the base or an ancestor commit, or verbatim lines from the named file at base. Only these are handed in as follow-ups, without a
number limit; everything else is omitted by the reviewer. Every follow-up needs a command that runs and fails on base, plus `--before` naming the base or an ancestor commit (a hash or ref) or verbatim lines in the named file at base. ak replays submitted follow-ups even when no blocking finding was handed in. A passing, unfinished or unexecutable proof, a quote without a command, or a `--before` absent from base drops the follow-up; the reason and evidence are recorded under `## Notes`. Notes appear under `## Notes` in result.md and the PR body and start no fix run. A fixer receives only blocking findings, with ak’s output from both commits. The run's `run.json` and PR description carry only the final
passing review's list, plus checks that passed only on re-run with their `flaky:` evidence. Earlier reviews' items
are discarded. Nothing reads or writes `~/.agentkit/followups/`; existing files and archives are left alone.
On merge each review follow-up becomes an open line in the session's plan on the run's project, checked by its failing command until the session puts its own test in its place (`ak plan check N`, which must fail on the commit the line names, the one its check failed on when written; a line from before lines named one takes it unproven), for the session to build itself; an open line with the same check prevents a duplicate, and the ending names each line, or why the plan refused it. Every run notice typed into a session uses the same composer and byte bounds as `ak tell`. A fitting line stays unchanged; a longer ending, review-round result or maintainer decision names the full `result.md` and counts its follow-ups, naming the session's plan for those it accepted and keeping refusals and fix-run names in the result. Before compaction, ak saves the full notice and follow-ups in `result.md`, including older pending endings; saved notices survive report rebuilds, and after-merge evidence stays there when the tick clears its delivery receipt. Nothing is cut from those files. A flaky check's evidence instead starts an ordinary run of the same session, with the executors and reviewers the session's record holds at that moment (the discovering run's if the session has no record), and a fresh checkout of the merged target. Its task is the defect and evidence. An open fix at the same site in that session prevents a duplicate. There is no setting or backlog.
In its first turn, the executor checks the current target and other open runs. A defect already gone or being fixed ends with `ak hand-in not-needed "<why>"`: done, no PR, checks or review. Otherwise it adds a regression test, shows failure before and success after, and writes the run's `regression/regression.sh` to invoke it: that folder is the one place in the run directory its turns may write. After done-when passes, the loop runs it detached on the base commit with changed tests overlaid (none when the fix changes only tests) and a fresh bytecode cache; a pass there fails the gate. A successful base failure is recorded once per run, and the checkout returns to the branch head, clean. Every probe records its original checkout first; after a crash, the resumed run restores it before verifying or building. An owner-only decision ends with `ak hand-in blocked "<question>"`.
The merged run's ending names its fix runs too. The session stays working until they end; stopping or closing it stops them. Their follow-ups start runs the same way. Runs without a session, scratch runs and reviews of other people's PRs start none.
A FAIL starts a fix round: the fixer fixes every undisputed finding, or uses `ak hand-in dispute path:line "why it is wrong" --run COMMAND` or `--quote LINES`. Only blocking findings handed to that fixer may be disputed; review and first executor turns refuse disputes. Commands must exit 0; quotes must exist in the named file.
ak gives the next reviewer each dispute beside its finding, with ak’s own proof output. Hand the finding in again to uphold it, weighed normally; otherwise it is dropped, with its dispute under `## Disputes` in result.md. Three rounds is the budget: at the third FAIL the run ends
`fail`, hands back its open findings (their first 600 characters, with their count and the path of the reviewer's whole report when that cuts them short) with `three rounds spent: split or re-scope`; no `--rounds` above three starts or resumes, and a job gives it no more rounds and no rerun on another model.

A run woken from a landing line delivers under its repository lock only when its integrated tree matches the lander’s approved stack tree; a changed tree keeps its place. A task's red verdict or failed required PR check uses the landing fixers and re-review without a task round, then rejoins at its place; a fixer reads the check's output's end, as before, and ahead of it every line above that end naming a failure, with the lines indented under it (each piece's and each command's last 20 KB, as the gate keeps them), so a red piece behind others is never missed. A PR's red verdict goes back to its seat; its next push is reviewed and rejoins the line. A failed re-review ends with its findings; a fourth red hands back the last failure, and resuming the run afterwards starts its count again. A merge, including a seat's own PR on PASS, carries `Suite-Passed-Tree: <tree sha>` only when the declared `tests:` suite passed on the delivered tree; CI can skip its repeat when the trailer matches the pushed commit's tree. If GitHub's default merge body cannot be read, ak merges without the trailer and CI runs as usual.
After PASS, a writable run joins its repository’s landing line and its worker exits. Its record keeps its place and PASS across stops of the worker, restarts, updates and crashes. A background run or job task exits; the job follows its record, and foreground `ak run`, `ak run resume` and `ak run merge` follow new log lines and print the ending. `ak run merge` joins the same line for a saved delivery retry.
The lander checks the reviewed branch brought up to date with `origin/<target>` (a rebase, or a merge where `merge: merge` is asked or the branch carries merge commits), in scratch checkouts, stacking members in line order. Green deliveries stay first, in their tested order, while running or resuming themselves; those needing an explicit resume leave the line. Live rejoiners finish cleanup before later stacks are checked. When every unanswered stack fits, a pass checks them side by side. Otherwise it checks the deepest unanswered stack first (a sharded suite takes every free turn, so one check fits). Green covers every member through that stack; each covered stack records the deepest tree as `tested`, and only main’s tip after the batch must be tested. Red is narrowed by checking halfway between the last green stack or the target and the red one, until the red stack sits directly behind green or the target. Each narrowing check starts as soon as a turn is free, in the same pass. A tree already checked with the same commands answers at once, with passing evidence kept for a day; batch coverage is reused only while its tested tree remains in the line. A batch includes its covered members’ `# once` commands; two members with the same tree still owe their own checks. A green member wakes in that pass once every stack ahead is green, and waits for earlier deliveries to finish; a red stack after a green one wakes only its newest member to fix, and later stacks rebuild without it and continue checking in the same pass. Members conflicting with the bare target tip wake to fix at once; conflicts only with earlier members wait. A PR whose seat pushed past the head that passed its review is not checked: it goes back, and its new head is reviewed before the line checks it. It wakes the run to push, open the PR, wait for required checks and merge, squash by default. A pass whose line changed under it, so that its verdicts can no longer be written, starts no further check (checks already running finish, and their results are kept as evidence), and the next pass checks the line as it is. Passes and deliveries hold separate locks: one pass checks the line while one delivery can merge. Delivery confirms the approved stack tree still matches; a target move rejoins at the same place. Landing fixes run outside that lock, re-review without a task round, and rejoin at their place. The record, the tick and a member's follower (a foreground `ak run` or its job) start fresh passes on the installed ak; a missed launch or wake is retried. Each pass has its own scope in the runs slice and memory derived from the host and members’ recorded needs. A stopped member leaves the line and is never woken.
When the first stack fails and the target tree has no pass recorded by the lander’s own ak commit, the lander runs the bare target’s declared suite once, so an ak change that breaks the checks reads as a red target, never as the member’s fault. A red target gets one repair first; every other member keeps its place, unblamed, while the repair holds that tree. A PR gets no repair and waits on none: its seat is handed the target's failure, and its next head is checked on its own, so one that mends the target lands. A merged repair or `not needed` ending lets the line check the target again. A passing target wakes the member to fix itself. A clean integration keeps the review, an empty one ends PASS, and a suite that changes its checkout records no passing tree. `ak run status` and the result say where each check ran. Members land in tested stack order.
Fork deliveries stay outside the line: without push rights the run integrates, checks, forks and opens its PR upstream, ending `PASS, not merged: waiting for the maintainer` with exit 0; the tick follows the maintainer’s decision. `--no-merge` stops at the verdict. Other ended `merged: no` runs name their reason and exit 1. Before each round, a run whose installed ak moved replaces itself with `ak run resume <id>`, keeping its pid, slot and saved PASS; it never moves holding a turn or child.

A run ends `blocked` when the task is wrong: an executor or fixer runs `ak hand-in blocked "<why>"`,
or a fix round leaves the same checks failing the same way (or no harness can run it, see Resumption). No
checks, no reviewer, no further round. `result.md` opens `# BLOCKED — <title>`, and the orchestrator writes a new task.

Scheduled errors and merge waits send no ending. Every ending goes to the launching seat as one line typed at its next
quiet prompt: `run <id> finished <PASS merged|PASS not merged|DONE|FAIL|BLOCKED|ERROR>: <why>. Result: <path>. Decide the
next step.` A seat mid-turn gets it from the tick; its line is typed once, and one still sitting in the seat's composer
gets only its Enter, none while text you typed sits beside it, and counts as delivered only once that composer, read
whole, is empty. A seat that has died is reopened by the run and told `continue <task>`; only when that fails does a
`Needs you` card go to you. A run you launch by hand has no seat: its result is on the terminal and in `ak run status`.
Workers and checks run with `$AGENTKIT_UNATTENDED`, so a run one of them starts belongs to nobody. A project's `AGENTS.md` front matter may declare `health: <shell command>`: exit 0 means its live product works with the change deployed. For three hours after merging, the tick reads the declaration at the merge commit, from GitHub if it is unavailable locally, and runs it in the original repository checkout with `AK_MERGE_SHA` set to that commit. It tries at most once per commit per tick, stopping at the first pass: `live_at` goes into the run and its history row, and the launching seat hears that the change is live, unless it has declared done since the run finished: its job is over, and the line would open a turn it could end only by declaring done again. Each attempt has a 30-second timeout that kills its process group. A command still failing when the window closes goes back once with its last output, using the merge-commit checks' existing break marks. An unreadable declaration retries next tick without changing merge-check handling. The project owns its deploy; without `health:`, merging behaves as before.

Several task files run as one job: `ak run a.md b.md [--parallel N] [--bg]`, one card at the end, receipt in
`~/.agentkit/jobs/<id>/job.json`, keeping `owner_words` from the seat's Claude, Codex or Grok record since its previous job (the whole conversation for its first), capped at 64 KiB of UTF-8 JSON keeping the newest words; ak notices are excluded and relayed owner replies count. A later task will check delivery against them. Every task starts at once, up to `--parallel`; work that waits on another piece is the session's to build in
order. `repo: none` delivers
files in `~/.agentkit/work/<id>`, which its hand-back names, not a PR. A seat's own PR whose diff touches only prose or translation files (regular files, no binary, submodule or link; `AGENTS.md` and generic `.txt` files other than named prose such as `README.txt` excluded) skips the reviewer and joins the line like a passed review. `ak run --review-pr URL` reviews a PR with
no executor and posts the verdict as a GitHub review: a seat's own PR of any size joins the repository's landing line on PASS. Its reviewer also gets the seat's open plan lines, the outcomes the user agreed to, each naming its project: one on this repository that the PR claims but misses is a finding whose proof is that line's check. Review rounds run no suite; the lander checks the change on top of the target and earlier members. Delivery updates the PR head to the approved stack tree with a lease protecting a newer seat push, waits for green required checks and merges pinned to that head.
A review FAIL or red landing verdict sends findings back to the seat and waits for its push, shown by `ak run status`; the next head is reviewed with the previous findings first. The third FAIL or a closed PR ends the run. Anyone else's PR has no line behind it: its suite runs in its one review, and it asks the inbox on PASS. `ak run status` lists every run of the last seven days but the smoke suite's own, with its round and age; naming one acknowledges it and prints its `result:`, `record:`,
`workspace:` and `continue:` lines. An ending handed back, acknowledged or superseded (by a later merged run of its
title, or a relaunch `from:` its branch) reads `done`, as does a parked run a later merged run replaced, and a job's tasks read their runs as they are now. `ak run` exits 0 on PASS, 1 on FAIL, `exhausted`, `blocked` or an unfinished merge, 2 on error.

A run never waits forever. A check with no output for 20 minutes is killed with everything it spawned and fails the
round; the whole checks list has a six-hour ceiling. Either stop names the last output and each still-running child with no live child of its own, with its command and elapsed time. A model turn with no harness event for 20 minutes is killed and
retried on the same conversation. Each `git` and `gh` attempt has 120 seconds with prompts disabled; Git remote calls (`fetch`, `push`, `ls-remote`) and `gh` retry a timeout once after one second, then say the remote did not answer. Other Git calls stop for cleanup; a refused prompt stops at once and says to check `gh auth status` and the remote's credentials.
A stop ends the run `exhausted`, or `pass` with `merge_failed` while the review still stands; its result and hand-back name `ak run merge <id>` for that PASS. Before the first
turn the run adds build junk (`__pycache__/`, `node_modules/`, …) to the repo's `.git/info/exclude`. Before review it commits executor leftovers, leaving test sandboxes (top-level `.ak-test-*`, removed before each turn), run locks (`recovery.lock`, `delivery.lock`) and dependency trees (`node_modules`, `venv`, `.venv`, including nested paths and symlinks) uncommitted and counted in the sandbox log regardless of `.gitignore`; a staged one is unstaged and a staged deletion of one committed, so the done-when starts on a clean checkout.
`~/.agentkit/env/<repo>.env` is exported into every worker, check and `cleanup:` for that repo.

### Deploying with the release kit

A project on its own Linux host deploys with `tools/release.py`, copied to its `deploy/release.py` and run every minute or two by a systemd timer as the project's own user, never root. It releases only commits on the first-parent line of the branch ak lands on (what its clone's `origin/HEAD` names) that descend from the live release and carry ak's `Suite-Passed-Tree:` stamp for their own tree, the newest first, and never one that is an ancestor of a commit that failed after its switch: a failed release waits for a newer one, also after main is rewritten and garbage collected. A branch that no longer contains the live release is refused until someone releases by hand. Each release is built in its own directory with a fresh virtualenv from its requirements file; its install and migrate commands run before the `current` link switches, each in its own process group that ends with it. A failure before the switch changes nothing live, and the next tick tries again. After the switch the release's restart command runs, then its health command until it passes within its time. Any failure after the switch puts the live release back: the link, its restart, its health. A restore that fails, or a tick cut off mid-release, is finished by the next tick, and every tick first prunes old releases, never the live or the previous one. The kit holds no privileges and installs nothing outside its own directory: the project's units point at its `current` link, the project's installer puts them in place, and the restart command may use a sudo rule for exactly that restart. The timer's OnFailure= alert says why, and the project's `health:` hands the break back to its seat. `deploy/release.toml`, read from the commit being released, names the restart and health commands, and optionally the health time, requirements file, interpreter, install and migrate commands and how many older releases to keep. Migrations must keep the previous release working: a restore puts the code back, never the schema.

### New features in live projects

A hobby project ships straight to live. When a new feature comes up in a repository whose `AGENTS.md` front matter has
no `users:` line, the orchestrator asks once, "Does <project> have real users?", and that feature's first task adds
`users: none` or `users: real`; no line reads as `none`. In a `users: real` repository a new feature merges round by
round behind the project's own switch, on only for you until you turn it on for everyone; only the reviewer is told, and
it fails a round whose new feature is outside the switch or on for anyone else by default. A project names its switches with
one command in the same front matter, `features: <command>`: `<command> list` prints them as JSON (`id`, `name`, `you`, `everyone`, `you_switchable`, and `everyone_since`, when it last went on for everyone, ISO 8601 UTC, or null) and `<command> set <id> you|everyone on|off` flips one, printing the new row or one line on stderr. The menu lists such a project whether or not a session sits in it, as `ACME · 2 hidden features`, and Enter or a click on that heading opens `agentkit · ACME`, where the arrow keys pick a feature and `you` or `everyone` and Enter flips it through `set` at once, while `list` is asked in the background every minute (every ten seconds while that screen is open) and never holds up a draw; the project's own owner page flips the same switches. A switch on for everyone for two weeks is proven: once a day the tick reads the list of each checkout in `~/code` that declares one and queues, as `ak tell` queues a line, every switch it shows proven, longest first: a switch an open session's plan already names goes to that session, the rest to the newest open session filed under that checkout, one line each, saying to take each out of the code and keep the feature as everyone has it. A switch on for everyone whose row gives no `everyone_since` is named in the same line, asking for the field, since without it ak cannot tell when it is proven. It says so again each day one is still listed, until the project's deploy has dropped each from the list; the same line still waiting is not queued again. What a session was told stands: a switch turned off after is still taken out, since turning a proven switch off is a code change. A list that cannot be read, or a checkout with no open session, is tried again the next hour; the line names the project, so it holds even in a session filed elsewhere by the time it is typed.

## The states and the cards

A session is `● working`, `! needs you` or `✓ done`, and nothing else exists. One function, `watch.session_state`,
decides which, and every screen reads that answer: the menu row, the project heading, the top line, `ak orch list`, `ak
orch why`, the status bar and the window title. A seat's own hook event (a turn begun or ended, a question) decides it again at once, in the background, as does a run it launched entering a step or a round or ending, and an open menu draws again, as recorded, within two seconds of any seat's record changing or any seat's run moving, whatever tmux holds. A run carries on if tmux does not answer within a second; the next tick or step redraws the bar. Its ladder, top first: a login this harness needs has expired (its own,
or the one a run it launched is parked on, or `gh` while a run owes a push) is `needs you`; the Claude worker token
dying within a fortnight is `needs you` on every seat; a question on its screen is `needs you` even during an open turn, and so is one it asked with `ak notify needs` that nothing has answered, from the end of the turn that asked and through any turn a hand-back opens after it: while the turn that asked runs on, the seat is `working`, since its screen shows no question and it is not waiting for you (the question asks first: its `?` within its first 80 characters, or the command refuses it, since line two and the row show a question from its start), whatever its runs are doing (a watcher's own alert about the seat waits for its prompt); typed text nobody sent while no client is attached, with no turn in flight, is `needs you` (`unsent: <text>`, every row of a wrapped or multi-line draft) whatever its runs are doing, and with a client attached the typed text is his typing, which reads as the rungs below say; a run it launched that is unfinished is `working`, whether going
or waiting for a slot, window, target change or login the tick lifts by itself, or an error with a scheduled retry, or
`exhausted` on a window or a dead reviewer, which the tick resumes by itself unless a later merged run replaced it (then it is settled and reads `done`); a seat that ended its turn on `ak wait <session>` is `working` with `waiting on <session>` while that session itself reads `working` by its own runs or turn, never by a wait of its own, and `needs you` with `waiting on <session>, which asks you: <question>` while that session waits on your answer to a question it asked, which is no stop for the wait, until the tick has told the seat that session stopped (below) or the seat's next `ak wait` or `ak notify`; a harness turn in flight is `working`, parked run or not, and so is one whose question has come down: only its Stop ends it, or the harness's own record that you interrupted it once it had begun to answer (Claude Code sends no Stop after an Esc, and writes `[Request interrupted by user]` as the conversation's last message; an Esc before any answer records nothing but puts your prompt back in the composer word for word, so the seat reads it as your draft; once you edit or empty it, by a word or all of it, the seat reads `working` until your next prompt, since only your prompt put back whole tells an Esc from a turn still thinking toward its first answer while you type your next line); an error with no automatic resume that
still needs attention (see below), or an `exhausted` run the tick cannot resume (rounds spent, a stopped `git`, no verdict), handed back or not, until `ak run resume <id>` or `ak run stop <id>`, unless a later merged run replaced it, is `needs you` (`run <id> parked: <reason>`), and so is a `stalled` one, unacknowledged and not replaced (`run <id> stalled: resume it with ak run resume <id>`), and a merge wait only its 24 hours turned away (`run <id> waits to merge: <reason>`);
nobody in the seat any more is `needs you` with `session closed: press N to reopen`; the seat's own `ak notify done` is
`done` with the summary's first line until a newer notice, or `needs you` (`run <id> parked: <reason>`) while a run of its own sits parked and undecided, however often the session is opened, read or scrolled (a question on its screen, or typed text nobody sent, reads `needs you` over it; a job's `all N tasks finished` is no declaration of the seat's, though its card is still `Done`); otherwise it is at its prompt, which is `needs you`
with the question it asked or `waiting for you`. Your prompt after a question answers it, in the pane or over Remote Control, even after a rename: it stops blocking title sync and leaves the reason; hand-backs and `ak tell` lines reach a seat whose question is open, as the work that does not wait on the answer goes on. Recording the answer runs in the background, so your prompt never waits for a notification lock. Only a prompt handled in the seat's own pane counts. Earlier prompts, slash commands (including `/compact` and `/rename`), a line another seat sent with `ak tell` (headed `[from seat <name> at <HH:MM>, not the owner; reply with ak tell <name>]`), `<task-notification>` prompts and a line ak itself typed into the seat since the question (a hand-back, a wait notice: its typing receipt says so) answer nothing, and a turn another seat's message opened keeps a done the seat declared before it; watcher alerts keep their own recovery rules. Where the seat's harness reports your prompts through its prompt hook, only your prompt answers its own question: the seat asked and works on, so neither opening it nor its output since answers anything. Where the harness has no prompt hook, opening through ak followed by fresh output answers it, as it does a watcher's alert anywhere, unless ak has typed a line of its own into the seat since you opened it (a hand-back, an `ak tell` line, an idle `/compact`). These exclusions do not change the turn-ending rules. Each Claude seat's launch sets `crossSessionInbound` to `refuse` in its login's user settings, which Claude Code reads again when they change, so every session on that login refuses Claude Code's own messages between sessions, seats opened before included, as does a session you start there yourself: those messages reach only Claude sessions on the same account, so seats message each other with `ak tell` instead. The same launch sets `switchModelsOnFlag`, so a message Claude's safeguards flag moves that session to another model by itself instead of pausing it on a dialog until you answer. `ak orch why <seat>` says what decided it, on what evidence, since when. Text you type in the composer is an unsent draft, with or without a status line under it.

A row is number, name, orchestrator, state, and one last column: the reason for `needs you` and `done`, and for
`working` its place in the landing line, else the tasks bar (from `~/.agentkit/state/plan-<session>.md` under the seat's name or any name it was renamed from, the newest such plan winning, else from its unfinished jobs' tasks) in the room the row has: merged tasks solid, each live run of the seat part of the next slot by its step (building ¼, checks ½, review ¾, landing ⅞), dotted, red on its last round, and the count on the fill (`███▒▒░░░ 3/8` without colour); else empty, never `N running`, and never when the work will finish: the bar and its count are the seat's progress. The highlighted row opens its seat's live line under it, the seat bar's second line at the row's width, and the orchestrator is in its company's colour. `ak plan` lists its numbered outcomes. `ak plan add "OUTCOME" --check 'COMMAND'` accepts a line only when the command fails on a clean checkout of the project's default branch, without seat variables but with the project's env file (`~/.agentkit/env/<repo>.env`), as a run's checks have it. The line names the checkout it was written under and the repository there by its root commit (`~/code/acme#1a2b3c4d5e6f`); its check runs in that checkout wherever the seat is filed now, and only while the checkout still holds that repository: a path moved or reused, or a name another checkout shares, proves nothing. A line written before names the seat's checkout by name. Verifications of one plan run one at a time. Use `--eye` for what only you can judge; `ak plan tick N` marks only those lines done on your word. An
ended run is its orchestrator's business. `needs you` and `done` are messages, and opening the session is reading them.
Runs keep those row words in `ak run status`, with the parked state and its retry on the dim line; a wait that lifts
itself has an open circle (`○ waiting for claude login`), which is not a fourth session state.

Discord hears two things and nothing else. A `needs you` word held for 60 seconds with no attached client input since it began sends one
amber `Needs you · <session>` card. A `done` word sends one green `Done · <session>` card, red when the summary starts
with `FAIL`; an unfinished run delays it and a failed run drops the declaration with one log line. Publication rechecks the latest declaration, question and runs under the seat lock, so a delayed decision cannot announce newer unfinished work or page for work already completed. Only a still-unanswered question contributes its beginning; a resolved notice cannot renew a prompt past its input or install-history gate. If an answered card reopens for a newer question, its minute starts no earlier than that question, so earlier terminal input cannot suppress it. One card per episode
and recorded plan work: new receipts retain distinct verified outcomes through late handbacks, refreshed proofs, repeated or archived lines, rewritten summaries and seat renames. Newly verified outcomes get their completion even between ticks, and archiving pending work cannot discard its delayed receipt. Actual recorded receipts recover completed plan coverage after card loss, including across a later ending without outcomes. Older receipts, seats whose creation is unknown and completions without verified plan outcomes retain their episode and text/time gates. Input from an attached client since the episode began, or answering its question, edits open needs cards to `Answered`, except that a card already sent for the seat's own `ak notify needs` question waits for your answer; an untouched attached terminal does not suppress or close a card. A done edits them to `Done`, and edits never
ping; an edit Discord did not take stays on the card and is tried again at the next one. No card or retry goes out for
a seat you closed (`x`, `ak orch stop`, a pause script), whose row keeps its number, or an episode begun before this
install (`installed-at` or a fast-forward's newest module; a gone seat's when it went); `ak notify` counts from the
command. A card the webhook could not take is retried from the outbox after 1, 3, 10, 30 and then every 60 minutes.
Ghostty shows a desktop notice when another seat turns `needs you` while you are attached. Workers are refused, and the
test suites' `$AK_NOTIFY_SINK` outranks the webhook, so a test never reaches you. A card whose session is gone, neither a seat nor a saved record any more, or whose record is swept, has its open needs edited to `Answered` on the next tick, and the card goes once Discord has taken every edit. A delivered card's receipt, the message it created, names the user it pinged in its `mentions`: `state/discord-user.json` keeps that id and name, never the webhook, for the `c` screen's `Discord` row, which shows the id's last 4 digits until a card has named it. No call that posts nothing can name the user.

## The picker

Session records and `[defaults]` may list `reviewers` beside `workers`; new seats copy explicit default reviewers.
With separate groups, executors use only workers; reviews (including `--review-pr`) and spares use only reviewers. A model can be in both.
Runs save explicit groups in `run.json` at launch, show them in status and the preflight log, and keep them through handovers, refusals and resumes despite later edits; omitted reviewers keep the old shared-list behavior. Each group ranks by budget: the fraction of allowance left
divided by the fraction of window left, using the smallest provider non-session meter. The pair is the best by reviewer company -- another provider, then the executor's company, then the executor's own model -- then executor budget, then reviewer budget; equal budgets keep list order, and no model or run history gets a preference. A self-review is marked `self-reviewed` on the launch line, in `ak run status` and in `ak usage`. A model's own
`meter` still gates it. A meter at 100% used excludes a worker unless its provider or account has `credits` left, which rank it after every one with window left (seats and their accounts too) and show as `62,469 credits left`, or `$12.40 credits left` in money, on its usage row and under `ak usage`; so does a harness not installed or not logged in (no adapter or program, or
its `auth` verb says no for every subscription its provider lists, asked at every pick), with one `skipped <model>: <harness> is not logged in` line in the run's
log per pick; `--exec` or `--review` outside a bound group or naming an unavailable harness is refused, as is a resume whose saved executor no other model can take
over. An unknown budget ranks last, a pay-as-you-go provider joins only while every subscription that can run is ahead
of pace by more than `pace_margin`, and a run with no eligible pair parks `exhausted`, but a launch with no runnable
worker or reviewer (every harness skipped) is refused naming the groups, by a `--bg` launch's parent too. The orchestrator choice ignores pace (see `n`; every model spent launches the default with a WARN); a run without a session uses the
default groups and refuses task launches before any run or job exists if its executors are empty; without `reviewers`, legacy unbound picks and orchestrator resumes still work, and explicit PR reviewers may be outside workers even in a seat. Meters are cached for five minutes and each provider is probed at most once a minute host-wide, a refused worker included (Claude once in fifteen, and never before its last `Retry-After`; Muse's billed probe once in ten, whatever its meters do); a spent-window
refusal parks the provider until it refills, a usage-limit reset held or not: ak never spends one, and one held adds nothing to budget or headroom; its usage row says `1 reset in hand`, and the owner spends one by hand with `↻ spend a reset` on the Providers row of `c`; `ak usage` shows the choices, and a reading older than half an hour says `as of HH:MM` on its row and under `ak usage`. A Claude worker turn's last `rate_limit_event` becomes its account's session and weekly_all reading at once, with no request; any other meter keeps the endpoint's reading, and an older reading never replaces a newer one.

## The tick

`ak watch` runs every three minutes from cron on the server, under a lock so ticks never overlap, writing
`~/.agentkit/tmp/watch.log` and rolling it at 5 MB. Before typing new lines, it gives Enter to a composer holding
only ak's full account-switch notice, mid-turn continuation or resume nudge, even when its retries ran out and its mark
is gone. It reads the composer again under the typing lock before each Enter; other text and dialogs are left
alone, including partial lines whose last rows match a recovery notice. The whole composer must be visible,
from its opening to its closing chrome; cropped or scrolled composers and owner rows that resemble footer
text get no recovery Enter. Delivery stays at least once: a crash
between Enter and recording delivery can repeat a line.
Each tick: retries the notification outbox; reads every seat's
last error from its harness's own record of the conversation (Claude's transcript, Codex's rollout), off its screen
where it keeps none, and asks each harness's `auth` verb where a login looks gone; types `continue` into a seat stopped
on its harness's own stall words for three quiet minutes, at most every three minutes, and after an hour of that asks you once;
resumes, relaunches and brings back what Resumption says; types hand-backs waiting on a busy seat, including one whose turn stopped on background work, since its composer is open and takes a line at once, one at each quiet prompt, those of runs that wait on its decision before those of runs that merged; gives each hand-back, wait notice and told line its Enter only while the composer holds that line alone -- all of it, the end of one taller than the composer shows, or the harness's fold of one past `[screen] folds_over` -- so what you type just before that Enter is never sent with it, and counts it delivered only once the composer reads empty, so a line you edited while it waited stays yours to send; types `<session> is now <word>: <reason>. Decide the next step.` once into a seat whose `ak wait <session>` names a session that has stopped, at the seat's next quiet prompt, which ends that wait for good; types what another seat sent with `ak tell <session> "<text>"` into that session, every message waiting in one pass, oldest first, for as long as the seat takes each line: at a quiet prompt, or mid-turn where its harness holds a typed line for its model's next step (`[screen] queues_typing`, every shipped harness's) -- headed `[from seat <sender> at <HH:MM>, not the owner; reply with ak tell <sender>]`, its typing receipt naming the sender, so it is never the owner's words, and an open owner question holding none of it back, since only the owner's own prompt answers that (`ak tell` itself only queues it, under the receiver's lock, and says `queued`; a session it does not know, a closed one, its own seat, or a line longer than every configured harness shows whole in its composer (the smallest `[screen] folds_over`, Claude's 800 characters), is refused, and a message for a seat closed before it went in goes with that seat; a message leaves the queue only once its line was seen leaving the composer, so it goes in at least once and is never lost: a tick that dies mid-line is finished by the next from the composer read whole, the line alone there getting its Enter, an empty composer typed into, and anything else there never typed onto); closes idle browser
tabs; reviews others' PRs on repos this account owns and follows its own PRs on repos it does not; and once a day asks
the worker-token verb and schedules collection. A logged-out `gh` costs only the two GitHub passes. `ak watch --dry-run`
lists what a tick would do; `ak doctor` shows the slice, the tick's state and any effort a model does not take.

## Resumption

Nothing you launch is lost to a crash. A run whose loop process dies is resumed by the next tick where it stopped,
continuing the harness's own conversation (`claude -p --resume`, `codex exec resume`, Muse's `--session-id`); the first
death resumes at once, a second within ten minutes waits ten, a third within an hour parks the run and tells the seat
once. A job whose launcher dies is relaunched by the next tick in its launch directory, so its waiting tasks start in
order, while that directory is there, its seat's session exists and you did not close it, its launcher was alive (its heartbeat) under 24 hours ago, no unfinished task whose run stopped short of its ending was handed back, carded or
acknowledged, none was stopped, and this is not a third death within an hour; otherwise `ak run status` names `ak run
resume <job>` under it. A run with no output for 20 minutes has its step stopped and the loop carries on; a second
silence resumes the loop with each role re-picked from its own group and execution on another provider, trying reviewers from providers that refused nothing first and refused reviewers only as fallback; later picks use normal order. A third parks
it `stalled` for `ak run resume <id>`. Quota `exhausted`, including task and PR reviews and delivery retries, resumes when its window refills, a reviewer-transport one as
below; other `exhausted` runs wait for `ak run resume <id>`; an expired login parks `waiting_login` until the harness's
`auth` verb answers `yes`. A failed worker turn is read in its harness's own `[stall]` words and those no harness owns, whole (a `429` inside a longer number is none, and neither is any word inside a run id, which names a run's worktree and directory) and only where the harness spoke, never in the model's answer. A transient fault (`API Error`, `Overloaded`, a 5xx, an empty answer) retries the same
session after a minute; a second failure in a row hands the role to the next model in its group, and with nobody else the same session
is retried after 5, 15, 30 and 60 minutes, then hourly; the tick's silence clock starts where each wait ends. An empty
answer whose stderr (the adapter's own included) says the harness never ran (not installed, an unknown flag or model, a
refused login, even quoted as `API Error`) and names no 5xx, overload or capacity error goes to another provider at
once, or ends the run, a PR review included, `blocked` on that line. A refusal that names the account re-picks the pair from its saved groups, same worktree and round.

`ak run resume <id> [--rounds N] [--bg]` resumes the worktree, the worker sessions and the options a run left; it
refuses `blocked` and `stopped`, and needs the worktree, which lives seven days. `ak run merge <id>` retries the
delivery of a PASS whose push or merge did not finish. `ak run stop <id> [--keep]` is the one deliberate end: `stopped`
is final, and `--keep` holds the branch for a task with `from: <branch>`. After a reboot the first tick or menu brings
back Claude and Codex seats with proven conversations, once per boot, but none you closed; the tick tells one that died
mid-turn to continue it, as a run is, over at most three ticks, so it reads `working`, unless you prompted or renamed it.

### When a run goes silent

On `ak run status`'s dim line (`error · retry 14:32`, `waiting · retry after the next merge to origin/main`) an admitted
ending says why: its launch session still exists, it ended under 24 hours ago, and it was not handed back, carded or
acknowledged. Only those endings may be parked from a conflict FAIL or resumed from `error` or `waiting`, an older
tick's waits on a target ref included; by-hand runs and older endings wait for a person, and a job's run for its job, which resumes its own merge wait. The tick retries an admitted error on the
ladder above, an `exhausted` run after reviewer transport failures once a reviewer is eligible (at most hourly while it
keeps dying), and an admitted conflict `waiting` after main moves, task rounds spent or not. `ak run status <id>` on a
scheduled error keeps its retry and admission. When admission ends, an error loses its retry stamps, and it or a merge
wait reads `run <id> parked: <reason>` at once, before the tick clears an old stamp. An error with no automatic resume
reads `needs you` only while recent, unacknowledged, neither handed back nor awaiting it, and not superseded; an `exhausted` run the tick cannot resume reads the same, handed back or old, until `ak run resume <id>` or `ak run stop <id>`, unless a later merged run replaced it, and counts as `needs you` in the tally, never as `running`. A merge
wait on a target ref that no longer qualifies is inactive history: its row reads `done` with the parked reason, it adds no attention tally, neither the stop hook nor the tick counts it as work, and it can still be resumed by hand; only one its age alone turned away still reads `needs you` on its seat (above). A run recorded in the line to land holds no process and stays working without an age limit: status and the menu say `waiting · 3rd in line to land on main`, counting by when each member joined that repository's line. The tick and `ak run resume` leave it to the lander; its job follows it to its ending, including after `ak run merge`.

## Cleanup

A merged run's worktree and local branch go with the merge. A stop takes both at once, or with `--keep` the checkout
after seven days. A failed, blocked or errored checkout goes when its seat has been told or after seven days, unless a
resume can take it; its local branch stays until the 30-day removal, because a run that never pushed holds its only copy
there. A pass whose delivery ended without a merge loses its checkout after seven days, its branch kept, and a checkout
with no run record goes a day after its last use (its folder changed, or git wrote its index or moved its HEAD): a folder with no `.git`, one ak never finished making, the line's marked scratch whatever it
holds, any other only on a branch, not locked, with no submodule set up and `git status` listing nothing, untracked files
included. A seat's checkout with a change not committed, a clone, a detached one and one git cannot read stay. A run directory older than 30 days goes whole, with its checkout and branch, unless
the session that launched it still exists; a scratch run's workspace goes only with it. `~/.agentkit/tmp` entries older
than a day go, owned `/tmp` entries untouched for two days go and a gone Claude session's scratch folder after a day, a repository `TMPDIR` directly under `/var/tmp` like `/tmp` itself,
finished jobs after a week, and a state file named for a seat with no record, or an idle-compact stamp
whose wrapper is gone, a day after its last write. Trust and MCP entries in `~/.claude.json` and `~/.codex/config.toml`
that point into a gone `smoke-*` sandbox or `~/.agentkit/wt` checkout go in an atomic rewrite of just those entries, in
any layout; a file that does not parse is left alone. The collector writes `~/.agentkit/state/gc.log` and never touches a checkout under `~/code`, a live loop, or in `/tmp` a dot entry, `tmux-*`, `systemd-private-*`, another user's file or anything held open or used as a working directory. Age uses the newer of modification and inode-change times. Claude's pid records, matched to process start times, protect current conversations across hand launches and `/clear`; a client without a matching record keeps all scratch. Hidden handles are inspected read-only with noninteractive `sudo`; failed inspection defers `/tmp` cleanup. Planning scans processes once per temp directory, deletion once per batch. A checkout goes with its uncommitted work; a tree holding what this user
cannot remove is reported once, on any path, and never retried. `ak run gc --dry-run` gives each item's reason; `ak run
gc` also sweeps every merged worktree, regardless of repository or git registration, and day-old `smoke-*` sandboxes,
reporting count and space freed. The tick takes a leftover merged tree only if clean and registered. Each sharded smoke piece removes its own sandbox. A passing unsharded smoke suite removes its sandbox; a failed one keeps the newest failed sandbox and removes older ones whose suites ended.

## The config file

`~/.agentkit/config.toml` is copied from the checkout's `config.default.toml` by the first `install.sh` and never
overwritten. The menu's `c` screen changes it at once: `orch` (`●`), `exec` and `review` (`■`) are the highlighted session's, saved to its record, `‹ xhigh ›` a model's `effort`. An effort step is drawn at once from the catalog in hand; a harness's model list still being fetched counts from the next step. Reviewers keep one model, executors may be empty, and only a flip no run could start from is refused. Omitted reviewers show the worker marks until the first mark flipped writes separate lists.
A model's own screen sets its `model` from the harness's catalog (the effort following to one the new model takes) and its `effort`; `Remove` asks first, keeps the last model and the model's `[providers.*]` table even when it was that company's last. The line under the rows on `config · <name>` belongs to its harness and model id: `Reviewed` counts finished reviews, `caught` blocking findings, `already on main` follow-ups present on the base, and `unproven` notes, excluding stopped and suite runs. The shipped `opus` model uses Opus 5.5 (`claude-opus-5-5`). The keys:

- `max_runs` (0, no count cap; `ak run status` names the cap in force), `min_free_mb`, `max_load` (unset: ak's CPU pressure
  gates; pinned: the host load check, 0 disables it), `run_memory_max_mb` (one run's cap in MiB); `AK_MAX_RUNS`, `AK_MIN_FREE_MB` and `AK_MAX_LOAD` override them.
- `max_gates` (unset; 0 no cap): a pinned host-wide count for suites without `AK_SHARD`; pieces always use live headroom. Unset, a suite starts when the slice's live CPU and memory headroom fit one more, or none run. Waiters show `waiting for a heavy suite turn · N running · M more fit` from the admission reading, the wait charged to neither silence window nor ceiling; `ak run status` names the count in force and whether it is derived or pinned; a `config.toml` a suite cannot read means derived, named in the run log. A suite holding a turn runs with `AK_HEAVY_TURN=1`; one that runs one copy at a time behind a host-wide lock of its own should then not wait for that lock but exit 75 (EX_TEMPFAIL) at once while another copy holds it: that is no failed check and no re-run, the turn goes back and the suite runs again each poll until it starts, the polls charged to its ceiling and the turn waits not.
- `pace_margin` (10): the picker's pay-as-you-go margin above. `[defaults]`: `orchestrator`, `workers`, optional `reviewers`, the last created session's, what `n` starts from; an older
  file's `[tiers]` reads as the first of `A` over `B` without it, and the next save writes `[defaults]`.
- `[models.<name>]`: `harness`, `model`, `effort` (one that model takes, per `adapters/<h>.sh models`, or `none`), `provider`,
  `meter` (a meter of its provider that gates only this model). MiMo's `none` turns its thinking off and `high` leaves it on.
- `[providers.<name>]`: `mode` (`subscription` or `payg`). MiMo's comes from the global OpenCode `opencode.json`: a plain `https://` token-plan URL is a subscription, and anything else -- another host or scheme, a backslash or user part, a substitution, `OPENCODE_CONFIG`, a file not plain JSON -- is payg. OpenCode runs with project config off, so no workspace changes it. For Muse `usage_model` and `usage_effort`: the one cached request its meters come from.
  `accounts = ["default", "second"]` lists subscriptions, `default` the usual login; Claude keeps another's token in
  `secrets/claude_oauth_token.second` or its login in `~/.claude-second`. Every provider's subscriptions work for seats, workers and meters, each adapter keeping a named one's login apart (Codex's in `~/.codex-second`); turns use the account with most room, then the next. The menu shows one usage row per subscription in config order, numbered in roman numerals (`Claude I`, `Claude II`), each with its week's bar and its 5-hour note (`5h 40% left`, or `5h spent until 14:00` once spent).
  `seat_account = "second"` names the subscription new seats open on while it has room, then the others by room (without it, `default`); a seat's record keeps the one it opened on as `home_account` (`default` when absent), and an idle seat moves back only to that one once it has room.
  A seat whose subscription runs out (its harness's refusal is read off its screen, with or without a status line under the composer) resumes its conversation on the next account of the same provider with room and a working seat login (`auth seat`, or the named Codex account's own `auth.json`); new seats also check the login when choosing among configured accounts, and accounts with only a worker token serve workers. A manual new seat can open the configured usual login to sign in when none passes. If none is available during recovery, it reads `needs you` with `<provider> out of usage until <time>` once and recovers when usage returns; a refilled account keeps its login without another auth check (without a proven conversation id, the seat continues in place). Opening it to look keeps recovery active, drafts and questions defer it, closed seats stay closed, and idle prompts stay idle.

Secrets are in `~/.agentkit/secrets/`: `discord_webhook`, `discord_user_id` and `claude_oauth_token` (the worker token
`claude setup-token` mints, dated a year from its file). A repository's `AGENTS.md` front matter holds `tests:`, its
full suite, which a review of others' PRs runs as its check, `cleanup:`, one shell line ak runs once in a run's checkout
before removing it, and `users:` (above); task files go by convention in `~/.agentkit/tasks/<repo>/`. When a whole suite takes more than two minutes, ak starts a run in its session to split the `tests:` line itself, once per repository and line. The line then reads `AK_SHARD`: `k/N` selects its 1-based share, unset runs everything. ak runs the pieces together in one checkout, sizes them from live CPU room, host and run memory headroom, and measured cost, logs each separately, and retries red pieces alone.

## Adding a model or a harness

Press `c` and pick `+ add a model`: harness, then model, then effort, in the three lists the README describes; Enter
adds it, named from its label and offered as orchestrator and as worker at once. Or write the `[models.<name>]` block.
On `Providers`, `+ add` offers a provider `config.default.toml` has and the config has not. Pick one with Enter or a click on `⏎ add`: ak installs a missing harness, logs it in on the terminal, then adds its shipped `[providers.*]` table and first catalog model; `− remove` asks first, `Keep` picked, and a removed provider (`config.remove_provider`) leaves no model or usage rows, and `n` passes over its models in `[defaults]`; the last stays. `+ add` also offers another subscription of each provider the config has, as the name it will get (`ChatGPT II`): its adapter's `login` runs on the terminal under a fresh `AGENTKIT_ACCOUNT`, and only a login that finishes appends that name to `accounts` (`default` first when it was empty). `− remove` also lists each subscription of a provider with several but `default`, and takes only that name out of `accounts`. Neither removal deletes a login file: each records the login it took out (`config.keep_login`, `~/.agentkit/state/kept-logins.json`), and `+ add` lists every one whose adapter's `auth` still passes as `Use <who>` (what that `auth` says after `; logged in as`, else the name its usage row had), put back with no login: into `accounts` under its old name, or with its provider as it ships when that went too.

### Adding a harness

A harness is `adapters/<h>.sh`, `adapters/<h>.toml`, and a `[models.<name>]` line naming it; `tests/fixtures/adapters/echo.sh` and `echo.toml` are a working example.
It has three duties: hand the worker the prompt as written; let it close its turn with `ak hand-in done`; return `final.md` and a `session_id` that a second turn resumes. ak itself ends whatever a turn leaves running.
`python3 tests/check_harness_contract.py` proves all three on every adapter installed with a login; append a harness name to check only it. Live check 3 calls this same check. Each adapter's `[check]` table names its explicit `model` and `effort`, so the check names neither; its model belongs to `[catalog]` and uses that model's lowest effort.
The script implements the verbs: `run <model> <effort>
<workspace> <prompt> <out> [<session>]` (headless: the prompt goes from its file or stdin, never as one argument, which Linux caps at 128 KiB; writes `final.md` with the turn's last message, `session_id`, `stderr.log`, `events.jsonl`),
`usage` (one JSON object of meters, `error` set rather than a non-zero exit, and `credits`, the number of bought credits left, where the provider has them: Codex's while ChatGPT says `has_credits` and no `overage_limit_reached`, Claude's extra usage while it is on: the smaller of what its monthly limit has left and its prepaid balance, the limit unbounded when none is set and the balance while auto-reload is on, `"unlimited"` when both are; `currency`, an ISO code such as `USD`, says they are money in that currency), `auth [seat]` (one line, exit 0 with a
token, ending `; logged in as <who>` where it can tell, or 1 with why not; never a network call), `interactive <model> <effort> [<session> [new]]` (the TUI command line,
with the harness's own bypass flag), `hooks` (install its lifecycle hooks idempotently), `models` (an `id<TAB>label<TAB>efforts` line per model, efforts strongest last, `none` for a model that runs at no effort, empty
where the harness does not say, which `c` then offers at its harness's `[effort]` vocabulary: live where the harness lists them (Claude's models API, Muse's `muse serve` `model/list`),
else its `[catalog]`, which also stands in for a listing that fails, takes ten seconds or has no `timeout` to stop it), `install` and `login` for a fresh box, and
optionally `reset-status` and `reset` where the provider hands out usage-limit resets. Grok's `auth` passes on a refresh
token, since grok renews its six-hour key itself. Antigravity's `usage` reads the Gemini window of agy's own `/usage`
panel off that panel's endpoint. Refused, both `usage` verbs let their harness renew (`grok models`, `agy models`) and
ask again, and a renewed grok key still refused is `no login` until grok holds another or the endpoint answers it.
Claude's `auth` and `usage` first have Claude Code renew a lapsed seat login that holds a refresh token, one login at a
time, with its cheapest turn (`haiku`, one word, no tools, no saved conversation); only a failed renewal says `run /login`.

`interactive` is where the rulebook goes: a launch has written the file already, in its own process, and names it in `$AGENTKIT_RULEBOOK`; without one, `python3 tools/rulebook.py "$AGENTKIT_SESSION"` writes it and prints its path (`rb=${AGENTKIT_RULEBOOK:-$(python3 …)}`),
and the command line hands it to the harness, adding no instructions of its own, so an orchestrator behaves one way
whatever runs it. Anything else the launch writes goes beside that path, so a dry run's is thrown away with it. What a harness must check before its pane is replaced is its plugin's `checked`: the launch runs it in its own process and tells the adapter in the environment, so `interactive` starts no Python for it (Claude's settings, `$AGENTKIT_CLAUDE_CHECKED`). A
variable the seat's launch sets goes under `[launch] seat_env`, and the core drops it from child environments. What the
harness runs as besides its `[update] version` program, such as Muse's `muse-bin-<build>`, is named under `[launch] programs`: a tmux session made by hand is a seat only while one of those runs in it.

The manifest names `[worker] state`, the directories keeping its login and sessions (empty if none), and `logins`, credential files and locks that may be lent as symlinks: their targets allow refresh too. Paths accept `~/` and `$VARIABLE`; an unset or empty variable skips that path. Include its environment overrides, account directories and shared session stores; ak creates missing state directories and linked login files or locks before the turn. Everything else is data: `[check]` (contract model and effort), `[update]` (version, upgrade, revert, latest commands), `[usage]` flags,
`[instructions] read_limit` (the bytes of a project's `AGENTS.md` the harness reads on its own before it drops the rest),
`[conversation]` (what a seat owns), `[hooks] installed`, `[stop] enforce`, `[authority]` and `[[hooks.event]]` (which
of hooks and screen decides each live fact), `[screen]` and `[[rule]]` (the composer and dialog patterns read off the
bottom of the pane; `ruled = true` draws the composer between two rules, and every row between them is the draft, one that reads like a rule or starts with an indented prompt mark too; `folds_over` is the most characters a typed line shows whole before the harness folds it into a paste placeholder, and `folded` is that placeholder as its composer shows it; `scrolled` is what a composer scrolled past its height draws beside the text, a scrollbar or a count of the rows above, which is never read as typed), `[stall]` (its own words for a spent quota, a refusal, an outage and a harness that never ran, beside the ones no harness owns), `[resume]`, `[auth]`
(title, remedy, signatures), `[compact]` (the keys, the signal, where context is read, the idle minutes, the stash key), `[effort]` (its vocabulary),
`[catalog]` (models, efforts) and `[worker_token]` where it mints one. Then add `[providers.<name>]`.
An event with no state in `[[hooks.event]]` leaves the seat's last hook fact alone; a passive notice cannot end or reopen a turn.
`$AGENTKIT_ADAPTER_DIR` points at another adapter directory, which is how the offline suites run the loop with no model
behind it. Behaviour that needs Python goes in `agentkit/harness/<h>.py` behind one interface where every hook has a default (`tokens` reads `events.jsonl`; Muse's are in its session store). Reports updating ak's records go in the out dir; `record_turn(out, state_dir, account)` imports them after the box closes.

## The installer and updating

The README's one command works on a fresh macOS or Linux machine, safe to run again; `--server` and `--client [alias]`
set the role when the default is wrong, and `--phone-key KEY|FILE` appends the phone's key. It makes the directories
under `~/.agentkit` and `~/code` and puts `ak` on PATH. It installs what is missing: tmux, mosh, git, gh, jq, python3
3.11+, node, cron; on Linux also chromium, security-only unattended upgrades and Tailscale. With no harness installed it
asks once which to install and log in, or `all`, one provider being enough, and each adapter installs and logs its own
in, in a terminal; on a machine that has one it checks and logs in only those installed, wherever their binaries live,
adding none unasked. `gh auth login`, the Claude worker token, and the Discord webhook and user id are each asked for
once, only where missing and there is a terminal; the git credential helper and author are set from `gh` without asking.
On a server it also writes: the bypass defaults and update pins into `~/.claude/settings.json` (backed up beside itself
when it changes) and `~/.codex/config.toml`, each harness's lifecycle hooks through `adapters/<h>.sh hooks`, and the browser MCP registration. The server installs the tick's cron and, where a user systemd manager exists, writes
`~/.config/systemd/user/agentkit.slice.d/limits.conf` on every install, pinned by `slice_tasks_max`, `slice_memory_high`,
`slice_memory_max`, `slice_cpu_quota`: seats in `agentkit-seats.slice`, runs in the lower-weight `agentkit-runs.slice`. Where `sudo` needs no password it first derives the user unit's own `agentkit-limits.conf` from the machine (80%/90% memory,
4% of tasks, the slice's CPU quota, `OOMPolicy=continue`), taking over only its own or the hand-written file and leaving other drop-ins alone; without it, one line says to run `sudo -v` and re-run the install. Under a HOME not the account's own it touches nothing outside it.

`ak update` upgrades the harnesses this host has (any other is a `skipped` line), and none while a session works (it names those sessions and exits 0); it verifies them with the gates that can run there and rolls back a harness the gates fail, then fast-forwards `~/agentkit` itself and reruns `install.sh`, working sessions or not, as each `ak watch` tick does after a merge to main. `tests/live.sh` holds agentkit's checks that need the outside world, which the landing suite leaves out: where origin/main has one, the checkout moves only to a commit it passed on, exactly that one however far main has moved since, and until one has, nothing moves or reinstalls. Each tick starts it for origin/main when no check of that commit passed and none is running, detached, in a throwaway worktree of the commit under `~/.agentkit/state/live-checks/`, and ends it at two hours; a red one runs again after 10 minutes, 30, an hour, then hourly, and the second red in a row (one provider blip in its real model calls is not main broken) is handed back once with a bounded failure report and closing summary, to the newest live seat whose runs merged into agentkit, and a newer origin/main is checked as soon as none runs. A harness upgrade runs it right after `tests/smoke.sh`, and its failure reverts like smoke's. A checkout that is dirty, off main or cannot fast-forward is left as it is; that, or a failed fast-forward or `install.sh`, is said once per origin commit, in the tick's log and by `ak update`, and each tick reruns a failed `install.sh` until it passes. It runs in the foreground and says per harness whether it was upgraded, reverted, kept or left unchanged; `--dry-run` prints the plan. `ak` opens at once, then a detached process asks origin whether `~/agentkit` is behind and fetches, fast-forwards and reruns `install.sh`, filling the rule under its header while keys keep answering. The main screen starts again on the new code with the same session highlighted; an open sub-screen and its draft wait until you come back. Leaving lets the update finish; a failure says why as a notice, and the next `ak` retries while origin is ahead. A client starts the update and connects over ssh at once; its next `ak` takes the new code. Overlays and dry runs skip it. A tick upgrades a harness behind its `[update] latest` release, asked hourly at most, in the background through the same gates and rollback, sessions working or not, one at a time; a failed gate is said once in its log and that release is tried again a day after its last start. A worker turn that fails while its harness is being installed or reverted starts again on its session once that swap has ended, rather than reading as a harness that cannot run, and a launch naming a model whose harness was asked during one waits for it to end and asks again before refusing. Every harness ak ships names one, and a newer Muse build of the same X.Y.Z (`1.4.1-R4503.1`) is a newer release.

Agentkit’s own suite accepts `AK_SHARD=k/N` (1-based): each piece owns its checks and remaining test files, keeps dependent checks together and uses separate sandboxes; unset or `1/1` runs everything. The tmux safety guard runs in every piece. agentkit's own `tests:` suite runs `tests/smoke.sh` beside `tests/every_file.py`, streams smoke's output first, then follows every_file's buffer to its end, and runs with `AGENTKIT_ACCEPTANCE_REQUIRED=1` and, where the host allows a network namespace (`unshare`), with nothing but loopback: it tests agentkit's own code and reaches no real model, GitHub or Discord. The retry checks advance a test clock through the unchanged backoff schedule. Checks 1 to 5, 6, 6b, 6d, 6f, 6g, 31a, 31d and 31e need the outside world and run only in smoke.sh's live mode, beside every other check: `tests/live.sh` starts it, and the host and `ak update` run it as below. `tests/every_file.py` runs every `tests/test_*.py` that smoke.sh does not, each once, without the caller's `AGENTKIT_*`/`AK_*` variables, outside smoke.sh's lock. Unknown files start first, then longest first by their last measured time on this host, cached under `~/.cache/agentkit/test-times/<hostname>/` outside the checkout. Its pool grows with live host and cgroup memory, past the core count for waiting files; each start samples current CPU pressure and waits while stalls exceed the 20% ceiling or its slice exhausts its CPU quota. A file that fails runs once more alone, after the pool and after `tests/landing.py`'s smoke.sh and contract have ended: passing then, it counts as passed, is printed as `flaky:` with its first run's last lines and counted in the tally; failing again, it is named with its re-run's last lines. `tests/landing.py` also runs `tests/gate_contract.py`: on a stand-in checkout it proves every test file runs once in some share and a failing or empty one fails, so every_file's pool and order stay free to tune. Any part failing fails the suite. A file needs a positive unittest tally or, for other scripts, a `TESTS_RUN=N` line after its checks. Python imports under `agentkit/`, `tools/`, `bin/` and `tests/` must use the standard library or repository modules; that check includes files smoke.sh already ran. The live mode keeps a pool of private smoke targets, `<login>/agentkit-smoke`, `agentkit-smoke-2`, `agentkit-smoke-3` …, each under a host-wide lock of its own (`/tmp/agentkit-smoke-remote.lock`, `/tmp/agentkit-smoke-remote-2.lock` …), and `tests/e2e-fresh.sh` keeps private `<login>/agentkit-e2e` under `/tmp/agentkit-e2e-remote.lock`; a repository is created only when missing with the scopes `gh auth login` grants, and a gate resets the one it holds: force-push `main` to its seed commit and delete leftover `ak/*` branches. Provider logins are shared as the host's seats share them; only a remote would be reset under another suite, so the live suite takes a target for check 4 alone, from the seed until its delivery is read, and runs every other check beside other suites. Check 4 takes the first free target; when every existing one is busy and the pool is smaller than the heavy suites the host admits at once (the loop's own count), it creates the lowest number missing, and it waits only at that bound; the pool is the repositories the account lists, listed again every minute while a suite waits and before it takes a lock that came free, never the lock files; suites list, choose and create one at a time under `/tmp/agentkit-smoke-remote-make.lock`, and a listing that failed creates nothing; a suite that dies gives its target back as its lock's holder exits; each run title carries the suite's pid, as do the fixed names of the seats checks 6f, 20e, 25 and 34 start, so two suites share no run id and 6f's seat no systemd scope. The e2e gate holds its lock from its GitHub run through exit. A suite that cannot take a target or the lock fails that check and runs the rest. Cleanup is registered before HOME setup, so setup failures finish their retention receipt and keep the sandbox. The smoke suite reads shipped `config.default.toml` in its sandbox HOME and ignores the host's own agentkit config. It links individual credentials: `.claude/.credentials.json`, `.codex/auth.json`, `.config/muse/auth.json`, `.grok/auth.json`, `.local/share/opencode/auth.json`, Antigravity's `.gemini/antigravity-cli/antigravity-oauth-token`, GitHub's `.config/gh/hosts.yml`, `.agentkit/secrets/claude_oauth_token` and the desktop's `.local/share/browser-bridge/Xauthority`. Grok's `auth.json.lock` is shared too, so refreshers use the caller's lock, and so is `.agentkit/state/harness-swaps.json`, so a harness the host is reinstalling is waited for in the sandbox too. Harness login sources honor `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `GROK_HOME` and `GH_CONFIG_DIR` before those overrides are cleared for the sandbox. No caller directory is linked. It copies `.claude.json` for the account and MCP fields, `.gitconfig` and `.config/gh/config.yml` for GitHub access, and `.config/opencode/opencode.json` for installations storing static API keys there (honoring `OPENCODE_CONFIG_DIR` or `OPENCODE_CONFIG`). The Discord webhook, from `AGENTKIT_DISCORD_WEBHOOK` or `.agentkit/secrets/discord_webhook`, is never in the sandbox HOME: check 5's GET alone is handed it, in a HOME of its own, and the notification sink blocks posts. Installer binaries stay on PATH without linking their directories, and Muse's raw cached readings are copied with their original age to avoid another paid probe. Claude's direct MCP call uses the worker token when available, as its workers do. A harness in the sandbox renews the caller's login as it would at home. If Claude or Grok renames over a credential link, `tests/merge_logins.py` returns only valid tokens with a later expiry than the caller's current login before either the suite or `--claude-stream` removes its sandbox, writing the whole file beside the caller's and renaming it over the path that file resolves to. Cleared, invalid, expired or older logins never overwrite the caller's; a write failure preserves the sandbox and fails the gate. Settings, hooks, project trust, caches and MCP registration stay in smoke.sh's sandbox: it writes nothing outside its sandbox but refreshed logins, and a run is the suite's by its task or repo under `~/.agentkit/tmp/smoke-<stamp>/`, never by a `smoke-` id or title, and counts in no seat's tallies or offers. Checks needing an uninstalled harness, a missing login, a Discord secret, a user systemd manager or the shared browser skip as not on this host and count as passed, like a throttled meter's. Check 3a separately asserts that Claude streams events before its successful result and that `final.md` and `session_id` match it. Check 3 is `ak update`'s proof, in the live mode, that every harness still works: the standalone `tests/check_harness_contract.py` discovers adapter manifests; every harness installed with its login writes a file from the prompt, closes with `ak hand-in done`, returns `final.md` and `session_id`, then resumes that session and recalls the filename after the check removes the file, each one without is named as not checked and never counted as passed, and the suite fails when check 3 makes no real call at all (a settings file with no key in it, such as OpenCode's `opencode.json`, is no login). `tests/e2e-fresh.sh` links every harness's login the same way, from the same overrides, returns a renamed-over one the same way, finds each harness binary on the caller's PATH or in its installer's directory, asks each adapter's `auth` whether it can log in within the 20 seconds `worker.auth_ok` allows (Claude's worker token counts), and skips what the host lacks likewise; a lent login that is refused or unanswered fails. Its menu seat needs Claude's own pair and its GitHub run Claude and Codex. An exhausted model skips with the reason; the skip counts as passed when the same suite made a real model call that passed, and otherwise leaves the gate incomplete. Expired, malformed or unreadable saved logins fail. Exhaustion is checked per model on the usual login the sandbox borrows, in both its snapshot and the host-cache fallback. A failed live call that announces quota exhaustion or a billing refusal also skips, recording the refusal in the suite's snapshot so later checks avoid that provider even when its last meter was below 100%; other errors still fail. The GitHub run takes the executor and reviewer `ak run` would pick among every configured model from the suite's snapshot (`tests/check4_pair.py`), names them when it passes, and skips before resetting its remote only when every model it can run is exhausted, or as not on this host when it can run none; each MCP check skips when its required model is unavailable or exhausted. `bash tests/smoke.sh --claude-stream <out-dir>` captures events for the offline reader fixture; its sandbox HOME is a separate temporary directory removed on exit, leaving no credential links in the output.

## The Mac bridge and the shared browser

Drag a file into a session on the Mac: the agent runs `ak fetch <path>` on the server and reads the copy it prints, in
`~/.agentkit/macbridge/inbox/`. On macOS `install.sh` adds a LaunchAgent that connects out to the server over SSH and
sends only requested files, so Remote Login stays off; a reader under the terminal app supplies files macOS lets only
that app read, and a new terminal tab or `ak` starts both. It logs to the Mac's `~/.agentkit/macbridge/macbridge.log`.

The server runs one Chromium on a virtual display whose profile holds the real logins; it speaks CDP on `127.0.0.1:9222`
and five system units keep it up over reboots, plus one more for the browser tool: a single shared Playwright MCP server
on `localhost:8931` serves every seat over HTTP, from a package `ak browser install` pins once, never fetched per session.
Agents reach it through the `browser` (by URL) and `desktop` MCP servers `ak browser mcp-register` registers for Claude
Code and Codex, and Muse through `browser/bridge.py`. `ak browser status` shows the units, tabs and noVNC URL; `ak browser
login` prints the URL and password for signing a site in by hand; `ak browser install` stands it up where there is none.
The tick closes a tab idle for an hour or past twelve open, and one a run or seat opened closes when it ends or stops; Chromium is never restarted. noVNC binds to the Tailscale address.

## The history

Every run is recorded in `~/.agentkit/history.db`: repository, models and the launching seat's orchestrator, rounds,
verdict, timestamps, active seconds per step (checkpointed every 30 s; parks, slot, login and retry waits
are no step's), the seconds it waited for a slot and for a heavy-suite turn of its own, counted by the waiting process as it polls (one that dies loses at most a poll), the seconds its landing checks waited for a heavy-suite turn, counted the same way by the lander, and the seconds it held a place in its repository's landing line, from the record write that gives it one to the write that ends it -- landing, leaving, a stop, a wake to fix; recovery that keeps the place keeps it counting, and a slot admission while it holds one counts as both
(summed across resumes; a row from before they were kept reads as not recorded, never zero), tokens where the harness reports them (else unknown), peak process-tree memory, session, and the task's
words, goal points, checks and files changed. Merged runs also keep additions plus deletions, excluding files marked
`linguist-generated` in `.gitattributes`. Smoke and e2e runs are never recorded; an older agentkit's rows are read
as written, never rewritten. Statistics skip
stopped runs and suite runs, by name or run record. History is best effort.
`ak run status --history` compares the last 7 days with the 7 before for products and ak:
runs ended, shares merged in round 1 and ended without merging, median wall hours to merge and reported tokens per merge, ak's share of all recorded tokens (failed work included), and its committed code lines and README words now and 7 days ago; for all ended runs, the share of run time spent waiting for a slot or for a heavy-suite turn of its own, and the hours spent holding a place in a landing line, the lander's checks included, with the hours those checks waited for a heavy-suite turn (not recorded for a week with a run that ended before they were kept); a run started again since its ending (a resume, a delivery retry) counts there at its next ending.
It never picks a model or changes a limit; it also shows median rounds by task size per repo, and the bytes of the `AGENTS.md` that repo's last ended run handed its workers, measured as the ceiling measures it, against that ceiling, and nothing once that run was handed none (no file, or a link). Each run's row keeps that size, read at its base. Neither it nor `ak usage` prints per-model
success rates: a run's verdict describes the task, not the quality of its models. A run's own directory is
`~/.agentkit/runs/<YYYYMMDD-HHMM>-<slug>/`: `task.md`, `run.json`, `log.txt` (the whole loop, with a `WARN` line per
retry), `result.md` (linking a scratch run's files) and `round-<r>/<role>/{prompt.md,final.md,stderr.log,events.jsonl}`.

## Troubleshooting

- A harness login expired: open the seat and log in there; for `gh login expired`, run `gh auth login` on the server. Parked runs resume by themselves. For `claude worker token expires in N days`, run `claude setup-token` and replace `~/.agentkit/secrets/claude_oauth_token`.
- A dropped Mac file the server cannot read: open a new Mac terminal tab or run `ak macbridge --reader` there, then fetch again.
- Test one headless turn: `ak worker opus prompt.md --workspace ~/code/foo`.
- A stale usage reading: open the menu; it reads each provider again within a minute, Claude within fifteen or its endpoint's longer `Retry-After`.
- The slice ceiling: pin `slice_tasks_max` and friends in `~/.agentkit/config.toml` (an install rewrites its own `limits.conf`), or `systemctl --user set-property agentkit.slice TasksMax=4096` for now; the user unit's ceiling above it follows the machine where `sudo` needs no password.
- A failed `ak update` that could not restore Muse: its snapshot is under `~/.agentkit/tmp/muse-snapshot-*`, named in the log.
