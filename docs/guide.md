# How agentkit works

One interactive orchestrator plans with you and builds, whatever the size (its PRs go through `ak run --review-pr`); its rulebook
lists who does the work case by case with the reason, and it writes task files only for independent pieces that share no file
with its work, when its session has workers. Headless workers execute, another model reviews where the workers allow one, else the executor's own, and a script keeps going until the checks pass and the reviewer says PASS; then the run joins its repository’s landing line to merge its own PR. Wired in:
Claude Code, Codex CLI, Muse Code, Grok Build, OpenCode and Antigravity CLI. Standard library Python 3.11 and bash only.

## The session

Run listings load their shared cache once per process, then open only changed `run.json` files.
The cache at `state/run-records.db` updates individual runs in SQLite transactions, so one
run changing does not rewrite the history and concurrent readers see complete records.
A task or repo path that raises a symlink-loop error before or after resolution does not
identify a suite run, even if `..` follows a loop or a missing directory.

A session is a tmux session on agentkit's own server (`tmux -L agentkit`), so it outlives the connection that made it
and the orchestrator's process too. A bare `ak` is the menu on the server, on a client (over the ssh alias `install.sh
--client` recorded) and as the phone key's forced command `ak attach`. A tmux session there that agentkit did not start
and that runs no interactive agent in its panes, such as a watcher loop, is not a session: no row, no card, no count.
Ak workers (`AK_RUN_ROLE=worker`) and their descendants do not count; any old card closes on the next tick.
Each `new-session` a seat runs through its tmux shim carries that seat's name in its session
environment (`AK_TMUX_OWNER`). On ak's own server, the tick closes these auxiliary sessions once
every pane has been dead for a day, after saving their last screens in an exclusively created
file under `~/.agentkit/tmp/`. Untagged sessions, live panes and seats are excluded from this pass.
The shims keep the caller's Python environment unchanged when handing commands to the real binary.
An older project Python that cannot import the guard still runs the real command.

New seats and respawned panes receive the caller's `HOME`, harness state-root overrides declared by adapter manifests, notification sink and sink log, webhook override and owner mention. The session's environment is refreshed too, so its menu and future panes use the same state and delivery. A failed respawn keeps the old harness's environment for its menu and future panes. Absent overrides are removed: a sandbox probe keeps its state and delivery destination, and a normal seat clears an inherited test sink.

The key line stays the keys whatever the pointer rests on. The subscriptions are a
grid of gray meters under the header; one under the pointer takes its company's colour and the line under the
grid says the rest of it; the `i` page is gone. On a short empty menu, readings use the space
above the empty-state message and keys; no space is reserved for page controls.
A page fade does not shorten a later detail reveal or a seat's news glow.
Breathing dots, line tips and task squares fade in with their containing rows.

`n` opens the new seat's row in its place on the main screen, under the highlighted seat's project, numbered as it will be once made, and the line under it shows the crew it starts with: the highlighted seat's executors and reviewers, or from a heading the last creation's. An empty name (or pipe EOF) leaves `new`, then `new-2`, unnamed until its orchestrator knows the job and names it as briefly as possible in at most three words. Any rename ends auto naming; an unnamed seat gets the rule again on resume. The picker shows every model with `orch` (one choice), `exec` and `review` marks. ↑↓ move between models, ←→ between roles, space flips the selected mark, a click flips the mark clicked, Enter starts, Esc goes back. The role headings stay visible while rows scroll. Both role groups are saved in the session. Reviewers keep at least one model; executors may be left empty, the orchestrator's own `exec` mark then drawn filled and dim: it builds everything, and `ak run <task.md>` from that session is refused in one line before any run exists, while its own `ak run --review-pr` still runs. Only a choice or start no run could start from is refused in one line. Chosen already, the last created session's: `[defaults]
orchestrator` (shipped `opus`), or while it is spent the first model in config order that is not, and the `[defaults] workers` (`opus astra`) and `reviewers` (workers when omitted) not spent; a group whose defaults are all spent falls back to a fresh model that is not the executor itself before the executor. From a pipe the name, orchestrator and workers read one line each, Enter taking each default; reviewers inherit the defaults, and
`--dry-run` starts no session. The seat opens in `~/code`; `ak orch <name>` keeps the shell's directory and reopens an existing seat; a new seat opens only from a terminal, so an agent's `ak orch <word>` opens nothing and prints the commands. As soon as the project is known, `ak orch project [<seat>] <checkout>` files this seat (or the named one) by checkout name or path; only known checkouts are accepted, and it stays there until filed again. It then lists what is in flight on the checkout: each other session filed there or with a going run on it, whatever it is filed under, with its open plan lines (of a session filed elsewhere, those written on this checkout) and the files its going runs on the checkout change against their base, or a queued run's `files:`; sessions with neither are left out. A going run launched from no session shows as `run <id>` with only its files. A seat never filed so is refiled by each launched run under the project most of its runs belong to,
counting a run from its launch, still queued for a slot or not, for the checkout under `~/code` or `~/agentkit`
(agentkit's own; a second clone at `~/code/agentkit` counts as it) its task's `repo:` names, else for the one its task's `~/.agentkit/tasks/<project>/` is named for, never
one it merely inherits, and a worktree, sandbox or scratch workspace for nothing; a tie keeps its project. A seat with no
project is filed at the next menu draw or `ak watch` tick once one of its runs counts. `c` on its row opens the config with that session's orchestrator, executors and reviewers as its marks (on a heading only efforts): the arrow keys move, Enter, space or a click on another model's orchestrator mark asks `Move <name> to <model>?` under the rows (`Keep` picked, Esc keeps; `menu.move_asked`) and on `Move` moves the seat to that model at once under the same name, its runs, plan and record staying with a handover as the new one's first prompt, and on a role flips a mark and saves it to the session's record at once for the runs it launches next, `r` opens the models screen (`menu.models_screen`; the line under the models says what `ak models` recommends per role, off the matrix the tick last computed, or `nothing yet: ak models`): every model the matrix has a row for against the boards, one a row with its effort between arrows ←/→ step (its quality per role and its cost following, nothing saved), the recommended row per role and the rows as good, and the knob `as good as the best: within ‹ 5 ›`, whose ←/→ step `within` in config.toml at once (on a narrow screen the harness column gives way, then the cost); `r` there makes the executor and reviewer `ak models` recommends the seat's marks where an entry runs that model on that harness (the one running the row in that role, `matrix.runs`, else the first such entry; the line names it) and sets the row's effort as that entry's `exec_effort` or `review_effort`, unset where it is the entry's own effort or the row names none (`menu.take_advice`), and Esc goes back to `c`. On `c`, Esc goes back; reviewers keep one model and executors may go to none, a choice leaving no allowed pair is refused in one line, and so is a model whose harness is not installed or not logged in, or whose meter is spent. A model since removed from the config is passed over in a session's groups when its record is read (`config.load_session`), the way `[defaults]` passes one over, its orchestrator keeping its name until another is picked.


At launch, the rulebook reads `What ak is for` from the agentkit checkout's `AGENTS.md`, where present and unless the
project's `AGENTS.md` it hands after carries that same section as its own (a copy quoted in a template is none), then `orchestrator.md`,
this host's `~/.agentkit/rules.md` where you wrote one, and the body of the `AGENTS.md` on the default branch of the project the seat is filed under, as its workers get it; each `ak watch` tick fetches it from origin, so a merge there reaches the seat as a rulebook change, and a launch fetches nothing of a project that has been fetched: it reads the rules as last fetched, and fetches first only a project nothing has fetched yet. Its adapter hands it over
for that launch only (Antigravity's as an `--agent` definition in `~/.agentkit/state/antigravity`), never writing into your
own `~/.claude`, `~/.codex` or `~/.gemini`. A seat left open across a change to its rulebook is told with its next prompt, where its harness's prompt hook carries context: its current rulebook is written to a file of its own, and what changed since the one it holds -- the rules it last said it read, else its launch's -- to another, as a unified diff; every prompt of its own conversation names the change, or the whole file where ak no longer has the one it holds, until the seat runs the `ak orch rules CODE` the notice gives, saying it read that one; the code is that conversation's for those rules, so no other client and no older rules can say it. A compaction keeps the launch's rulebook, which is in the system prompt, and drops what the conversation read since, so the next prompt after one (a `SessionStart` from `compact`, on Claude Code and Codex) tells it what changed since its launch again. A seat opened before ak recorded which rulebook it was handed is told once the same way. Any other seat reads the new one at its next launch. A project's own `AGENTS.md` or `CLAUDE.md` holds its conventions and is never the place for agentkit's rules.

At every turn's end `hooks/orchestrator-stop.sh` sends the turn back with *Continue: decide the next step and do it*
unless the harness's question prompt is still unanswered (input in the owner's words answers it, never the harness's own bookkeeping) or this turn recorded `ak notify needs`, or one it asked before still stands unanswered; a merged run of this seat's not yet live where its project declares `health:`, a run of this seat's going, its job with a live launcher and an unsettled task (even before any run starts, following seat renames), `ak notify done`, or its `ak wait <pull request or run>` naming one that is not yet merged, closed, ended or unreadable for three ticks running, ends the turn only while none of its runs sits parked and undecided (a run a later merged run replaced is settled), which names each run with its parked reason and the commands its state takes, and is looked at, resumed, relaunched split or on another model, stopped, or asked of the owner; it blocks at most twice a turn, and only while the seat's plan has an open line of its own or a run of its sits parked undecided: with neither, nothing is owed and the stop stands; with an open line, the third stop with nothing recorded becomes a question to the owner carrying the seat's last words. A question mark in prose ends nothing: the block names the question prompt and `ak notify needs` (required without a question prompt). On Claude Code, background work the seat started counts as a run until it reports
back, and a stop sent back reads `working`. A harness
with no blocking end-of-turn hook declares `[stop] enforce = "nudge"`, and the tick types `continue` instead (a question mark on its screen ends nothing there either; `ak notify needs` this turn does, and so does one still unanswered from before it, as on a hooked harness, since a hand-back or a wait's end opens turns while a question stands), never ahead of the line telling a waiting seat its wait is over, never after a turn you stopped with Esc, and at most twice for the same parked run until the seat has a newer notice.

After a hooked orchestrator turn really ends without a recorded question, one headless model
reads its last assistant message for a still-open question to the owner. A question found there
is recorded in the seat's own words as its `needs`, and sent and answered as usual. The hook
returns without waiting for this reader; stops sent back, stops on background work, workers
and turns that already asked make no call. ak chooses the model from the seat's marked workers
in its normal order. A failed or unavailable call records no question and leaves one line in
`~/.agentkit/state/log-<seat>.txt`.

Every line ak types shares a check of the pane's own terminal and, when named, its wrapper's inner terminal: each tty reports how many input bytes wait unread. Before starting the harness, the wrapper names its inner tty once in the pane's `@ak_input_tty` option; it follows pane renames. A successful respawn clears the old name in the same tmux command list, before a new wrapper's publishing client can run; a failed respawn keeps the old guard. Older wrappers and harnesses without a wrapper keep the pane-only check, including after switching from a wrapped harness. Each relay poll writes newly read input in that same poll, retrying interrupted and partial writes until the terminal stops accepting bytes. When a non-reading harness backs up the relay, the inner tty holds unread input for the guard to see. While either tty holds any, no further line begins, even over a screen showing an empty composer; notices and nudges wait for the harness to read them. The check also holds confirmation of a typed notice while input is unread; its Enter keeps the existing composer checks. Unread-input deferrals spend none of the retries for reboot or account-switch notices. A terminal that cannot be asked keeps the previous typing behavior. Delivery stays at least once: a crash after Enter but before recording delivery can repeat a line.

Inside a seat `Ctrl-b m` opens the same menu as a popup: a number switches to that session, `n`
starts one, `c` opens this one's models as `c` does on the menu, `x` stops it -- or, done, closes it at once -- and Esc closes the popup. A seat is renamed with `ak orch rename` or by renaming its conversation: Claude's Remote Control title, Codex's thread name, Grok Build's manual session title and OpenCode's session title follow the seat's name. Muse sessions keep their own name: the installed Muse refuses `/rename` even after a turn and rejects `--name`, so ak never types a rename into Muse. Codex's index and database do not distinguish generated names from `/rename`, so Codex titles never rename the seat, even after an owner's `/rename`; use ak to rename it. ak confirms its name from the owned thread's login index and restores it if Codex replaces it after the first prompt, stopping after three unconfirmed tries until the seat's name changes; an acknowledged name is not retyped, and a mid-turn attempt without a receipt waits for the prompt before retrying. Grok waits for an empty prompt and confirms only the manual title in its own conversation; automatic titles never rename the seat. OpenCode's seat plugin sets and reads back its own session's title through the API, including new seats, ak renames and auto naming, without typing or touching drafts. OpenCode 2.0.14 gives owner and automatic titles the same field and event, so neither renames the seat; the plugin restores ak's name when either changes it. All four leave owner drafts alone. Claude waits past dialogs and drafts and counts only once it records the title (or the composer clears if its transcript is unreadable); it gives its held line Enter even when wrapped, after the third typing or a later rename, and types each name at most three times before giving up until the name changes. Superseded pending titles stay recorded as agentkit's within that conversation until the name is explicitly retaken, so a delayed title cannot rename the seat back; owner drafts are never touched. Each typed line, its brief pause and its first Enter share the seat's lock so senders cannot merge lines; confirmation waits release it. A manual rename in Claude or Grok Build renames the seat too, taking a free variant if the name is held (even its own former name); Claude's title readings resume after the last complete line, with one note that moves and is removed with its seat; title errors are logged for their seat without stopping health checks. The seat's status bar is
two lines, its menu row with the line under it always open, never moving: line one is its word (`! needs you` alone a filled amber chip), the name, the model that orchestrates it, dim, and its progress line as its row draws it, in 36 cells, with how many of your other seats need you at its right end (`! 2 other seats need you`; a click switches to the first); where it does not fit, the bar narrows to 24 and then 12 cells, then it folds to `! 2 need you`, and only then is the rest cut; line two is who builds (⚒) and who reviews (◎) and each task in flight as its squares (`astra ⚒   opus ◎   ■□□  ■■□`), never a task's name, for every word, as its question or summary is on its own screen, fewer squares, then the squares alone, down to one task's and a count, where a client is short of room, with `Ctrl-b m  menu` at its right end (`Ctrl-b m  x close` once it is done). Each line is cut with one `…` where it would run off any client, a phone included, and the
window title is `<name> · <state>`. Agentkit's tmux config is `~/.agentkit/state/tmux.conf`; `~/.tmux.conf` is never read or written.

Terminal input and screen output flow independently for every wrapped harness. A burst of typing,
pointer events or redraws cannot make the bridge wait on itself; slow readers apply bounded
backpressure without dropping bytes. Existing seats take a transport update on their next natural
restart, keeping their conversation.

ak types no compact command into any seat: each harness compacts its own conversation (Claude Code an idle one, from the
minimum its login's settings set), and two compactors on one seat would only clash. A `/compact` you type reads `working`
until it ends.

Any harness can hold the seat: `--model astra` opens Codex, `--model spark` opens Muse. A Claude seat owns its
conversation from launch by a uuid; its launched pane's `/clear` hook keeps reopening and titles on the new conversation,
using its recorded login. The watch tick binds older running seats to their own client pane without restarting them; if that pane is removed, restarting uses the session's current pane. Other panes and in-session `/resume` never transfer seat ownership.
A Codex seat trusts only agentkit's hooks; other hooks still need Codex's review. It proves its thread through a launch receipt. An OpenCode seat's plugin
writes its session into one, and Muse and Antigravity open a new conversation each time. A seat whose harness exited
keeps its window; the harness's own scope ends with it, and what it left running there (a shell's background
job, a test's helper, a server) is stopped with the scope. A dead, detached seat nobody has opened for seven days is retired, and a record seven days gone from
tmux, or seven days after you stopped its seat, is swept, unless a run of the seat's is unfinished or a question in it is unread; then the name is free again. A seat you stopped is listed under the menu's `p`, past sessions, until `x` on it there or the sweep takes its record, whether or not its conversation can be resumed, and Enter there or its number reopens it where it stopped. Rows reserve space for the stopped age before shortening the name or orchestrator; if even their shortest columns cannot fit beside it, the age wraps below and the labels use the freed space. A Codex seat's conversations are its own, under `~/.codex/agentkit-seats/<id>` whichever subscription it runs on, where they stay after the seat is removed and a switch's handover still reads them, so its server never imports the host's other Codex history; startup waits as long as the server needs while the seat is open, and closing it meanwhile leaves the next start working.

Codex seats have Remote Control enabled, but connecting the ChatGPT app is optional. Opening, resuming or changing a seat's subscription sends no pairing alert. Request a fresh code on the host with `python3 ~/agentkit/tools/codex-seat.py --pair <seat-name>`, then pair the app with that code. Each seat has its own connection and must be paired separately; terminal work continues without pairing. Old pairing cards close as `Pairing optional` when their seat next checks its connection.

Stopping a session (`x` on its highlighted row, after its one question under the row, `Keep` or `Stop`; `x` on a done session and `ak orch stop <name>` ask
nothing, so a finished session closes with one `x`) stops every run it launched, removes each run's worktree and local branch, edits its open Discord card to `Answered`, closes the tabs the seat or its
runs opened and ends its tmux session. The seat itself stays: its record and state files are kept with the stop mark, it leaves its project for the menu's past sessions (`p`), numbered after every seat with a row, and Enter there or its number reopens the conversation where it stopped (the endings of its runs that came in meanwhile are typed in then); a session with no record of its own, made by hand or from before ak kept records, goes with the one stop. `x` on it there, or `ak orch stop <name>` again, removes it at once: its record, every
state file named for the seat or for a name it had before a rename except its locks, rulebook included, what its harness held for it, and the pointers a rename left; the sweep does the same seven days after the stop. Only the stop mark is written back into the seat file, so a hand-back of its runs still waits instead of asking you to continue a seat you removed, and a seat you open under the name is told nothing of the old one's wait; the collector takes the mark and unused locks a day later. The remote branch stays for the PR, and the run directory for its result. Leaving the menu with Esc leaves a seat running and is not a stop. From a seat, `ak run stop` and `ak orch stop` refuse another seat's work (`owned by seat X; a seat stops only its own runs`); own runs and runs without a seat still stop. Without `AGENTKIT_SESSION`, the owner can stop any run or seat. A seat's `tmux` is `tools/tmux-shim`, first on the seat's PATH (`orch.start` puts `~/.agentkit/bin` there and links it; a running seat gets it at its next start): it reads the final argv bash built and refuses a kill that would end another seat (`kill-server`/`kill-session`/`kill-window`/`kill-pane`) or a type into one (`send-keys`, `paste-buffer`, `send-prefix`, `pipe-pane -I`), then execs the real tmux. Each command in it that starts a process (`new-session`, `new-window`, `split-window`, `respawn-pane`, `respawn-window`) gets `-e AGENTKIT_SESSION=<seat>` after its name, since tmux starts it in its server's environment: what a seat starts in tmux, such as an `ak run --review-pr` in a session of its own, speaks for that seat as a command in its shell does, and a `-e` of the seat's own later in the command wins. Which seat a `-t` names is answered by the real tmux, with a read-only command of the same target type as the one guarded — `list-windows -t` for a session target, `list-panes -t` for a window, `display-message -t` for a pane — so the guard's answer is the command's own, not a hand-made copy of tmux's lookup, and a current-relative target resolves to the seat's own session. A worker, a shell with no seat, and every failure run the real tmux. Out of reach, by design: a tmux reached by an absolute path, one started before the shim was on PATH, tmux's own `run-shell`/`if-shell`, a login subshell that rebuilds PATH, a `-t` left off or on another server, and the commands that move, replace or respawn a pane or window; the bypass-proof form is a separate `tmux -L <seat>` socket per seat. A `gh` shim sits beside it (every `tools/<name>-shim` is linked as `~/.agentkit/bin/<name>`, so a new one needs no change): it refuses a seat's `gh pr merge`, because merging is ak's job once a PR passes review with green checks and the seat lets it land through the line. The one seat that may run it by hand is the inbox, which `ak watch` asks before it merges someone else's PR; ak's own merges (the lander, a review run) run seatless, so the shim passes them. Like the tmux guard it catches the merge a seat reflexively types, not a determined bypass; out of reach, by design: merging through gh's API (`gh api ... pulls/N/merge`) or a GraphQL `mergePullRequest`, a gh alias for `pr merge`, and gh reached by an absolute path. A `git` shim refuses a seat's `git worktree add` whose checkout would land in `~/code`, which holds only the owner's checkouts, and names `~/.agentkit/wt/` instead; every shim is one sh body (`tools/shim`), so a worker's call and whatever runs seatless (ak itself, a test's sandbox) run the real binary at once with no Python start, which git, run all the time, needs; only a seat's own call asks the guard. The real binary is the first on PATH after the shim's own, so a wrapper ahead of it never loops. ak's own tmux calls never reach the shim, even from a seat's hook: they run the first `tmux` on PATH that is not it (`guard.real`). A git alias for `worktree add`, or a git reached by its absolute path, is beyond it. The `scp`, `rsync` and `sftp` shims refuse a transfer that writes to the live host — the ssh alias the owner set as `live_host` in `~/.agentkit/config.toml` (`config.live_host`); the deploy host is each owner's own, so ak ships with none and guards no transfer until you name yours. scp and rsync write to an operand after the first (the first operand is a download's source, which runs); a `live:` operand after it is a write and is refused, tested by position so a trailing `--exclude x` or `-e ssh` (rsync permutes its options) can't hide it, and with no list of each tool's value-taking options — parsing those out only re-derives their grammars. sftp connects to its host operand, so a live host there is refused. A read from live, a transfer to any other host, and any transfer when no live host is set, all run; beyond the shim, named: a download whose first operand is a value-option's argument (`scp -i key live:/x .`), and a write made inside `ssh live "…"`, whose remote shell the shim never sees.

## The run

`ak run task.md --bg` is one job: a task file, a worktree, an executor, the checks, a reviewer, fix rounds and a merge.
The orchestrator writes the task from `templates/task.md`: a title, `## Goal`, `## Constraints`, and a `bash` block
under `## Done when` whose every command must exit 0. Optional front matter: `repo` (the launching checkout, else the one its
`~/.agentkit/tasks/<project>/` folder is named for; `none` is a scratch workspace), `base` (the repo's default branch), `target` (the branch the PR merges into, default `base`), `from`
(a local branch to cut from), `merge` (`squash`, `merge` or `rebase`), `rounds` (3, the most). A task with `after:` is
refused at launch: a job's tasks are independent pieces; a run saved earlier that was to start from, or still
stands on, a dependency's passed tip ends blocked before any work, and `ak run merge` refuses it, any branch kept. A fresh `from:` run merges its fetched or local target before round 1, aborting conflicts and leaving them or missing targets for landing; a resumed run never repeats it. A check ending in `# once` runs once at landing on the commit to be merged; the executor is told not to run it,
its absence from the reviewer's input by design. Scratch and `--no-merge` runs execute every task check in each round, including `# once` and explicit suite lines; the declared suite is not added. The full suite declared as `tests:` in the target's `AGENTS.md` at its checked tip runs once at landing; the checkout's declaration applies only when the target has none. A changed line judges later changes after it merges. A matching done-when command runs with it, so a task lists only its own checks.
`files:` (repeatable, comma-separated Git pathspecs) limits the branch's own changed paths after rebasing; an unmatched path fails the gate with `outside files: <paths>`, goes to the fixer and overrides reviewer PASS. Without it there is no limit.
An unknown task front-matter key refuses launch before any receipt, naming it and the accepted keys in one line. Retired `done_when_minutes`, `turn_hours` and `stall_minutes` keys stay accepted with a warning.
A command that fails runs once more at once, within the same ceiling, and passes if the re-run does: `flaky:` keeps at most 20 lines absent from the passing re-run after masking numbers, hex ids and absolute paths for comparison. It names a file in the run directory holding the whole failed output, and joins the run's follow-ups as evidence. In agentkit's own suite a failed test file runs once more alone inside its piece, after the piece's other files, before the piece itself would be re-run.
Every prompt carries the whole body of the repository's `AGENTS.md` as on the base commit, front matter removed; a linked `AGENTS.md` gives nothing, and a round that adds or changes one fails its checks, asking for the file itself. A round that changes `AGENTS.md`, a PR review round that runs no suite included, fails its checks if the file, as a checkout holds it (line-end conversion included), is then past the most a harness reads of it on its own: the smallest `[instructions] read_limit` an adapter declares (Codex reads 32 KiB). The same round fails if the committed file goes through a Git filter or its front matter holds a line whose name ak does not read (it reads `tests`, `health`, `cleanup`, `users`, `features` and `suite_image`), so a misspelled `tests:` never silently drops the suite. Leaving the file alone passes this check even when it is already larger. The lander measures it again on the tree each change would land as, before any suite or earlier green result answers that tree, so changes that fit one by one cannot land together past it. One past it behind changes still in the line waits for their verdicts, since they can lengthen or shorten the file; with none ahead, it goes back to be tightened. A worker's harness, and a seat's, loads no instruction file or memory of its own where it has a switch for that (a seat's rulebook carries its project's `AGENTS.md`); its adapter's manifest says in one line what no switch reaches.

Where that piece named its failed tests and they failed again run alone (`gate.run_suite(confirmed=)`, the red stack's `tests`), those alone run there first (`AK_ONLY`, `AK_SHARD=1/1`, `gate.run_suite(only=)`): passing there, each named as run (`AK_RAN`), the red is the member's own, in a fraction of the piece's time; anything else proves nothing (a test the member added is not on the tip), so the whole piece decides, and a whole piece passing there answers for that piece through the pass. Green there is the member’s own red. Red there pauses the line (`land.paused`): the line’s `.green` file keeps the red entry with its probe count, nobody is woken, and at each step of the retry ladder (`turns.TRANSIENT_BACKOFF`: 1, 5, 15, 30 and 60 minutes) a pass runs the piece there again; red through the ladder is the target’s own and gets one repair. Where those tests run alone failed there again, each named as run and as failed (`AK_FAILED`) by a run that ended in a failing exit on the pinned tip (`gate.run_suite(confirmed=)`, a signal’s death or a moved checkout proving nothing), the red repeats, which no step of the ladder would clear: it is the target’s own, its repair starts at once with its entry kept as the ladder climbed, and the piece does not run there. A red `# once` check of the member’s own goes to the member without a probe. Every other member keeps its place, unblamed, while the line waits or the repair holds that tree. A PR gets no repair and waits on none: the target's failure goes to its own fixer turn, and the head that fix pushes is checked on its own, so one that mends the target lands. A merged repair or `not needed` ending lets the line check the target again. A passing target wakes the member to fix itself. A clean integration keeps the review, an empty one ends PASS, and a suite that changes its checkout records no passing tree, and the next check there starts from its commit, detached, moving no branch the suite checked out (`land._put_back`). `ak run status` and the result say where each check ran. Members land in tested stack order.
Fork deliveries stay outside the line: without push rights the run integrates, checks, forks and opens its PR upstream, ending `PASS, not merged: waiting for the maintainer` with exit 0; the tick follows the maintainer’s decision. `--no-merge` stops at the verdict. Other ended `merged: no` runs name their reason and exit 1. Before each round, a run whose installed ak moved replaces itself with `ak run resume <id>`, keeping its pid, slot and saved PASS; it never moves holding a turn or child. A detached launch still waiting for its slot moves the same way between polls, as the same launch, keeping its pid and place in line, so a change to admission reaches the runs already waiting (`run.pickup_while_queued`).

A run ends `blocked` when the task is wrong: an executor or fixer runs `ak hand-in blocked "<why>"`,
or a fix round leaves the same checks failing the same way (or no harness can run it, see Resumption). No
checks, no reviewer, no further round. `result.md` opens `# BLOCKED — <title>`, and the orchestrator writes a new task.

Scheduled errors and merge waits send no ending. An ending that needs the seat goes to it as one line typed at its
next quiet prompt: `run <id> finished <PASS not merged|FAIL|BLOCKED|ERROR>: <why>. Result: <path>. Decide the next step.`
A merged (`PASS merged`) or not-needed (`DONE`) ending goes the same way only while the seat's plan has an open line of its own, as
the end of a wait its turn may have ended on; otherwise it is recorded, never typed, and wakes no seat. A seat mid-turn
gets it from the tick; its line is typed once, and one still sitting in the seat's composer gets only its Enter, none
while text you typed sits beside it, and counts as delivered only once that composer, read whole, is empty. The tick reads
a seat found off its prompt once a pass for all the endings waiting on it, and the log names a waiting ending once, as it
is first deferred, again on each pass its seat reads at its prompt yet takes no line, and as it is said. A seat that
has died is reopened by the run and told `continue <task>`; only when that fails does a `Needs you` card go to you. A
run you launch by hand has no seat: its result is on the terminal and in `ak run status`.
Workers and checks run with `$AGENTKIT_UNATTENDED`, so a run one of them starts belongs to nobody. A project's `AGENTS.md` front matter may declare `health: <shell command>`: exit 0 means its live product works with the change deployed. For three hours after merging, the tick reads the declaration at the merge commit, from GitHub if it is unavailable locally, and runs it in the original repository checkout with `AK_MERGE_SHA` set to that commit. It tries at most once per commit per tick, stopping at the first pass: `live_at` goes into the run and its history row, and the launching seat hears that the change is live only while its plan has an open line of its own, as its turn may have ended waiting on it; otherwise that is recorded, never typed. Each attempt has a 30-second timeout that kills its process group. A command still failing when the window closes goes back once with its last output, using the merge-commit checks' existing break marks. An unreadable declaration retries next tick without changing merge-check handling. The project owns its deploy; without `health:`, merging behaves as before.

### Deploying with the release kit

A project on its own Linux host deploys with `tools/release.py`, copied to its `deploy/release.py` and run every minute or two by a systemd timer as the project's own user, never root. It releases only commits on the first-parent line of the branch ak lands on (what its clone's `origin/HEAD` names) that descend from the live release and carry ak's `Suite-Passed-Tree:` stamp for their own tree, the newest first, and never one that is an ancestor of a commit that failed after its switch: a failed release waits for a newer one, also after main is rewritten and garbage collected. A branch that no longer contains the live release is refused until someone releases by hand. Each release is built in its own directory with a fresh virtualenv from its requirements file; its install and migrate commands run before the `current` link switches, each in its own process group that ends with it. A failure before the switch changes nothing live, and the next tick tries again. After the switch the release's restart command runs, then its health command until it passes within its time. Any failure after the switch puts the live release back: the link, its restart, its health. A restore that fails, or a tick cut off mid-release, is finished by the next tick, and every tick first prunes old releases, never the live or the previous one. The kit holds no privileges and installs nothing outside its own directory: the project's units point at its `current` link, the project's installer puts them in place, and the restart command may use a sudo rule for exactly that restart. The timer's OnFailure= alert says why, and the project's `health:` hands the break back to its seat. `deploy/release.toml`, read from the commit being released, names the restart and health commands, and optionally the health time, requirements file, interpreter, install and migrate commands and how many older releases to keep. Migrations must keep the previous release working: a restore puts the code back, never the schema.

### New features in live projects

A hobby project ships straight to live. When a new feature comes up in a repository whose `AGENTS.md` front matter has
no `users:` line, the orchestrator asks once, "Does <project> have real users?", and that feature's first task adds
`users: none` or `users: real`; no line reads as `none`. In a `users: real` repository a new feature merges round by
round behind the project's own switch, on only for you until you turn it on for everyone; only the reviewer is told, and
it fails a round whose new feature is outside the switch or on for anyone else by default. A project names its switches with
one command in the same front matter, `features: <command>`: `<command> list` prints them as JSON (`id`, `name`, `you`, `everyone`, `you_switchable`, and `everyone_since`, when it last went on for everyone, ISO 8601 UTC, or null) and `<command> set <id> you|everyone on|off` flips one, printing the new row or one line on stderr. While a session sits in such a project, its heading says `2 hidden features` at the right when it fits beside the name, and Enter or a click on that heading opens `agentkit · ACME`, where the arrow keys pick a feature and `you` or `everyone` and Enter flips it through `set` at once, while `list` is asked in the background every minute (every ten seconds while that screen is open) and never holds up a draw; the project's own owner page flips the same switches. A switch on for everyone for two weeks is proven: once a day the tick reads the list of each checkout in `~/code` that declares one and writes an open plan line for every switch it shows proven, longest first: a switch an open session's plan already names goes to that session's plan, the rest to the newest open session filed under that checkout, one line per switch, saying to take it out of the code and keep the feature as everyone has it, with the project's own switch list as the line's check, which fails while the list still shows the switch and ticks itself once the project's deploy has dropped the row. A switch on for everyone whose row gives no `everyone_since` gets a line asking for the field, since without it ak cannot tell when it is proven. A line already open for that check is not written twice, and nothing is typed into a session. What a plan line says stands: a switch turned off after is still taken out, since turning a proven switch off is a code change. A list that cannot be read, or a checkout with no open session, is tried again the next hour; the line names the project, so it holds even in a session filed elsewhere.

## The picker

Session records and `[defaults]` may list `reviewers` beside `workers`; new seats copy explicit default reviewers.
With separate groups, executors use only workers; reviews (including `--review-pr`) and spares use only reviewers. A model can be in both.
Runs save explicit groups in `run.json` at launch, show them in status and the preflight log, and keep them through handovers, refusals and resumes despite later edits; omitted reviewers keep the old shared-list behavior. Each group ranks by the matrix (`ak models`, the one the tick last computed, `matrix.rank`, read off
the row at the effort the config runs the model at in the role): the models within `within` of the best of them, the
cheapest first, then the others by quality; a model no board has, or a matrix nobody computed yet, after every ranked
one; then by budget: the fraction of allowance left divided by the fraction
of window left, using the smallest provider non-session meter. The pair is the best by reviewer -- another model, from the executor's company as readily as from another, before the executor's own -- then the executor's place in its group's order, then the reviewer's; models equal on all of it keep list order, and ak's own run numbers never rank. A self-review is marked `self-reviewed` on the launch line, in `ak run status` and in `ak usage`. A model's own
`meter` still gates it. A meter at 100% used excludes a worker unless its provider or account has `credits` left, which rank it after every one with window left (seats and their accounts too) and show as `62,469 credits left`, or `$12.40 credits left` in money, on its usage row and under `ak usage`; so does a harness not installed or not logged in (no adapter or program, or
its `auth` verb says no for every subscription its provider lists, asked at every pick), with one `skipped <model>: <harness> is not logged in` line in the run's
log per pick; `--exec` or `--review` outside a bound group or naming an unavailable harness is refused, as is a resume whose saved executor no other model can take
over. An unknown budget ranks last, a pay-as-you-go provider joins only while every subscription that can run is ahead
of pace by more than `pace_margin`, and a run with no eligible pair parks `exhausted`, but a launch with no runnable
worker or reviewer (every harness skipped) is refused naming the groups, by a `--bg` launch's parent too. The orchestrator choice ignores pace (see `n`; every model spent launches the default with a WARN); a run without a session uses the
default groups and refuses task launches before any run or job exists if its executors are empty; without `reviewers`, legacy unbound picks and orchestrator resumes still work, and explicit PR reviewers may be outside workers even in a seat. Meters are cached for five minutes and each provider is probed at most once a minute host-wide, a refused worker included (Claude once in fifteen, and never before its last `Retry-After`; Muse's billed probe once in ten, whatever its meters do); a spent-window
refusal parks the provider until it refills, a usage-limit reset held or not: ak never spends one, and one held adds nothing to budget or headroom; its usage row says `1 reset in hand`, and the owner spends one by hand with `↻ spend a reset` on the Providers row of `c`; `ak usage` shows the choices, and a reading older than half an hour says `as of HH:MM` on its row and under `ak usage`. A Claude worker turn's last `rate_limit_event` becomes its account's session and weekly_all reading at once, with no request; any other meter keeps the endpoint's reading, and an older reading never replaces a newer one. Each worker turn that spent a known number of tokens records, per subscription and each weekly meter gating its model, its tokens beside how far it moved that meter from the subscription's reading before the turn to the one after it (the turn's own stream, else a probe after it, never one the probe's cadence answers with a reading from before the turn ended), in `state/capacity.json`, only when both readings name the same reset (a usage-limit reset spent during the turn names a later one); a meter that did not move counts the tokens against zero percent. A meter's pairs count for its latest week and the week before it: the last week any reading of that meter named before it, as `usage.json` keeps the last two each weekly meter named (a week no turn was paired in still counts), while that one ended no earlier than the latest began; older pairs are dropped as a turn records. `ak usage` shows, after `left`, what the shared week holds: the sum of the tokens over the sum of the percent moved by the pairs of the week its reading names and the week before, as `week ≈ 310M tokens` (two significant digits and an SI letter; a 30-day window says `30d`), `-` while no pair has moved it; `--json` carries `capacity_tokens` and `capacity_pairs` on each subscription. `price` on a provider's table (`usage.price`) is what each of its subscriptions costs a month, in whatever its owner pays in; the column after `holds`, `a month`, says the price and what one million tokens cost at it off that week, a month being 365.25/12 days of the window (`usage.per_million`, two significant digits): `200 ≈ 0.15 per 1M tokens`, in grouped digits and never an exponent (`5,000,000 ≈ 3,700 per 1M tokens`), the price alone while the week is unmeasured, `-` without a price; `--json` carries `price` and `price_per_1m`. It picks nothing, and the menu's usage rows do not show it.

## The tick

`ak watch` runs every three minutes from cron on the server, under a lock so ticks never overlap, writing
`~/.agentkit/tmp/watch.log` and rolling it at 5 MB. Before typing new lines, it gives Enter to a composer holding
only ak's full account-switch notice, mid-turn continuation, re-ask notice or resume nudge, even when its retries ran out and its mark
is gone. It reads the composer again under the typing lock before each Enter; other text and dialogs are left
alone, including partial lines whose last rows match a recovery notice. The whole composer must be visible,
from its opening to its closing chrome; cropped or scrolled composers and owner rows that resemble footer
text get no recovery Enter. Delivery stays at least once: a crash
between Enter and recording delivery can repeat a line.
Each tick: retries the notification outbox; reads every seat's
last error from its harness's own record of the conversation (Claude's transcript, Codex's rollout), off its screen
where it keeps none, and asks each harness's `auth` verb where a login looks gone; types `continue` into a seat stopped
on its harness's own stall words for three quiet minutes, at most every three minutes, and after an hour of that asks you once;
resumes, relaunches and brings back what Resumption says; types hand-backs waiting on a busy seat, including one whose turn stopped on background work, since its composer is open and takes a line at once, one at each quiet prompt, those of runs that wait on its decision before those of runs that merged; gives each hand-back and wait notice its Enter only while the composer holds that line alone -- all of it, the end of one taller than the composer shows, or the harness's fold of one past `[screen] folds_over` -- so what you type just before that Enter is never sent with it, and counts it delivered only once the composer reads empty, so a line you edited while it waited stays yours to send; logs what it read of the seat (its state, what decided it, its composer) as a hand-back it could not type is first deferred, and on each pass a seat that reads at its prompt takes none, keeping that screen in `~/.agentkit/state/refused-<seat>.txt`; asks once per tick whether what each seat's `ak wait` names is over (a run no longer going, a pull request merged or closed, or while open, the newest run whose `review_pr` names it over as a wait on that run would be, its line the one told; a pull request gh could not read for `watch.UNREAD_TICKS` ticks running counts as over, said with gh's reason, while one gh is logged out of holds and puts the seat on gh's `needs you` rung), writes that on the wait the moment it is, and types `<fact>; your wait is over. Decide the next step.` once into that seat at its next quiet prompt, naming the fact and nothing else, which ends that wait for good: the line goes in at least once and is never lost, a tick that dies mid-line being finished by the next from the composer read whole; closes idle browser
tabs; reviews others' PRs on repos this account owns and follows its own PRs on repos it does not; once a day asks
the worker-token verb and schedules collection; and on the first tick of each ISO week (UTC) runs the weekly audit (`audit.weekly` writes, `watch.tell_audit` delivers): it writes `~/.agentkit/state/audit/<week>.md`, the scoreboard with the week's largest loss in one line (`scoreboard.loss`: the first measure in the vision's order, quality, speed, cost, size, that reads worse than the week before, else the first the board reads at all), opens the `audit` seat with `[audit]`'s models when there is neither a seat nor a record (`orch.ensure` with `roles`, which remembers no default), resumes it when its record is there and its process gone, leaves it while the owner closed it, and types one line naming the week, the loss and the report into it at its quiet prompt, at least once, the mark kept in `~/.agentkit/state/audit.json` until the composer reads empty. Once that line is in, the same seat is told each stall the tick finds, once, the same way (`stuck.scan`, `~/.agentkit/state/stuck.json`): a landing line's check pass that has run more than three times the median of the line's last passes (each lander keeps those that took a minute or more, `land.passes`), and half an hour at least, while its lander lives, or the run first in line for a slot for three times the median wait there of the last 20 firsts let in (kept beside the queue), and half an hour at least, while a poll within four rewrote the queue (`gate.first_in_line`: a longer gap ends that wait); a stall's line typed and awaiting its Enter is sent before the next week's is written. `[audit].on = false` runs none of it. A logged-out `gh` costs only the two GitHub passes. `ak watch --dry-run`
lists what a tick would do; `ak doctor` shows the slice, the tick's state and any effort a model does not take.

## Resumption

Nothing you launch is lost to a crash. A run whose loop process dies is resumed by the next tick where it stopped,
continuing the harness's own conversation (`claude -p --resume`, `codex exec resume`, Muse's `--session-id`); the first
death resumes at once, a second within ten minutes waits ten, a third within an hour parks the run and tells the seat
once. A job whose launcher dies is relaunched by the next tick in its launch directory, so its waiting tasks start in
order, while that directory is there, its seat's session exists and you did not close it, its launcher was alive (its heartbeat) under 24 hours ago, no unfinished task whose run stopped short of its ending was handed back, carded or
acknowledged, none was stopped, and this is not a third death within an hour; otherwise `ak run status` names `ak run
resume <job>` and `ak run stop <job>` under it. A run with no output for 20 minutes has its step stopped and the loop carries on; a second
silence resumes the loop with each role re-picked from its own group and execution on another provider, trying reviewers from providers that refused nothing first and refused reviewers only as fallback; later picks use normal order. A third parks
it `stalled` for `ak run resume <id>`. Quota `exhausted`, including task and PR reviews and delivery retries, resumes when its window refills, a reviewer-transport one as
below; other `exhausted` runs wait for `ak run resume <id>`; an expired login parks `waiting_login` until the harness's
`auth` verb answers `yes`. A failed worker turn is read in its harness's own `[stall]` words and those no harness owns, whole (a `429` inside a longer number is none, and neither is any word inside a run id, which names a run's worktree and directory) and only where the harness spoke, never in the model's answer. A transient fault (`API Error`, `Overloaded`, a 5xx, an empty answer) retries the same
session after a minute; a second failure in a row hands the role to the next model in its group, and with nobody else the same session
is retried after 5, 15, 30 and 60 minutes, then hourly; the tick's silence clock starts where each wait ends. An empty
answer whose stderr (the adapter's own included) says the harness never ran (not installed, an unknown flag or model, a
refused login, even quoted as `API Error`) and names no 5xx, overload or capacity error goes to another provider at
once, or ends the run, a PR review included, `blocked` on that line. A refusal that names the account re-picks the pair from its saved groups, same worktree and round.

`ak run resume <id> [--rounds N] [--bg]` resumes the worktree, the worker sessions and the options a run left; it
refuses `blocked` and `stopped`, and needs the worktree, which lives seven days. `ak run merge <id>` retries the
delivery of a PASS whose push or merge did not finish. `ak run stop <id> [--keep]` is the one deliberate end: `stopped`
is final, and `--keep` holds the branch for a task with `from: <branch>`. Given a job's id, it stops the job's launcher
and each of its runs still going, records every unfinished task `stopped` and ends the job, which is then collected like
any finished one; a resume of it begun before the stop stands down. After a reboot the first tick or menu brings
back Claude and Codex seats with proven conversations that still owe work, once per boot, but none you closed: one
that died in a turn or asking you, or with an open plan line, an undecided or going run of its own or an unanswered
question; the rest stay down and reopen with their number. Runs resume as before. The tick tells one that died
mid-turn to continue it, as a run is, over at most three ticks, so it reads `working`, unless you prompted or renamed it,
and tells one that was asking you, in a turn or not, by its question on screen or its own unanswered `ak notify needs`,
to ask it again once it rests at its prompt with nothing running, asked or typed there.

### When a run goes silent

On `ak run status`'s dim line (`error · retry 14:32`, `waiting · retry after the next merge to origin/main`) an admitted
ending says why: its launch session still exists, it ended under 24 hours ago, and it was not handed back, carded or
acknowledged. Only those endings may be parked from a conflict FAIL or resumed from `error` or `waiting`, an older
tick's waits on a target ref included; by-hand runs and older endings wait for a person, and a job's run for its job, which resumes its own merge wait. The tick retries an admitted error on the
ladder above, an `exhausted` run after reviewer transport failures once a reviewer is eligible (at most hourly while it
keeps dying), and an admitted conflict `waiting` after main moves, task rounds spent or not. `ak run status <id>` on a
scheduled error keeps its retry and admission. When admission ends, an error loses its retry stamps, and it or a merge
wait reads `run <id> parked: <reason>` at once, before the tick clears an old stamp. An error with no automatic resume
reads `needs you` only while recent, unacknowledged, neither handed back nor awaiting it, and not superseded; an `exhausted` run the tick cannot resume reads the same, handed back or old, until `ak run resume <id>` or `ak run stop <id>`, unless a later merged run replaced it, and counts as `needs you` in the tally, never as `running`. A merge
wait on a target ref that no longer qualifies is inactive history: its row reads `done` with the parked reason, it adds no attention tally, neither the stop hook nor the tick counts it as work, and it can still be resumed by hand; only one its age alone turned away still reads `needs you` on its seat (above). A run recorded in the line to land holds no process and stays working without an age limit: status and the menu say `waiting · 3rd in line to land on main`, counting by when each member joined that repository's line. The tick and `ak run resume` leave it to the lander; its job follows it to its ending, including after `ak run merge`.

## Cleanup

The daily retention pass resets failed user units named `agentkit-*` after a day in that state,
unless an unconcluded run still names the unit as its scope. This keeps memory-cap evidence
until the reaper can read it; other units are left alone. It also stops every service or scope
in a slice named `agentkit-test…` once it has been active for a day: no test suite runs that long,
so it was left behind, however its suite ended. Units in any other slice are never stopped.

On ak's server, with a user systemd manager, each tick stops every login of ak's user that ended
over a day ago and still runs something, such as a detached mosh-server or an `opencode serve` an
ssh login started. logind abandons a login's scope the moment the login ends, so that scope's last
change says when; the stop is logind's, of the whole login (`loginctl terminate-session`). The
tick's log names the login and what it still ran, and nobody is paged. ak's own tmux server and
seats live in `agentkit.slice`, never in a login. A login still in use, a client, and a host ak
was never installed on are left alone.

A merged run's worktree and local branch go with the merge. A stop takes both at once, or with `--keep` the checkout
after seven days. A failed, blocked or errored checkout goes when its seat has been told or after seven days, unless a
resume can take it; its local branch stays until the 30-day removal, because a run that never pushed holds its only copy
there. Before removing a run's checkout while keeping its branch, ak commits its tracked edits, new files and staged
changes without repository hooks, leaving out junk and the done-when's artifacts. If the checkout is off its branch,
a rebase or merge is unfinished, or Git cannot save the work, the checkout stays. The collector respects that hold
until seven days, then retries saving; work that still cannot reach the branch stays. Removal that also drops the
branch is unchanged. A pass whose delivery ended without a merge loses its checkout after seven days, its branch kept, and a checkout
with no run record goes a day after its last use (its folder changed, or git wrote its index or moved its HEAD): a folder with no `.git`, one ak never finished making, the line's marked scratch whatever it
holds, any other only on a branch, not locked, with no submodule set up and `git status` listing nothing, untracked files
included. A seat's checkout with a change not committed, a clone, a detached one and one git cannot read stay. A run directory older than 30 days goes whole, with its checkout and branch, unless
the session that launched it still exists; a scratch run's workspace goes only with it. `~/.agentkit/tmp` entries older
than a day go, owned `/tmp` entries untouched for two days go and a gone Claude session's scratch folder after a day, a repository `TMPDIR` directly under `/var/tmp` like `/tmp` itself,
finished jobs after a week (a job whose launcher is gone is stopped, as `ak run stop <job>` stops one, once nothing was written in its directory or its tasks' run directories for 30 days), and a state file named for a seat with no record a day after its last
write. Trust and MCP entries in `~/.claude.json` and `~/.codex/config.toml`
that point into a gone `smoke-*` sandbox or `~/.agentkit/wt` checkout go in an atomic rewrite of just those entries, in
any layout; a file that does not parse is left alone. The collector writes `~/.agentkit/state/gc.log` and never touches a checkout under `~/code`, a live loop, or in `/tmp` a dot entry, `tmux-*`, `systemd-private-*`, another user's file or anything held open or used as a working directory. Age uses the newer of a file's or link's modification and inode-change times, and a directory's modification time alone: systemd-tmpfiles' daily pass moves every directory's change time. Claude's pid records, matched to process start times, protect current conversations across hand launches and `/clear`; a headless turn's is the one named by its stdout, the event stream ak launched it writing to, and a client neither names keeps its working directory's project, named as Claude Code names it: a hyphen for each UTF-16 unit that is not an ASCII letter or digit, and past 200 the first 200 and a hash of the path. Hidden handles are inspected read-only with noninteractive `sudo`; failed inspection defers `/tmp` cleanup. Planning scans processes once per temp directory, deletion once per batch. A checkout goes with its uncommitted work; a tree holding what this user
cannot remove is reported once, on any path, and never retried. `ak run gc --dry-run` gives each item's reason; `ak run
gc` also sweeps every merged worktree, regardless of repository or git registration, and day-old `smoke-*` sandboxes,
reporting count and space freed. The tick takes a leftover merged tree only if clean and registered. Each sharded smoke piece removes its own sandbox. A passing unsharded smoke suite removes its sandbox; a failed one keeps the newest failed sandbox and removes older ones whose suites ended.

## The config file

overwritten. A turn its harness ended for the limit (Claude Code's `wrap_up` note, after which the model stops with nothing refused) is continued on the new account, unless the seat reported its job done after that note.

Muse keeps each named login's credentials under `~/.muse-<name>/muse/auth.json` and links its `settings.json` to the usual login's user settings (`~/.config/muse/settings.json`, or under the usual `XDG_CONFIG_HOME`). The first launch carries over settings held only by that login; the usual login's values win conflicts, including nested ones. Seats and workers then read and write that shared file. Its `.settings.json.lock` links to the usual login's lock too, so migrations and Muse's settings writes take turns.

Secrets are in `~/.agentkit/secrets/`: `discord_webhook`, `discord_user_id` and `claude_oauth_token` (the worker token
`claude setup-token` mints, dated a year from its file; within 3 days of its end it pages the owner once a day, as a login does). A repository's `AGENTS.md` front matter holds `tests:`, its
full suite, which a review of others' PRs runs as its check, `cleanup:`, one shell line ak runs once in a run's checkout
before removing it, and `users:` (above); task files go by convention in `~/.agentkit/tasks/<repo>/`. When a whole suite takes more than two minutes, ak starts a run in its session to split the `tests:` line itself, once per repository and line. The line then reads `AK_SHARD`: `k/N` selects its 1-based share, unset runs everything. ak runs the pieces together in one checkout, sizes them from live CPU room, host and run memory headroom, and measured cost, logs each separately, and retries red pieces alone. A line can also name its failed tests: their IDs one per line in the file `AK_FAILED` names; with `AK_ONLY` set (and `AK_SHARD=1/1`) it runs only the IDs listed in that file, and with `AK_RAN` set too it names there each one it ran: the lander's tip probe trusts a pass of listed IDs only where each is named, since a line may skip an ID it does not know and exit 0. A red piece that named them retries just those first: failing again, the piece is red without a whole retry, and a landing check's red names them (its `tests`, `gate.run_suite(confirmed=)`); passing, the whole piece retries and decides, since a failure can need the tests before it. So a test that fails in its piece and again alone is red, even where a whole retry would have passed. Memory is counted without the file cache reclaim frees before an OOM kill, under a hard cap too; tmpfs, shared memory and locked pages stay counted (`host.held_mb`). A piece's cost (`gate.suite_cost`) is what that repository's suite's finished pieces spent: their CPU as each piece's box reports it, the landing line's checker's included, and their memory where the run's own cgroup can tell, or a cgroup holding nothing but the checker and what it started, as the landing line's does (`host.own_cgroup`); it is never less than 0.7 CPU and 0.4 GB, and that until measured.

## The installer and updating

The README's one command works on a fresh macOS or Linux machine, safe to run again; `--server` and `--client [alias]`
set the role when the default is wrong, and `--phone-key KEY|FILE` appends the phone's key. It makes the directories
under `~/.agentkit` and `~/code` and puts `ak` on PATH. It installs what is missing: tmux, mosh, git, gh, jq, python3
3.11+, node, cron; on Linux also chromium, security-only unattended upgrades and Tailscale. With no harness installed it
asks once which to install and log in, or `all`, one provider being enough, and each adapter installs and logs its own
in, in a terminal; on a machine that has one it checks and logs in only those installed, wherever their binaries live,
adding none unasked. `gh auth login`, the Claude worker token, and the Discord webhook and user id are each asked for
once, only where missing and there is a terminal; the git credential helper and author are set from `gh` without asking.
On a server it also writes: the bypass defaults and update pins into `~/.claude/settings.json` (backed up beside itself
when it changes) and `~/.codex/config.toml`, each harness's lifecycle hooks through `adapters/<h>.sh hooks`, and the browser MCP registration. The server installs the tick's cron and, where a user systemd manager exists, writes
`~/.config/systemd/user/agentkit.slice.d/limits.conf` on every install, pinned by `slice_tasks_max`, `slice_memory_high`,
`slice_memory_max`, `slice_cpu_quota`: seats in `agentkit-seats.slice`, runs in the lower-weight `agentkit-runs.slice`. The parent slice uses `CPUWeight=40`, below systemd's default of 100, so ak can use every idle core and yields CPU to other work under contention; no CPU quota is written unless `slice_cpu_quota` is pinned. Landing checks can reclaim CPU from lower-weight builds with or without a quota; other landing checks and CPU used outside ak still consume their room. Where `sudo` needs no password it first writes the user unit's own `agentkit-limits.conf` (80%/90% memory,
4% of tasks, `CPUWeight=40`, no CPU quota, `OOMPolicy=continue`), rewriting only a file whose first line marks it as agentkit's and leaving other files byte-identical; without it, one line says to run `sudo -v` and re-run the install. Under a HOME not the account's own it touches nothing outside it.

`ak update` upgrades the harnesses this host has (any other is a `skipped` line), and none while a session works (it names those sessions and exits 0); it verifies them with the gates that can run there and rolls back a harness the gates fail, then fast-forwards `~/agentkit` itself and reruns `install.sh`, working sessions or not, as each `ak watch` tick does after a merge to main. `tests/live.sh` holds agentkit's checks that need the outside world, which the landing suite leaves out: where origin/main has one, the checkout moves only to a commit it passed on, exactly that one however far main has moved since, and until one has, nothing moves or reinstalls. Each tick starts it for origin/main when no check of that commit passed and none is running, detached, in a throwaway worktree of the commit under `~/.agentkit/state/live-checks/`, and ends it at two hours; a red one runs again after 10 minutes, 30, an hour, then hourly, and the second red in a row (one provider blip in its real model calls is not main broken) is handed back once with a bounded failure report and closing summary, to the newest live seat whose runs merged into agentkit, and a newer origin/main is checked as soon as none runs. A harness upgrade runs it right after `tests/smoke.sh`, and its failure reverts like smoke's. Both paths start live checks in agentkit's slice, so its ceiling and the run admission gate count their CPU use; without a user systemd manager, or when placement is refused before the check starts, they start plainly. While a harness upgrade runs, `~/agentkit` neither moves nor reruns `install.sh`, so its gates test one commit from start to end: an upgrade that begins during a move waits for it to finish, and a move that comes due during the upgrade happens at the first tick after it. A checkout that is dirty, off main or cannot fast-forward is left as it is; that, or a failed fast-forward or `install.sh`, is said once per origin commit, in the tick's log and by `ak update`, and each tick reruns a failed `install.sh` until it passes. It runs in the foreground and says per harness whether it was upgraded, reverted, kept or left unchanged; `--dry-run` prints the plan. `ak` opens at once, then a detached process asks origin whether `~/agentkit` is behind and fetches, fast-forwards and reruns `install.sh`, filling the rule under its header while keys keep answering. The main screen starts again on the new code with the same session highlighted; an open sub-screen and its draft wait until you come back. Leaving lets the update finish; a failure says why as a notice, and the next `ak` retries while origin is ahead. A client starts the update and connects over ssh at once; its next `ak` takes the new code. Overlays and dry runs skip it. A tick upgrades a harness behind its `[update] latest` release, asked hourly at most, in the background through the same gates and rollback, sessions working or not, one at a time; a failed gate is said once in its log and that release is tried again a day after its last start. The second failed gate in a row for that harness is handed back through the same seat delivery, once, with the failing checks and the log path; a busy or unavailable seat is retried on later ticks, and only a passing gate for that harness clears the count and hand-back. A worker turn that fails while its harness is being installed or reverted starts again on its session once that swap has ended, rather than reading as a harness that cannot run, and a launch naming a model whose harness was asked during one waits for it to end and asks again before refusing. Every harness ak ships names one, and a newer Muse build of the same X.Y.Z (`1.4.1-R4503.1`) is a newer release.

Agentkit’s own suite accepts `AK_SHARD=k/N` (1-based): each piece owns its checks and remaining test files, keeps dependent checks together and uses separate sandboxes; unset or `1/1` runs everything. The tmux safety guard runs in every piece. agentkit's own `tests:` suite first runs, in every piece, the static checks `STATIC_CHECKS` in `tests/suite_shares.py` names (dead code, boundaries, the map and the docs), and stops there when one fails; then it runs `tests/smoke.sh` beside `tests/every_file.py`, streams smoke's output first, then follows every_file's buffer to its end, and runs with `AGENTKIT_ACCEPTANCE_REQUIRED=1` and, where the host allows a network namespace (`unshare`), with nothing but loopback: it tests agentkit's own code and reaches no real model, GitHub or Discord. The retry checks advance a test clock through the unchanged backoff schedule. The checks `LIVE_CHECKS` in `tests/suite_shares.py` names need the outside world and run only in smoke.sh's live mode, which runs no other check: `tests/live.sh` starts it, and the host and `ak update` run it as below. `tests/every_file.py` runs every `tests/test_*.py` that neither smoke.sh nor the static checks run, each once, without the caller's `AGENTKIT_*`/`AK_*` variables, outside smoke.sh's lock. Unknown files start first, then longest first by their last measured time on this host, cached under `~/.cache/agentkit/test-times/<hostname>/` outside the checkout. Its pool grows with live host and cgroup memory, past the core count for waiting files; each start samples current CPU pressure, and while stalls exceed the 20% ceiling or its slice exhausts its CPU quota it starts a file only when none is running, so a busy host slows the sweep but never stops it. A file that fails runs once more alone, after the pool and after `tests/landing.py`'s smoke.sh and contract have ended: passing then, it counts as passed, is printed as `flaky:` with its first run's last lines and counted in the tally; failing again, it is named with its re-run's last lines. `tests/landing.py` also runs `tests/gate_contract.py`: on a stand-in checkout it proves every test file runs once in some share and a failing or empty one fails, so every_file's pool and order stay free to tune. Any part failing fails the suite. With `AK_FAILED` set it names there, by checkout-relative path, each static check, `tests/smoke.sh` or `tests/gate_contract.py` that failed and each test file that failed its re-run too; with `AK_ONLY` set it runs only the listed ones it knows, whatever its share, a test file through every_file.py with its re-run, and an ID it does not know runs nothing and fails nothing; with `AK_RAN` set too it names there each listed one it runs, so a run of an ID it does not know counts for nothing. A file needs a positive unittest tally or, for other scripts, a `TESTS_RUN=N` line after its checks. Python under `agentkit/`, `tools/`, `bin/` and `tests/` must parse with Python 3.11's grammar, the oldest ak supports (a newer interpreter accepts syntax 3.11 refuses, such as a `type` alias; landing reports it as `invalid Python 3.11`, though f-strings are still read by the running interpreter's rules), and its imports must use the standard library or repository modules; that check includes files smoke.sh already ran. The live mode keeps a pool of private smoke targets, `<login>/agentkit-smoke`, `agentkit-smoke-2`, `agentkit-smoke-3` …, each under a host-wide lock of its own (`/tmp/agentkit-smoke-remote.lock`, `/tmp/agentkit-smoke-remote-2.lock` …), and `tests/e2e-fresh.sh` keeps private `<login>/agentkit-e2e` under `/tmp/agentkit-e2e-remote.lock`; a repository is created only when missing with the scopes `gh auth login` grants, and a gate resets the one it holds: force-push `main` to its seed commit and delete leftover `ak/*` branches. Provider logins are shared as the host's seats share them; only a remote would be reset under another suite, so the live suite takes a target for check 4 alone, from the seed until its delivery is read, and runs every other check beside other suites. Check 4 takes the first free target; when every existing one is busy and the pool is smaller than the heavy suites the host admits at once (the loop's own count), it creates the lowest number missing, and it waits only at that bound; the pool is the repositories the account lists, listed again every minute while a suite waits and before it takes a lock that came free, never the lock files; suites list, choose and create one at a time under `/tmp/agentkit-smoke-remote-make.lock`, and a listing that failed creates nothing; a suite that dies gives its target back as its lock's holder exits; each run title carries the suite's pid, as do the fixed names of the seats checks 6f, 20e, 25 and 34 start, so two suites share no run id and 6f's seat no systemd scope. The e2e gate holds its lock from its GitHub run through exit. A suite that cannot take a target or the lock fails that check and runs the rest. Cleanup is registered before HOME setup, so setup failures finish their retention receipt and keep the sandbox. The smoke suite reads shipped `config.default.toml` in its sandbox HOME and ignores the host's own agentkit config. It links individual credentials: `.claude/.credentials.json`, `.codex/auth.json`, `.config/muse/auth.json`, `.grok/auth.json`, `.local/share/opencode/auth.json`, Antigravity's `.gemini/antigravity-cli/antigravity-oauth-token`, GitHub's `.config/gh/hosts.yml`, `.agentkit/secrets/claude_oauth_token` and the desktop's `.local/share/browser-bridge/Xauthority`. Grok's `auth.json.lock` is shared too, so refreshers use the caller's lock, and so is `.agentkit/state/harness-swaps.json`, so a harness the host is reinstalling is waited for in the sandbox too. Harness login sources honor `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `GROK_HOME` and `GH_CONFIG_DIR` before those overrides are cleared for the sandbox. No caller directory is linked. It copies `.claude.json` for the account and MCP fields, `.gitconfig` and `.config/gh/config.yml` for GitHub access, and `.config/opencode/opencode.json` for installations storing static API keys there (honoring `OPENCODE_CONFIG_DIR` or `OPENCODE_CONFIG`). Installer binaries stay on PATH without linking their directories, and Muse's raw cached readings are copied with their original age to avoid another paid probe. Claude's direct MCP call uses the worker token when available, as its workers do. A harness in the sandbox renews the caller's login as it would at home. Checks needing an uninstalled harness, a missing login, a Discord secret, a user systemd manager or the shared browser skip as not on this host and count as passed, like a throttled meter's. Check 3a separately asserts that Claude streams events before its successful result and that `final.md` and `session_id` match it. Check 3 is `ak update`'s proof, in the live mode, that every harness still works: the standalone `tests/check_harness_contract.py` discovers adapter manifests; every harness installed with its login writes a file from the prompt, closes with `ak hand-in done`, returns `final.md` and `session_id`, then resumes that session and recalls the filename after the check removes the file, bare, in backticks or as a Markdown link's text, each one without is named as not checked and never counted as passed, and the suite fails when check 3 makes no real call at all (a settings file with no key in it, such as OpenCode's `opencode.json`, is no login). `tests/e2e-fresh.sh` makes its throwaway HOME under `~/.agentkit/tmp/e2e-*`, not `/tmp`, so the worker boxes of its real task, each with an empty `/tmp` of its own, can run that HOME's agentkit; its private tmux socket directory stays short under `/tmp` even with a long caller HOME and is removed on cleanup; it links every harness's login the same way, from the same overrides, returns a renamed-over one the same way, finds each harness binary on the caller's PATH or in its installer's directory, asks each adapter's `auth` whether it can log in within the 20 seconds `worker.auth_ok` allows (Claude's worker token counts), and skips what the host lacks likewise; a lent login that is refused or unanswered fails. Its menu seat needs Claude's own pair and its GitHub run Claude and Codex. An exhausted model skips with the reason; the skip counts as passed when the same suite made a real model call that passed, and otherwise leaves the gate incomplete. Expired, malformed or unreadable saved logins fail. Exhaustion is checked per model on the usual login the sandbox borrows, in both its snapshot and the host-cache fallback. A failed live call that announces quota exhaustion or a billing refusal also skips, recording the refusal in the suite's snapshot so later checks avoid that provider even when its last meter was below 100%; other errors still fail. The GitHub run takes the executor and reviewer `ak run` would pick among every configured model from the suite's snapshot (`tests/check4_pair.py`), names them when it passes, and skips before resetting its remote only when every model it can run is exhausted, or as not on this host when it can run none; each MCP check skips when its required model is unavailable or exhausted. `bash tests/smoke.sh --claude-stream <out-dir>` captures events for the offline reader fixture; its sandbox HOME is a separate temporary directory removed on exit, leaving no credential links in the output.

A suite whose `tests:` line names `AK_SHARD` can run on a suite helper: a Mac with Apple's `container` that `suite_helper` in `~/.agentkit/config.toml` names by ssh alias. Before it waits for a turn here, ak asks the Mac over ssh (`tools/helper/mac.sh`) whether it is on its charger, free of another suite (it takes one at a time) and how many pieces fit: the CPUs its load leaves and half the memory macOS calls free; each piece gets two CPUs or more (a one-CPU VM hands terminal bytes over late, failing the suite's terminal tests) and twice the piece's measured memory, or more once its repository's VMs ran out of memory. When one fits, it sends the checkout's HEAD and its `origin` default branch, with only the history the Mac lacks: the Mac keeps each repository's history between its suites (the whole of it arrives with the first, a week unused deletes it, and git's own gc drops commits nothing reaches two weeks on). It runs each piece in a Linux VM of its own, built once from the recipe the repository's `AGENTS.md` front matter names in `suite_image: <path>`, else from the repository's own `tools/helper/Containerfile`, as agentkit has; a repository with neither runs its suite here, since its tools are not in an image. Each repository's image is its own; the recipe may `COPY` only files HEAD tracks, not links, named by plain path, which ak sends with it, their modes too, else the suite runs here with a `WARN` line; it provides bash, git, `ip`, `unshare`, `setpriv` and a user `ak` of uid 1000 with home `/home/ak`. A changed recipe, copied file or its mode replaces that image, the base image its build fetched goes, a repository's image goes with its history, and the Mac's other images stay. Each VM has only that tree and its repository's history mounted, read-only, no DNS and nothing but loopback; the harness programs this host has are stand-ins there that answer only `--version`. No turn is taken here while the pieces run there; a piece that finds another suite on the Mac waits up to three minutes for it. A piece the Mac lost -- it left the charger or slept, the connection or the VM broke -- or failed runs again here, all of them at once on this host's turns, and decides the suite; a VM that ran out of memory is a line in the log, and the repository's next VMs each get what one piece fewer would have had (twice as much after a suite of one piece), kept in `~/.agentkit/state/helper-memory-<repo>`; any other failure there, a piece that changed the checkout it tests among them, is a `WARN` line in the log naming a file that keeps what the piece printed there. `caffeinate` keeps the Mac awake while a piece runs, and the VM stops when ak's ssh session ends. A Mac that does not answer, is on battery or has no room leaves the suite here.

## The Mac bridge and the shared browser

Drag a file into a session on the Mac: the agent runs `ak fetch <path>` on the server and reads the copy it prints, in
`~/.agentkit/macbridge/inbox/`. On macOS `install.sh` adds a LaunchAgent that connects out to the server over SSH and
sends only requested files, so Remote Login stays off; a reader under the terminal app supplies files macOS lets only
that app read, and a new terminal tab or `ak` starts both. It logs to the Mac's `~/.agentkit/macbridge/macbridge.log`.

The server runs one Chromium on a virtual display whose profile holds the real logins; it speaks CDP on `127.0.0.1:9222`
and five system units keep it up over reboots, plus one more for the browser tool: a single shared Playwright MCP server
on `localhost:8931` serves every seat over HTTP, from a package `ak browser install` pins once, never fetched per session.
Agents reach it through the `browser` (by URL) and `desktop` MCP servers `ak browser mcp-register` registers for Claude
Code and Codex, and Muse through `browser/bridge.py`. `ak browser status` shows the units, tabs and noVNC URL; `ak browser
login` prints the URL and password for signing a site in by hand; `ak browser install` stands it up where there is none.
The tick closes a tab idle for an hour or past twelve open, and one a run or seat opened closes when it ends or stops; Chromium is never restarted. noVNC binds to the Tailscale address.

## The boards

`ak models` (`agentkit/matrix.py`) reads the public boards whose numbers export, each at most once a day into
`~/.agentkit/state/matrix.json` (`FRESH_FOR`); `--refresh` asks again now, `--json` prints the scored rows, the
recommendation and each board's `asked_at`, `fetched_at` and `error`. Artificial
Analysis is asked with the key in `~/.agentkit/secrets/artificialanalysis_key` (free at artificialanalysis.ai/login;
without it the board says `no key` and the others are still asked): its free endpoint, page by page, one row per model
and effort, every number it gives as `aa.<field>`, a table's fields under the table's name (`aa.evaluations.artificial_analysis_coding_index`,
`aa.pricing.price_1m_input_tokens`; the intelligence, coding, agentic and capability indexes, prices, output speed;
per-benchmark scores are Pro's). Arena Agent is read off its leaderboard's Hugging Face dataset, page by page, the `agent` and
`agent_steerability` boards as `arena.<board>`. LiveBench 2.0 is read off its newest release whose table answers (the
dates are in its page's script): each suite as `livebench.<suite>` and `livebench.cost_coding`, the cost of a successful
coding task as the site counts it; the release's cost file is part of the answer. A board's row is one model at one effort,
read off the bracket in its name (`Claude Opus 5.5 (max)`; `Acme Pro (High) (0813)` is `Acme Pro (0813)` at high; `Acme
5 (Max, Default Fallback)` is `Acme 5 (Default Fallback)` at max; `(Non-reasoning)` is `none`, a bracket naming no effort
leaves the row at none). A board that cannot answer keeps its last
rows with the error beside them and, like one that answered, is not asked again before the day is up. Callers at once
share one collection: each writer of `state/matrix.json` (`collect`, the stored matrix) holds `matrix.lock` from reading it to replacing it.

The matrix (`rows`) is one row per model and effort the installed harnesses offer (every `config.manifests` name
`config.harness_present` says is here, their `config.catalog`, and every configured model): an effort a board lists
for the model, among those the harness offers, or one the config runs it at in any role (`config.role_effort`), so a
board naming no effort counts for every effort of its model, and a model no board lists at any effort is one row at
none. A board's model is found by its letters and digits (`normal`: `claude-opus-5-5` is `Claude Opus 5.5 (max)` at
max), else by the board's name the id extends with a version only (`muse-wonder-full` for `muse-wonder-full-1.0`;
`found`), else by the one board name that is the model with a qualifier in brackets (`Acme 5 (Default Fallback)` for
`acme-5`; two such names stand for nothing), else, on a board where none of these finds it, by `benchmark` on the
config entry; at the row's effort, else the board's row naming none, never a row at another effort (`matching`). Each row carries the config name that runs it and the
roles it runs it in (`roles`), every matched board's numbers and which board model and effort each came from.

Every row is scored per role (`scored`), on quality and cost alone: speed is ak's own to fix, and the subscriptions
follow the choice. A column is the row's share of the best value in that column among the rows (100 for the best; 0 at
zero or below, still counted: Arena's net improvement can be negative). A model's score for a role is the mean share
over the role's measures on its row holding the most of them, kept with how many it rests on, and it needs at least
half of them, else no score; a row's quality is that times what its effort keeps of it (`kept`): its mean share over
the role's measures whose values differ between the model's efforts, else over the intelligence index, against the
model's best effort, 1 where nothing tells the efforts apart, and a row lacking what tells the others apart has no
score (a board naming no effort counts for every effort of its model, so LiveBench's numbers never tell efforts apart;
Artificial Analysis's indexes do). `ROLES` names each role's measures and why, pinned by `tests/test_matrix_measures.py` so they change only
with a visible test change and the owner's yes: orchestrate is Arena Agent's net improvement and steerability, Artificial
Analysis's agentic index and LiveBench's long-horizon suite; execute is Artificial Analysis's coding and agentic indexes,
LiveBench's coding and long-horizon suites; review, with no public review board exporting its numbers, is the
intelligence and coding indexes and LiveBench's reasoning suite (Artificial Analysis's free endpoint carries its indexes,
never one benchmark's score, which is Pro only). A row within `within` points of the best for the role counts as as
good as it (`WITHIN`, 5: the three boards disagree with each other about the differences between the top models by
more; `within` in config.toml, a number 0 or more, overrides it), and the cheapest of those is recommended
(`recommended`), the others beside it, one per model at its cheapest such effort: by `cost`, what Artificial Analysis's
index run cost on the row, then `$/task`, LiveBench's cost of a successful coding task, for a row Artificial Analysis
has not run, unpriced last, then the higher quality (exact; the table rounds it), then the row the config runs in the
role, then the higher effort (`effort_rank`), then the first by harness and model name, so the pick is the same however
the table is ordered and the table and `--json` name the same rows. The table lists the best rows first: model,
harness, id and effort, `orch`, `exec` and `review` as `97 of 3`, `cost` and `$/task`; under it the recommendation per
role with the rows as good beside it, or that no board has a row ak can run, how a row is scored, what each role is
scored on, one line per board with how many rows, when and its note, and the rows no board has. `--json` is the scored
rows, `within`, the recommendation (per role its rows as good, the recommended first), ak's own numbers (`live`) and
the boards' notes.

ak's own numbers (`live`) stand under the scores, per configured model, the effort it ran at and role, and never rank
(AGENTS.md, Owner rules): over the history's runs that ended with a verdict of the work (`pass`, `fail`, `blocked`; a stopped, not needed or
errored run counts for nothing), of the runs it executed, the share merged in round 1 (a merge as the scoreboard tells one:
the row's size, else its record; a run passed without merging is none), and of the pull requests its seat wrote (the writer
the run's row keeps, never the seat that launched a review of another's), the share merged in round 1; over the runs it
finished a review of, in any round and whatever became of the run since (its decision stood once given; a stopped run's
never counts), by its harness and model id, the share whose round 1 it ended PASS (a review from before its round was
recorded counts for nothing); each as `55% of 320`, `-` where it ran none. Every run records the effort each role ran it
at, the entry's for that role at the time (`executor_effort` at the executor's turn, `own_orchestrator_effort` with the
writer of a seat's own pull request as its review's launch captures it, which a restart carries with the writer, and each
review's `effort` on its review row with its round and verdict), so a model's numbers are one row per effort (`opus @ max`,
the strongest first), and its bare name holds the runs from before that was recorded. Attribution: artificialanalysis.ai,
arena.ai, livebench.ai.

## The history

Every run is recorded in `~/.agentkit/history.db`: repository, models and the launching seat's orchestrator, the model
whose seat wrote the pull request it reviewed, rounds, verdict, timestamps, active seconds per step (checkpointed every 30 s; parks, slot, login and retry waits
are no step's), the seconds it waited for a slot and for a heavy-suite turn of its own, counted by the waiting process as it polls (one that dies loses at most a poll), the seconds its landing checks waited for a heavy-suite turn, counted the same way by the lander, and the seconds it held a place in its repository's landing line, from the record write that gives it one to the write that ends it -- landing, leaving, a stop, a wake to fix; recovery that keeps the place keeps it counting, and a slot admission while it holds one counts as both
(summed across resumes; a row from before they were kept reads as not recorded, never zero), one row per phase of the run -- each step a process ran, ended at its last checkpoint while it runs, and each wait, whole -- in order, tokens where the harness reports them (else unknown), peak process-tree memory, session, and the task's
words, goal points, checks and files changed, and the change it belongs to: the PR it reviews as `owner/repo#n`, however its URL was spelled, else the change of the run a `from:` launch continues, else its own; and each finished review, by the harness and model id
that ran it, with its weighed counts, its round and the round's verdict. Merged runs also keep additions plus deletions, excluding files marked
`linguist-generated` in `.gitattributes`. Smoke and e2e runs are never recorded; an older agentkit's rows are read
as written, never rewritten. Statistics skip
stopped runs and suite runs, by name or run record. History is best effort.
`ak run status --history` compares the last 7 days with the 7 before for products and ak:
runs ended, shares merged in round 1 and ended without merging, median wall hours to merge and reported tokens per merge, ak's share of all recorded tokens (failed work included), and its committed code lines, README words and AGENTS.md words now and 7 days ago; for all ended runs, the share of run time spent waiting for a slot or for a heavy-suite turn of its own, and the hours spent holding a place in a landing line, the lander's checks included, with the hours those checks waited for a heavy-suite turn (not recorded for a week with a run that ended before they were kept); a run started again since its ending (a resume, a delivery retry) counts there at its next ending. For each change merged in the week, every run of it that ended in the two weeks counts: the board shows the median hours a change spent in model turns, in ak's own work (its checks and merge steps), waiting (for a slot, a heavy-suite turn and in a landing line) and with its seat between its runs (the wall time from its first run's start to its last run's end less its runs' time), or `no merged change`. Each second of a run's phase rows is in one part, the first that holds it: a model turn, else ak's own work (a merge step runs from the run's place in the line), else a wait; time in none, such as a park on a spent quota window, is in no part; a run with no phase row (no step and no wait) splits as zero, and a change with a run whose step columns count seconds its step rows do not hold -- one from before the rows were kept, or begun before them -- is not recorded.
For the changes merged in each week it shows how many broke after review passed them: their own tests went red at landing (a suite piece red on their tree after the target alone passed, or a required check failed; `deliver.suite_red`), or main's checks or their live `health:` broke after their merge, once the tick tells a seat of the break (`watch.broke_after_merge`). Each run's history row keeps both. A conflict with the target, a head moved past its review, a red target or the rules' size is no break, and neither is code a later change rewrites: that may be the next feature. A merged run whose row is from before breaks were recorded is counted as unknown.
`built` counts the week's merged runs by who built the change, seats (a pull request's review, the seat's own or another's) against workers (a task or fix run), each with the share of its merged runs that merged in round 1 (a run from before its row named its change is told by its record, and counts in neither once that is gone); `parks` counts the runs the park stopped that week to wait on an older change's lines (`leases.park` stamps the moment on the run's row, `parked_at`, since a stopped run is in no other count); `sunk` is the share of the week's recorded tokens, and their count, that went to runs that ended without delivering a merge, the cost the medians per merged run leave out; `owner` is the owner's time: the questions seats asked them that week, the cards sent to them, and the median hours a question answered that week had waited since it was last asked, each moment a row notify writes as it decides it (a question new to a notice, a card delivered, each standing question answered, by the owner's prompt or, where no prompt hook reports one, by output after an open). `intent` is the median hours from the owner's first message to the done that ends it, over the week's dones whose start ak knows, and how many those are: each done records the first message in the seat's conversation since that conversation's previous done, read from the conversation itself with ak's own lines left out, so a rename keeps a seat's dones and a name opened anew starts its own; its start is unknown with no message of the owner's since, where the harness reads no messages or cannot read them at that done, and for the first done of a conversation begun before an older history first kept dones. Beside it, the median hours from that first message to live, over the intents that are: a known start keeps the runs the seat started from it to the done, and the intent is live once each has ended and each that passed is live (`health:`), at the last of them; while one runs, one that passed is not live, or none passed, it is not.
`scoreboard.loss` names a week's largest loss off that board, for the weekly audit: the first measure in the vision's order (quality: changes that broke main or live after merge, changes whose tests went red at landing, runs ended without merging, runs merged in round 1; speed: hours from the owner's first message to done and to live, hours to merge, time waiting; cost: questions asked of the owner, cards sent to them, tokens per merged run, ak's share of all tokens, tokens spent on runs that never merged, runs the park stopped; size: ak's code lines, README words and AGENTS.md words) that reads worse than the week before, else the first the board reads at all this week.
What the board measures is pinned by `tests/test_scoreboard_measures.py`, row by row with the parts each cell is built from (`scoreboard.MEASURES`), so a measure added, dropped or renamed is a visible test change, made with the owner's yes.
It never picks a model or changes a limit; it also shows median rounds by task size per repo, and the bytes of the `AGENTS.md` that repo's last ended run handed its workers, measured as the ceiling measures it, against that ceiling, and nothing once that run was handed none (no file, or a link). Each run's row keeps that size, read at its base. Neither it nor `ak usage` prints per-model
success rates: a run's verdict describes the task, not the quality of its models. A run's own directory is
`~/.agentkit/runs/<YYYYMMDD-HHMM>-<slug>/`: `task.md`, `run.json`, `log.txt` (the whole loop, with a `WARN` line per
retry), `result.md` (linking a scratch run's files) and `round-<r>/<role>/{prompt.md,final.md,stderr.log,events.jsonl}`.

## Troubleshooting

- A harness login expired: open the seat and log in there; for `gh login expired`, run `gh auth login` on the server. Parked runs resume by themselves. For `claude worker token expired`, or `expires … (in N days)` under the ak screen's usage, run `claude setup-token` and replace `~/.agentkit/secrets/claude_oauth_token`.
- A dropped Mac file the server cannot read: open a new Mac terminal tab or run `ak macbridge --reader` there, then fetch again.
- Test one headless turn: `ak worker opus prompt.md --workspace ~/code/foo`.
- A stale usage reading: open the menu; it reads each provider again within a minute, Claude within fifteen or its endpoint's longer `Retry-After`.
- The slice ceiling: pin `slice_tasks_max` and friends in `~/.agentkit/config.toml` (an install rewrites its own `limits.conf`), or `systemctl --user set-property agentkit.slice TasksMax=4096` for now; the user unit's ceiling above it follows the machine where `sudo` needs no password.
- A failed `ak update` that could not restore Muse: its snapshot is under `~/.agentkit/tmp/muse-snapshot-*`, named in the log.
