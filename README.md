# agentkit

You talk. It ships.

One command installs it. One word opens it. You tell one orchestrator what you want, and agentkit works until the change ships or it truly needs you. Then it tells you, once. Each orchestrator's rulebook opens with `What ak is for` from the agentkit checkout's `AGENTS.md`, where present.

Jobs keep your words since the seat's previous job, capped at the newest 64 KiB, from Claude, Codex or Grok records. ak's notices are excluded; relayed owner replies count. Delivery checks will use them.

A seat's own `ak run --review-pr` fixes a FAIL itself: a fixer turn on the run's checkout of the PR (the seat's own model, headless) takes the findings, its commit is pushed to the PR branch over the reviewed head, and the next round reviews it, for up to three review rounds; nothing is typed into the seat and nothing waits for it. PASS merges with green checks. A seat's own pull request's first review takes at most 400 added lines (generated files aside; what it deletes never counts) and a task at most three per-round checks: past either, ak refuses with `split it`; size is recorded. `ak run status --history` compares the last two weeks of products and ak: runs ended, first-round merges, endings without a merge, median hours to merge and tokens per merged run, plus ak's share of tokens and its code lines and README words now and seven days ago. The scoreboard never picks a model or changes a limit.

## Install

```bash
git clone https://github.com/Sfaiug/agentkit ~/agentkit && ~/agentkit/install.sh
```

On a terminal, and only for what is missing, it asks: which harness to install when there is none (one, or `all`; one is enough, and a run on a machine that has one keeps what it has and adds none), each harness's login, `gh auth login`, `sudo tailscale up`, the Claude worker token `claude setup-token` prints, and a Discord webhook URL and user id (Enter skips those three). sudo asks for its password where packages are missing. Everything else has a default that works.

## Use

Type `ak`. It opens at once and checks for an update behind the screen, the rule under the header filling as it goes. When the update finishes, the main screen starts again on the new code with the same session highlighted; an open sub-screen waits until you come back. Leaving lets the update finish. One screen: your sessions, what each is doing, and one line at the top: `nothing needs you` or `2 need you`. Six keys:

```
1 2 3   open that session
n       start a session
x       stop a session, or close a done one
c       change the config and the session's models
esc     leave
```

From a seat, `ak run stop` and `ak orch stop` refuse another seat's work (`owned by seat X; a seat stops only its own runs`). Your own runs and runs launched outside a seat still stop; the owner's menu and plain terminal can stop any work.

Seats keep terminal input and redraws flowing independently, even when both buffers fill; the shared transport applies to every wrapped harness. Each relay poll writes newly read input as far as the harness terminal accepts it, without waiting for another poll.

Starting or resuming a seat keeps the caller's home, harness state locations and notification destination, even on a tmux server started by another shell. Its menu uses the same environment. A failed resume keeps the old harness and its menu together. A sandboxed probe stays in its sandbox.

A seat's own `tmux` is a shim first on its PATH: a kill (`kill-server`/`kill-session`/`kill-window`/`kill-pane`) that would end another seat, or a type into one (`send-keys`, `paste-buffer`, `send-prefix`, `pipe-pane -I`), is refused, since nothing a seat writes is typed into another seat; which seat a `-t` names is answered by the real tmux, so the guard's answer is the command's own. Every other call runs the real tmux. A tmux reached by an absolute path, tmux's own `run-shell`, a `-t` left off, and the commands that move, replace or respawn a pane or window are beyond it; the bypass-proof form is a `tmux -L <seat>` socket per seat. A `gh` shim on the same PATH refuses a seat's `gh pr merge` — merging is ak's job once a PR passes review with green checks, so the seat lets it land through the line; the inbox, which `ak watch` asks before merging someone else's PR, may run it by hand. Like the tmux guard it catches the merge a seat reflexively types, not a determined bypass: gh's API or GraphQL merge, a gh alias for `pr merge`, and gh by an absolute path are beyond it. A `git` shim refuses a seat's `git worktree add` into `~/code`, which holds only the owner's checkouts: a seat's checkout goes under `~/.agentkit/wt/`. `scp`/`rsync`/`sftp` shims refuse a transfer that writes to the live host — the ssh alias you set as `live_host` in config (ak ships with none and guards nothing until you name your own deploy host) — because a file reaches the live host only through the repo. scp/rsync write to an operand after the first, so a `live:` write is caught by position even behind a trailing `--exclude x` or `-e ssh`, with no option grammar to re-derive; sftp's host operand is refused. A read from live, a transfer to any other host, and a write made inside `ssh live "…"` (beyond the shim, as with gh) all run.

On a terminal a key acts the moment you press it, no Enter. One session is highlighted: ↑↓ (or `k` `j`, or the wheel) move it and Enter opens it. A click on a session opens it, and a click on the key line does what that key does. Whatever the pointer is over lights up, on every screen: the session or row under it takes the highlight, and a key or a mark a soft background. Nobody needs a manual: while the pointer rests on a session, its state word, a project, a usage row, any key on the key line but `esc back`, a model or a mark on `c` and `n`, an effort, or a provider or subscription, the key line says what it is in one sentence, wrapping at words without cutting it or moving the rows above. Lists leave room for the whole explanation, so hovering never scrolls the screen; the keys come back when it leaves. A usage row under it sends one glint across its bar and puts a hairline tick at the share that would be left had it been spent as fast as time passes, and the key line reads `Claude II · 68% left · resets Thu 20:00 (in 2 d 6 h) · lasts at this pace`: `runs out early at this pace`, `lasts at this pace` or `on pace` says whether the allowance lasts the week, and a spent one says nothing of pace. Two digits within half a second are one number. Esc goes back from every screen and question, and leaves this one; `q` is no key. A name or a Discord secret is typed on the same keys, so Esc cancels it at once with nothing saved. From a pipe, an empty line or the end of input goes back.

`x` is the highlighted session's. When a session is done, press `x` on it and it is closed at once: its runs, checkouts, conversation and files go with it, and the key line says `x close` while it is highlighted. Any other session asks first, under its row: `Stop <name> and everything it runs?`, with `Keep` picked until you move to `Stop`; Esc keeps it. `c` holds the highlighted session's models: its orchestrator, executors and reviewers. Picking another orchestrator moves the seat to it at once under the same name, its runs, plan and record staying, with a handover as the new one's first prompt; a model whose harness is not installed or not logged in, or whose meter is spent, is refused in one line.

`c` is every model once, under its company: `orch` (`●`) marks the highlighted session's orchestrator, `exec` and `review` (`■`) mark its executors and reviewers, and `‹ xhigh ›` is the model's effort, beside a bar for each level it offers filled up to it (`▂▃▅▆█`; a model with one effort shows its word alone); on a project's heading, or with no sessions, only the effort shows. ↑↓ move between models and ←→ between those columns, the effort's too; Enter, space or a click flips a mark, Enter or space on an effort steps it up through that model's own efforts and from the highest back to the lowest, and a click on `‹` or `›` steps it down or up; a step never waits on a harness's model list. Each change is saved at once; reviewers keep at least one model, executors may be left empty, and only a choice no run could start from is refused in one line. An older session without reviewers shows its worker list in both role columns; the first mark flipped writes separate lists. ← from the marks reaches a model's label, and Enter there opens its own screen: its model id picked from its harness's catalog (the effort stays if the new model takes it, else moves to the nearest it does), its effort, and `Remove`, which asks `Keep` or `Remove` and is refused for the last model. Esc goes back to its row. Its reviewing line shows finished reviews, catches, existing defects and unproven notes for that harness and model id, excluding stopped and suite runs. Under the models, `+ add a model` is three lists in one screen: a harness of a company the config has, then a model its catalog offers (one already configured is marked, and can be added at another effort), then an effort that model takes; Enter on the effort adds it, named from its label (`sonnet`, `sonnet-2`), and Esc steps back one list. `Providers` lists your providers in their colours, the pointer on Claude giving the worker token's expiry, which stands under the rows once it is 14 days away or less; ←→ choose `+ add`, `− remove` or, while a subscription holds a usage-limit reset, `↻ spend a reset`. `+ add` offers the ones agentkit ships that you have not added. Pick one with Enter or a click on `⏎ add`: ak installs a missing harness, logs it in on the terminal, and adds it as it ships with its catalog's first model. It also offers another subscription of each provider you have, by the name it will get (`ChatGPT II`): that one is logged in on the terminal and added to the provider's `accounts`, and a login that fails adds nothing. `− remove` asks `Remove <provider> and its models?`, `Keep` picked, and takes its models and its usage rows with it; the last provider stays. It also lists each subscription of a provider with several but the usual login, and `Remove Claude II?` takes only that one out of `accounts`. Removing never deletes a login: while its harness still accepts it, `+ add` offers a removed subscription, or a removed provider's usual login, as `Use <email>` (or the name its usage row had), and puts it back with no login step. A provider that lists `accounts` has one usage row per subscription in config order, numbered in roman numerals (`Claude I`, `Claude II`), each with its week's bar and its 5-hour window (`5h 40% left`, or `5h spent until 14:00` once spent). `Discord` shows who a card pings and where it goes, `@acme-owner · webhook …a1B2c3`: the name Discord gave that user id on the last delivered card (the id's last 4 digits until one has) and the webhook's last 6 characters, never more of it; Enter runs it (its two secrets are the only typing left). `Version` is agentkit's commit and its date, and does nothing. Esc goes back.

A session is one of three things, and nothing else:

```
! needs you   it asked you something, or it cannot go on without you
● working     a run of its own is going, or a turn is, or a session it waits on works
✓ done        it said so, and the row carries its summary
```

The word moves when the session's harness starts or ends a turn or asks something: at once on the session's own two-line tmux bar, and within two seconds on an open menu. Line one opens with the word and says who orchestrates (`● working  ak-verification  opus orchestrates`), then, while it works, its tasks bar: merged tasks solid, each run going part of the next task by its step (building, checks, review, landing), red on its last round, the count on the fill. Its right end names each other seat that needs you (a click switches to it) and counts the rest, and every other seat's bar shows the change at once. Line two carries the question or summary, or what each run is doing now (`lg1 ■■■□ astra reviewing · 11m`), and `Ctrl-b m  menu`. Runs update it at each step, round and ending, waiting at most one second for tmux; the next tick or step retries. No screen says when a seat's work will finish.

Notices with no state in the harness's manifest leave the last hook fact alone: a running turn stays working, and an ended turn stays at its prompt.

Press `n`, then Enter. `n` uses the same model names and provider headings as `c`, with what your last session was created with already chosen (the shipped models the first time):

```
         orch  exec  review
Claude
  fable   ○     □      □     claude · xhigh
› opus    ●     ■      ■     claude · xhigh
ChatGPT
  astra   ○     ■      ■     codex · xhigh
```

Every model has all three marks; the headings stay visible while the rows scroll. ↑↓ move between models, ←→ between roles, space or a click chooses, Enter starts from anywhere, Esc goes back. The session saves both role groups. Reviewers keep at least one model; executors may be left empty, and then the orchestrator builds everything, its own `exec` mark drawn filled and dim, and the session launches no task. Only choices or starts no run could start from are refused in one line. If a nonempty default group has no unspent models, its fallback takes another company's fresh model before the executor's company's, before the executor itself. A model whose provider is spent reads dim with `spent · resets Fri 14:00` and is never chosen for you. `n` first asks `Name:` two spaces in, with `auto` dim in the field and `esc back` below it; a bare `ak orch` asks `Name (Enter: auto):`. Type a name, or press Enter for `new`, then `new-2`: the orchestrator names it as soon as it knows the job, as briefly as possible in at most three words. To name it yourself and end auto naming, rename its conversation or run `ak orch rename <name>`. Claude's Remote Control title, Codex's thread name, Grok Build's manual session title and OpenCode's session title follow the seat's name. Muse sessions keep their own name: the installed Muse refuses `/rename` even after a turn and rejects `--name`, so ak never types a rename into Muse. Codex's index and database do not distinguish generated names from `/rename`, so Codex titles never rename the seat, even after an owner's `/rename`; use ak to rename it. ak confirms its name from the owned thread's login index and restores it if Codex replaces it after the first prompt, stopping after three unconfirmed tries until the seat's name changes; an acknowledged name is not retyped, and a mid-turn attempt without a receipt waits for the prompt before retrying. Grok waits for an empty prompt and confirms only the manual title in its own conversation; automatic titles never rename the seat. OpenCode's seat plugin sets and reads back its own session's title through the API, including new seats, ak renames and auto naming, without typing or touching drafts. OpenCode 2.0.14 gives owner and automatic titles the same field and event, so neither renames the seat; the plugin restores ak's name when either changes it. All four leave owner drafts alone. Claude waits past dialogs and drafts and counts only once it records the title (or the composer clears if its transcript is unreadable); it gives its held line Enter even when wrapped, after the third typing or a later rename, and types each name at most three times before giving up until the name changes. Superseded pending titles stay recorded as agentkit's within that conversation until the name is explicitly retaken, so a delayed title cannot rename the seat back; owner drafts are never touched. Each typed line, its brief pause and its first Enter share the seat's lock so senders cannot merge lines; confirmation waits release it. A manual rename in Claude or Grok Build renames the seat too, taking a free variant if the name is held (even its own former name); Claude's title readings resume after the last complete line, with one note that moves and is removed with its seat; title errors are logged for their seat without stopping health checks. That is all. As soon as the project is known, the orchestrator files its seat with `ak orch project <checkout>` (name or path), where it stays until filed again, and is shown what the project's other sessions have in flight (open plan lines, files their runs change); a seat never filed so is refiled by each launched run under the project most of its runs belong to, keeping its project on a tie.

After `/clear` in a Claude seat's launched pane, reopening and title changes follow its new conversation on its login. The watch tick binds older running seats to their own client pane without restarting them. If that pane is removed, restarting the seat uses its current pane. In-session `/resume` does not transfer seat ownership. Say what you want. The orchestrator asks until the goal is clear and checkable, then goes. Close the terminal.

`ak plan` lists [numbered outcomes with checks or your judgement](docs/guide.md#the-states-and-the-cards).

## While you are away

Agentkit does not stop until the work ships, or until it truly needs you. Truly needs you means exactly two things: a question only you can answer, or a failure it has tried every way around. Everything else it handles itself: a provider running dry or down for hours, a crash, a reboot, main moving underneath, its own upgrade (the host moves only to a commit whose `tests/live.sh`, agentkit's checks that need the outside world, passed on it; a run takes the new code at its next round, saying `picked up agentkit <old>..<new>`), a reviewer that hesitates, a test budget that was too small, a stuck session.

`AGENTS.md`'s `health:` command checks merged changes in production; passing reports them live.

A turn can end waiting on its job while the launcher is alive and any task is unsettled, even before the first run starts and after a seat rename. A job whose launcher is gone or whose tasks have all settled gives no wait.

Sessions never message each other, on any harness. A session whose work must wait for another's pull request or run ends its turn with `ak wait <pull request URL or run id>`; the tick ends the wait when that pull request merges or closes or that run ends, or when gh could not read the pull request for three ticks running (while gh is logged out the wait holds, and the session reads `needs you: gh login expired`), and types one line into the session saying so, at its next quiet prompt. Nothing one session writes is ever typed into another, and a wait never names a session.

When a session's pane terminal or its wrapper's inner terminal reports unread input, ak holds further lines until those bytes are read, even if the screen shows an empty composer. The wrapper names its inner terminal on its tmux pane before starting the harness; each successful respawn clears the old name before a new wrapper can publish, so switching to a harness without a wrapper keeps the pane-only check. Messages and notices stay queued, and waiting spends none of the recovery-notice retries. The check also holds confirmation of a typed notice while input is unread; the usual composer checks still decide its Enter. A terminal that cannot be checked keeps its previous typing behavior. When the whole composer is visible and shows only ak's full account-switch notice, mid-turn continuation or resume nudge, the next tick gives it Enter under the typing lock, even after its retries ran out; cropped or scrolled composers, partial lines and other text stay yours. Delivery stays at least once: a crash between Enter and recording delivery can repeat a line.

A run recorded in the line to land holds no process and stays working however long it waits. Status and the menu show `waiting · 3rd in line to land on main`; only the lander moves it. Its job follows it to its ending.

Each Codex seat runs its own app server with Remote Control enabled; the pane connects over a private Unix socket. The seat trusts only the hooks agentkit installs; Codex still asks you to review other hooks. Its hooks, rulebook, launch receipt and synced name stay with that conversation. Its conversations are its own, under `~/.codex/agentkit-seats/<id>` whichever subscription it runs on, so it opens in seconds however much Codex history the host holds, and they stay after the seat is removed; startup waits as long as the live server needs while the seat is open, and closing it meanwhile leaves the next start working. The server stops when the pane exits and starts again on resume. Its remote computer and conversation use the seat name in the ChatGPT app. Resumes and account switches keep its installation; removing the seat removes its remote enrollment. Pairing is optional: opening or resuming a seat sends no pairing alert. To connect it from the ChatGPT app, request a fresh code on the host with `python3 ~/agentkit/tools/codex-seat.py --pair <seat-name>`. Older pairing cards close as `Pairing optional`. No daemon or separate Codex installation is needed; workers still use `codex exec`.

A session whose subscription runs out resumes its conversation on another account of the same provider whose seat login passes. Its harness's refusal is read off the seat's screen, with or without a status line under the composer. New sessions also check the login when choosing among configured accounts; accounts with only a worker token serve workers. A manual new session can open the configured usual login to sign in when none passes. If none is available during recovery, it reads `needs you` with the reset time and recovers when usage returns. A refilled account keeps its login without another auth check; without a proven conversation id, the seat continues in place. Opening it to look keeps recovery active; drafts, questions and closed seats are left alone, and idle prompts stay idle. Every provider's subscriptions work for seats, workers and meters; another one is added and removed on the Providers screen of `c`. Credits bought beside a subscription, and what Claude's extra usage has left, the smaller of its monthly limit's remainder and its prepaid balance, count as usage left: once its window is spent, ak keeps picking it for seats, workers and reviews after every subscription with window left, and its usage row says `62,469 credits left` or `$12.40 credits left`. ak never spends a usage-limit reset by itself, and one held adds nothing to what it counts as usage left: its usage row says `1 reset in hand`, and you spend one with `↻ spend a reset` on the Providers row of `c`, which asks which subscription when several hold one; the row then shows the week that came back. Every Claude worker turn refreshes its account's session and weekly meters from its own stream, with no request. A billing refusal parks the worker's account and hands its round to another model, like spent usage.

The orchestrator builds, whatever the size; workers take only independent pieces that share no file with its work or each other, and a session that marks no executor launches no task: its orchestrator builds everything. Every change is checked by its tests and reviewed by a different model before it merges, from a different company where your model groups allow it, else by the executor's own model, marked self-reviewed; only wording you picked yourself merges on its tests alone. Session records and `[defaults]` in `config.toml` may name `reviewers = ["astra"]` beside `workers = ["opus"]`: executors come only from workers, reviewers only from reviewers, ranked by review tier then live budget. When a stalled worker turn changes provider, reviewers from providers that refused nothing go first, with refused reviewers as fallback; later picks use normal order. Past run success and speed never affect the pick. New sessions copy explicit default reviewers. Outside a session, empty default executors refuse task launches before any run or job exists. Without `reviewers`, the shared worker list and legacy picks behave as before, including explicit PR reviewers outside workers. Runs show the saved launch groups in status and the preflight log and keep them through retries, handovers and PR reviews; `--exec` and `--review` cannot name a model outside a bound group. A seat's own PR joins the landing line on PASS and merges its approved stack tree with green checks; anyone else's asks the inbox. A change has at most three review rounds, counted across runs: a review of a seat's own PR inherits the rounds earlier runs spent on that PR, a task launched `from:` a branch continues the change of the run that branch still belongs to and inherits its rounds (a branch name freed by a merge or a stop starts a new change), `ak run resume --rounds` cannot go past what the change has left, more rounds are refused before a run starts, `--anyway` or not, a round another run of the change spent meanwhile is refused as this one would spend it, and work its reviewer still fails after the third goes back to the orchestrator with the findings, to split or redesign. From the second round on, ak re-proves each earlier finding's `--run` proof on the new commit itself and lists the quoted and disputed ones for the reviewer to judge again: a finding still failing blocks whatever the reviewer hands in, and one handed in again at its site is weighed as ak's replay is. The commit a review judged is recorded as the run's `delta_from` by every review, a landing re-review included.

Every worker turn, proof replay and check runs in a bubblewrap box with empty GitHub login files, Git credential stores and SSH keys, no reachable SSH agent, and no GitHub token variables: only the orchestrator's own shell reaches a server. A directory on the way to any of them that is closed to you refuses the box and names the fix; a key kept outside `~/.ssh`, and not linked from it, stays readable where it is. A proof or check has the same filesystem walls, with throwaway overlays for the account's home and `$HOME` so caches and tool config work while it runs and every HOME write outside its writable places disappears when it ends; a home with a mount beneath it, as inside another box, stays read-only. Each box, including one inside a box, has its own empty `/tmp`, `/var/tmp` and `/dev/shm` and a copy of the host's readable `/run` directories, symlinks and regular files on disk in its out dir, excluding masked credentials, `/run/user`, sockets, FIFOs and device nodes; it sets `TMPDIR=/var/tmp` and an empty `XDG_RUNTIME_DIR=/run/user/<uid>` of mode 0700, covers an existing host runtime directory outside those places with an empty directory, and refuses if any of the four host directories is missing, preserving resolver paths while keeping host services there unreachable; a socket elsewhere (under HOME, for instance) or an abstract socket stays reachable, and the box's own network will close the abstract ones. ak's own `git`, the first in a directory ak's own `PATH` names in full, tells a box which credential stores to hide and where the workspace's Git storage is. A `git` that only the turn's `PATH`, a relative `PATH` entry or the current directory names is never asked; with no other, the box refuses. A turn writes only its workspace, out dir and its harness's declared state. Network access stays the same. Every child dies when its turn or command ends, even after detaching or clearing its environment. A turn that leaves processes running is unfinished: ak logs their command lines and asks once to finish in the foreground. Loop helpers keep the run's directory marker, so separate ak homes cannot end each other's processes. The installer adds bubblewrap; `ak run` refuses at launch if this host cannot start nested boxes, naming the remedy. Workers receive the whole base commit's `AGENTS.md` body. `AGENTS.md` must be a file: a link gives workers nothing, and a round that adds or changes one fails its checks. A round that changes `AGENTS.md` fails its checks if the file is then past the most a harness reads of it on its own (the smallest `[instructions] read_limit` an adapter declares); an untouched file passes this check regardless of size.

Reviewers use `ak hand-in finding path:line "what" "why it matters" --run 'command'` (or `--quote 'lines'`), `ak hand-in follow-up` with a one-line `--run` (no backticks or checkout path) and `--before` when the defect predates the task, then `ak hand-in done`. ak refuses missing files, invalid lines, absent quotes or evidence, and calls outside worker turns, in one sentence. A finding’s `--run` command must fail while the defect exists; exit 0 is refused with instructions to fix the proof or use `--quote`. After the turn ak replays each finding’s command in its own clean checkout, on the reviewed commit then on base with changed tests overlaid. A passing or unfinished proof on the commit is a note, as are exits 126/127. Other non-zero exits count as failures regardless of output, including missing scripts or data files. Proven defects block on changed lines or beside removals. Elsewhere a proof passing on base blocks, a failing base proof becomes a follow-up, and unfinished base proofs or exits 126/127 become notes. Quoted findings are checked again against the reviewed commit (the workspace for scratch): a missing file, invalid line or absent verbatim quote makes a note. Valid quotes block on changed lines and become notes elsewhere; without a base, every proven finding blocks. Command evidence keeps ak’s own exit status and bounded output from both commits. Only hand-in records decide a review: done means FAIL with any finding still blocking, otherwise PASS; without done the reviewer is asked once more in its session, then replaced, whatever its text says. Records survive retries, parks and host interruptions on the same session; run.json keeps the weighed records for FAIL hand-backs. Published PR descriptions and reviews are bounded; the run retains the complete records.

Every worker rule says `[checked by ak: <test file>]` and what ak does, or `[worker judgement]`. ak commits uncommitted executor work before checks and review. Every executor and fixer turn closes with `ak hand-in done`, `ak hand-in blocked "<why>"` when the task cannot be done as written, or `ak hand-in not-needed "<why>"` when a fix run's first turn finds the defect gone or already being fixed. The closing record decides the outcome and establishes an answer regardless of the final text. Later records are refused. Reviewers cannot use blocked or not-needed; executors and fixers cannot use finding or follow-up. Without a closing record, the worker is asked once more in its session; a second turn without one proceeds as done to checks and review. The work summary is kept for result.md, including after a closing ask or restart. Turns write only their workspace, Git storage, out dir and declared harness login and sessions. Elsewhere is read-only; temporary files and shared memory use disk under out, removed after teardown.

A reviewer can block only with evidence: a command that fails, a reproduction, or quoted file lines showing the defect. Task reviewers may run whatever is needed to prove or dismiss a finding, except done-when commands whose output they already have, the repository's `tests:` suite (run once at landing on the commit to be merged), and checks marked deferred. Unknown task front-matter keys are refused before a receipt is written, naming the key and accepted keys in one line. Optional task `files:` lines list comma-separated Git pathspecs; changes outside them fail the gate and override reviewer PASS. Heavy suites start when live CPU and memory fit one more, or none run; a pinned `max_gates` caps suites without `AK_SHARD`. When a whole suite takes more than two minutes, ak starts one run per repository and line in its session to split it. A suite line that reads `AK_SHARD=k/N` runs its 1-based share, or everything when unset: ak sizes concurrent pieces from live headroom, the run's memory cap and measured cost, and retries red pieces alone. A round runs only the task's done-when commands and review. A change needs a check that fails on the old code: once its checks pass, ak replays them on base with the branch's tests laid over, then on base with all its changes, each in a clone made from git alone, and records the proof when a check fails on the first and passes on the second. It never fails a round for a missing proof: the result and PR say `base proof: none shown` and why. A fix run proves its `regression.sh` instead. The full suite runs once at landing on the commit to be merged; a failure goes to the landing fixers. Agentkit’s own suite splits its checks and remaining test files across `AK_SHARD=k/N` (1-based), keeping dependent checks together and pieces in separate sandboxes; unset or `1/1` runs everything. The tmux safety guard runs in every piece. Its gate rejects test files that report no cases and Python imports outside the standard library and repository. Its file pool grows with live memory, past the core count for waiting files, and pauses starts while CPU pressure is high. Its landing suite reaches nothing beyond loopback where the host allows a network namespace, and fails on a skipped check. Its retry checks advance a test clock through the unchanged backoff schedule; `tests/live.sh` runs the checks that need the outside world (real models, GitHub, Discord, live meters, the shared browser and user systemd) before a host takes new agentkit code and when a harness upgrades. Its check 3 is `python3 tests/check_harness_contract.py [harness]`: every installed adapter with a login proves prompt delivery, `ak hand-in done`, final output and session recall, using the model and effort in its own manifest. A separate live Claude check proves events arrive before its result and the returned files match that result. Scratch and `--no-merge` runs execute every task check in each round, including `# once` and explicit suite lines; the declared suite is not added. `ak run status` and the result say where each check ran. Outside a landing line, a failing command parks on a red target only if it passes on the old target base of the last head whose checks and review passed; landing re-reviews that skip the suite keep that head. An unchanged base needs no second probe. A command failing on both different commits goes to the branch's fixer. Probes leave nothing behind outside a temporary directory. Scratch reviewers keep the deliverable workspace read-only. Repository reviewers, including reviewers of others' PRs, use a temporary copy with separate Git refs and no push remote. Only regular files and links are copied, into writable directories. Cleanup repairs read-only directories in that copy. Unreadable paths and other file types are skipped with a WARN naming the path; snapshot errors are also recorded in the patch. After every reviewer turn, retries included, ak saves any edits, new files or commits to `round-N/reviewer-changes.patch`, undoes them and logs a WARN naming what it restored. Files already present before review stay. Reviewers of others' PRs may run tests and commands. Follow-ups never block: a defect from before the task has a command that fails on base and `--before` naming the base, an ancestor commit (hash or ref), or verbatim lines in the named file at base; a smaller defect of this change that need not hold it has no `--before` and a command that fails on the reviewed commit, and counts as from before the task if it fails on base too. ak replays every follow-up and drops unproven ones, recording the reason and evidence in Notes. Notes appear under `## Notes` in result.md and the PR body and start no fix run. Only blocking findings, with ak’s proof outputs, go to the fixer. Every round's follow-ups, whatever its verdict, plus checks that passed only on re-run with their `flaky:` evidence, go into `run.json` and the PR description; no shared follow-up file is read or written. Flaky excerpts compare lines with numbers, hex ids and absolute paths masked, and name a file in the run directory holding the whole failed output. A fixer uses `ak hand-in dispute path:line "why it is wrong" --run COMMAND` or `--quote LINES` for a blocking finding handed to its turn, and fixes every undisputed finding. Disputes are refused in review and first executor turns, for other locations, for commands that do not exit 0, or for quotes absent from the named file. ak gives the next reviewer each dispute beside its finding with ak’s own proof output. The reviewer upholds it by handing the finding in again, weighed normally, and drops it by not doing so. Dropped findings and their disputes appear under `## Disputes` in result.md.

A check stopped for silence or its ceiling names the last output and the commands still running, with their elapsed times. A failing done-when after a clean rebase gets up to three landing fixer rounds without spending task rounds. Landing re-review, including older saved reviews, runs at the current round even when the budget is spent: a PASS lands without spending a round; fixing a FAIL's findings spends a task round while any remain. An unreachable target parks a pending landing review as a retryable error; an exhausted conflict fixer keeps its pending review at the current round. Timed-out Git remote calls (`fetch`, `push`, `ls-remote`) and `gh` retry once after one second; checkout edits stop for cleanup, and a refused credential prompt stops at once. A PASS whose delivery stopped names `ak run merge <id>` to finish it. A task or PR review whose last eligible reviewer runs out of quota waits for the window to refill, then the tick resumes it; delivery retries follow the same rule.

When a session's run merges, each review follow-up becomes an open line in that session's plan (`ak plan`) on the run's project, checked by its failing command until the session puts its own test in its place (`ak plan check N`), for the session to build with the context it has; an open line with the same check prevents a duplicate, and the run's result names the lines, or why the plan refused one; a merged run's ending, like a change going live or a run not needed, is typed into the session only while its plan has an open line, as the end of a wait its turn may have ended on, and is otherwise recorded, never typed: the session hears only what needs its decision. Every run notice typed into a session uses the bounds of a typed line: what every configured harness's composer shows whole, and 8,000 bytes. A fitting line stays unchanged; a longer ending, review-round result or maintainer decision names the full `result.md` and counts its review follow-ups, kept whole there. Before compaction, ak saves the full notice and follow-ups in `result.md`, including older pending endings; saved notices survive report rebuilds, and after-merge evidence stays there when the tick clears its delivery receipt. Nothing is cut from those files. A flaky check's evidence instead starts an ordinary run of that same session, using its saved workers and the merged target branch. Its task carries the defect and evidence; an open fix at the same site in that session prevents a duplicate. The executor first checks the current target and other open runs: a defect already gone or being fixed ends with `ak hand-in not-needed "<why>"`, counted as done with no PR or review. Otherwise it adds a regression test that fails before and passes after. Once its checks pass, the loop runs its `regression.sh` on the base commit with changed tests overlaid (none when the fix changes only tests) and a fresh bytecode cache; a pass there fails the gate, and the checkout returns to HEAD. Every probe records its original checkout first; after a crash, the resumed run restores it before verifying or building. An owner-only decision ends with `ak hand-in blocked "<question>"`. The merged run's result names the fixes it started; the session stays working until they end, and stopping or closing it stops them. Fix runs' own follow-ups work the same way. Runs without a session, scratch runs and reviews of other people's PRs start none. There is no setting or follow-up backlog.

Each tick, ak merges every pair of live runs of a repository that are to land (never a `--no-merge` one) in memory (`git merge-tree`, over the base they share, uncommitted edits included) and writes a pair that cannot merge on the younger run as waiting on the older, under `~/.agentkit/state/leases/`: a run's lease is its own diff, declared by nobody. A younger run still before its review (its executor turn, or ak's commit step, which runs the scan itself) is stopped there with its branch kept, waiting on the older, and `ak run status` names the wait; once the older has landed or is over, the tick starts its task again on the newest base as a new run of the same seat, which an `ak wait` on the stopped run then follows, and `ak run stop` or closing its seat calls that off. A younger run past that point, a pull request's review, a job's task, a red target's repair and a suite's split are only written down: the lander orders their landings. After PASS, a writable run joins its repository’s landing line; its worker exits. The lander keeps green deliveries in their tested order, then stacks waiting members in join order. When every unanswered stack fits, a pass checks them side by side. Otherwise it checks the deepest unanswered stack first: green covers every member through it; red is narrowed halfway from the last green stack or the target until only the newest member is blamed. Narrowing and rebuilding without that member continue in the same pass, as soon as a check turn is free. A tree already checked with the same commands answers at once; batch coverage is reused only while its tested tree remains in the line. Green members wake in line order and wait for earlier deliveries to finish; only main’s tip after a batch must be tested, and each covered stack records that tested tree. Only a red member leaves to fix itself. The saved place and PASS survive worker stops, crashes, restarts and updates. Foreground `ak run`, `ak run resume` and `ak run merge` follow new log lines to the ending; jobs follow the record. Fork deliveries stay outside the line. Automatic `--review-pr` merges join it too: review rounds run no suite, and the lander checks their changes on top of the target and earlier members. Delivery updates the PR head to that approved stack tree with a lease protecting any newer seat push, then pins the merge to that head. The installed ak starts a fresh pass when membership or verdicts change, after each delivery, from the tick, and from whatever follows a member, so a pass that died unstarted is retried where no tick runs. Passes and deliveries hold separate locks, so checks and merges overlap. Each pass has its own scope and the memory a landing suite needs; on supporting hosts, a test over the cap dies alone so the lander can report its failure. A stopped member leaves the line and is never woken. Members conflicting with the target tip wake to fix at once; conflicts only with earlier members wait. A woken member skips the slot queue, count cap and CPU gate but never the memory gate, `land` ahead of `fix`. It delivers only when its integrated tree matches the lander’s approved stack tree; a changed tree keeps its place. When the first stack fails and the target tree has no recorded pass, the lander checks the bare target’s own suite once. A red target gets one repair first; every other member keeps its place, unblamed, while the repair holds that tree. A PR gets no repair and waits on none: the target's failure goes to its own fixer turn, and the head that fix pushes is checked on its own, so one that mends the target lands. A merged repair or `not needed` ending lets the line check the target again. A passing target leaves that member to fix itself. A task's red verdict or failed required PR check uses the landing fixers and re-review without a task round, then rejoins at its place. A PR's red verdict goes to the run's own fixer turn as findings; the fix it pushes gets review and rejoins the same line. A failed re-review ends with its findings; a fourth red hands back the last failure, and resuming the run afterwards starts its count again. Merges carry `Suite-Passed-Tree: <tree sha>` when the declared `tests:` suite passed on the delivered tree, so CI can skip a repeat on byte-identical code. If GitHub's default merge body cannot be read, ak merges without the trailer and CI runs as usual.

## New features in live projects

A hobby project ships straight to live. The first time a new feature comes up in a project, the orchestrator asks once whether it has real users, and the answer goes into the front matter of its `AGENTS.md`: `users: none` or `users: real`. In a `users: real` project a new feature merges round by round but stays hidden behind the project's own switch, on only for you until you turn it on for everyone; the reviewer fails a round that shows it to anyone else. The project names the one command that lists and flips its switches in the same front matter, `features: <command>`, which answers `<command> list` and `<command> set <id> you|everyone on|off`. A switch on for everyone for two weeks is proven and comes out of the code: once a day ak writes an open line into the plan of the session in that project whose open plan already names each switch, else the newest open one, for every switch its list shows proven, with the project's switch list as the line's check, so it ticks itself once the project's deploy has dropped the row; a switch on for everyone whose row lacks `everyone_since` gets a line asking for it. One turned off after its session was told still comes out: turning a proven switch off is a code change. The `ak` menu then lists the project whether or not a session sits in it, as `ACME · 2 hidden features`, and Enter on that heading opens its switches, `you` and `everyone` for each feature, flipped with the arrow keys and Enter; the project's own owner page flips the same ones.

## Hearing back

One Discord card when a session needs you. It waits 60 seconds, and input in an attached terminal since the episode began holds it back. Once sent it reads `Needs you` for as long as the session does: opening the session to look closes nothing. It reads `Answered` once you answered or the session is working again, and `Done` once it declared its job done. A terminal left untouched still gets the card. One when the whole job is done: a session's done waits until every line of its plan is proven, a check line by its check passing on the default branch (`ak plan`), an eye line by your word, and, where the project proves itself live (`health:`), until the merged change has passed that probe, for the three hours after the merge in which the tick probes it: the seat reads `working` meanwhile, and no card goes out. New receipts remember distinct verified plan outcomes through late handbacks, refreshed proofs, summary changes and renames. Removing completed lines adds no work; newly verified outcomes keep their pending completion until it is sent. Older receipts, seats whose creation is unknown and completions without verified plan outcomes keep their original gates. Each card uses the latest question, declaration and run state, so an older decision cannot announce unfinished work or ask you after completion. A question's time counts only while it remains unanswered. After an answer, a reopened card's minute starts no earlier than the current question; input before that question cannot suppress it. Two words and the session name. Never for a session you closed yourself, never after an upgrade for anything that stood before it. Open the host, press the session's number, read, answer. Your next prompt answers its question in the pane or over Remote Control, even after a rename: its card reads `Answered`; hand-backs never wait for it. Recording the answer runs in the background, so your prompt never waits for a notification. Only a prompt handled in the seat's own pane counts; slash commands, messages from sessions or tasks, and prompts from other panes answer nothing. Watcher alerts keep their own recovery rules. A hand-made tmux session with no interactive agent in it, such as a watcher loop running only ak workers and their descendants, has no row, card or count; its old card closes on the next tick, as for a session that is gone. The card of one you stop or close reads `Answered` at once.

Claude question dialogs stay `needs you` even during an open turn. A question a session asks with `ak notify needs` during its own turn is kept back until that turn ends, where its harness reports its turns to ak by hook (one whose turns only its screen shows is asked at once, as before): until then the session reads as its turn and runs say and no card goes out, since its screen shows no question and it is not waiting for you, and nothing you type meanwhile answers it. From the end of that turn it reads `needs you` until your answer, which your next prompt there is, through any turn a hand-back opens meanwhile. Asked for another session with `--session`, or while an earlier question of the session's own still stands unanswered, it is asked at once: the newer one takes the earlier one's place, and its card stays as it is. Such a question asks first: `ak notify needs` refuses one whose `?` is not within its first 80 characters, since line two and the menu row show a question from its start. Text you type in the composer is an unsent draft, with or without a status line under it. In Claude's composer, a prompt mark typed at the head of an indented continuation stays part of your draft.

## Never needed

Choosing a project. Editing config. Merging. Cleaning up: a stopped session leaves only its stop mark and locks until a daily pass takes them, and that pass takes every checkout (including landing checkouts left by a crash), seat file and harness trust entry nothing uses any more. Restarting anything. Reading a manual. The whole help fits on one screen.

The collector also removes your `/tmp` entries after two days without changes and ended Claude sessions' scratch folders after one day. A repository's `TMPDIR` directly under `/var/tmp` is collected the same way; any other value is skipped. Dot entries, `tmux-*`, `systemd-private-*`, other users' files and paths held open or used as a working directory stay. Both modification and inode-change times count toward age. Claude's live process records protect its current conversations; a client without a matching record keeps all scratch. Hidden process handles are inspected read-only with the host's noninteractive `sudo`; if that inspection fails, `/tmp` cleanup waits. `ak run gc --dry-run` previews removals; automatic removals appear in `~/.agentkit/state/gc.log`.

## Plugins

A model is a few lines in `~/.agentkit/config.toml`, or press `c` and add one. Every model can orchestrate and work; `n` starts from what the last session was created with. A harness is two files under `adapters/`, and says which models it runs and the efforts each takes (`adapters/<h>.sh models`); `ak doctor` names a model set to an effort it does not take. Claude Code, Codex, Muse, Grok Build, OpenCode and Google's Antigravity CLI (`gemini`) come wired in. One provider is enough to start: a harness that is not installed or not logged in is never picked, one model left reviews its own work, marked self-reviewed, and `ak run` refuses in one sentence when no worker can run; groups spanning two providers allow review by a different company.
