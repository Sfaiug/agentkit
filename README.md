# agentkit

You talk. It ships.

One command installs it. One word opens it. You tell one orchestrator what you want, and agentkit works until the change is merged or it truly needs you. Then it tells you, once. Each orchestrator's rulebook opens with `What ak is for` from the agentkit checkout's `AGENTS.md`, where present.

Jobs keep your words since the seat's previous job, capped at the newest 64 KiB, from Claude, Codex or Grok records. ak's notices are excluded; relayed owner replies count. Delivery checks will use them.

A seat's own `ak run --review-pr` sends FAIL findings back to the seat and waits for its push, for up to three review rounds; PASS merges with green checks. No size limit refuses a PR or a task; size is recorded. `ak run status --history` compares the last two weeks of products and ak: runs ended, first-round merges, endings without a merge, median hours to merge and tokens per merged run, plus ak's share of tokens and its code lines and README words now and seven days ago. The scoreboard never picks a model or changes a limit.

## Install

```bash
git clone https://github.com/Sfaiug/agentkit ~/agentkit && ~/agentkit/install.sh
```

On a terminal, and only for what is missing, it asks: which harness to install when there is none (one, or `all`; one is enough, and a run on a machine that has one keeps what it has and adds none), each harness's login, `gh auth login`, `sudo tailscale up`, the Claude worker token `claude setup-token` prints, and a Discord webhook URL and user id (Enter skips those three). sudo asks for its password where packages are missing. Everything else has a default that works.

## Use

Type `ak`. It opens at once and checks for an update behind the screen, the rule under the header filling as it goes. When the update finishes, the main screen starts again on the new code with the same session highlighted; an open sub-screen waits until you come back. Leaving lets the update finish. One screen: your sessions, what each is doing, and one line at the top: `nothing needs you` or `2 need you`. Six keys:

```
1 2 3   open that session
n       start a session
x       stop a session, or close a done one
c       change the config and the session's models
s       toggle solo on the session's row
esc     leave
```

From a seat, `ak run stop` and `ak orch stop` refuse another seat's work and say to message its owner. Your own runs and runs launched outside a seat still stop; the owner's menu and plain terminal can stop any work.

On a terminal a key acts the moment you press it, no Enter. One session is highlighted: ↑↓ (or `k` `j`, or the wheel) move it and Enter opens it. A click on a session opens it, and a click on the key line does what that key does. Whatever the pointer is over lights up, on every screen: the session or row under it takes the highlight, and a key or a mark a soft background. Nobody needs a manual: while the pointer rests on a session, its state word, a project, a usage row, any key on the key line but `esc back`, a model or a mark on `c` and `n`, an effort, or a provider or subscription, the key line says what it is in one sentence, wrapping at words without cutting it or moving the rows above. Lists leave room for the whole explanation, so hovering never scrolls the screen; the keys come back when it leaves. A usage row under it sends one glint across its bar and puts a hairline tick at the share that would be left had it been spent as fast as time passes, and the key line reads `Claude II · 68% left · resets Thu 20:00 (in 2 d 6 h) · lasts at this pace`: `runs out early at this pace`, `lasts at this pace` or `on pace` says whether the allowance lasts the week, and a spent one says nothing of pace. Two digits within half a second are one number. Esc goes back from every screen and question, and leaves this one; `q` is no key. A name or a Discord secret is typed on the same keys, so Esc cancels it at once with nothing saved. From a pipe, an empty line or the end of input goes back.

`x` is the highlighted session's. When a session is done, press `x` on it and it is closed at once: its runs, checkouts, conversation and files go with it, and the key line says `x close` while it is highlighted. Any other session asks first, under its row: `Stop <name> and everything it runs?`, with `Keep` picked until you move to `Stop`; Esc keeps it. `c` holds the highlighted session's models: its orchestrator, executors and reviewers. Picking another orchestrator moves the seat to it at once under the same name, its runs, plan and record staying, with a handover as the new one's first prompt; a model whose harness is not installed or not logged in, or whose meter is spent, is refused in one line. The roles flip with the arrow keys and Enter or a click, each flip saved to its record at once for the runs it launches next; each group keeps one model, and a choice leaving no allowed pair is refused in one line.

`c` is every model once, under its company: `orch` (`●`) marks the highlighted session's orchestrator, `exec` and `review` (`■`) mark its executors and reviewers, and `‹ xhigh ›` is the model's effort, beside a bar for each level it offers filled up to it (`▂▃▅▆█`; a model with one effort shows its word alone); on a project's heading, or with no sessions, only the effort shows. ↑↓ move between models and ←→ between those columns, the effort's too; Enter, space or a click flips a mark, Enter or space on an effort steps it up through that model's own efforts and from the highest back to the lowest, and a click on `‹` or `›` steps it down or up; a step never waits on a harness's model list. Each change is saved at once; each group keeps at least one model, and only a choice no run could start from is refused in one line. An older session without reviewers shows its worker list in both role columns; the first mark flipped writes separate lists. ← from the marks reaches a model's label, and Enter there opens its own screen: its model id picked from its harness's catalog (the effort stays if the new model takes it, else moves to the nearest it does), its effort, and `Remove`, which asks `Keep` or `Remove` and is refused for the last model. Esc goes back to its row. Its reviewing line shows finished reviews, catches, existing defects and unproven notes for that harness and model id, excluding stopped and suite runs. Under the models, `+ add a model` is three lists in one screen: a harness of a company the config has, then a model its catalog offers (one already configured is marked, and can be added at another effort), then an effort that model takes; Enter on the effort adds it, named from its label (`sonnet`, `sonnet-2`), and Esc steps back one list. `Providers` lists your providers in their colours, the pointer on Claude giving the worker token's expiry, which stands under the rows once it is 14 days away or less; ←→ choose `+ add` or `− remove`. `+ add` offers the ones agentkit ships that you have not added. Pick one with Enter or a click on `⏎ add`: ak installs a missing harness, logs it in on the terminal, and adds it as it ships with its catalog's first model. It also offers another subscription of each provider you have, by the name it will get (`ChatGPT II`): that one is logged in on the terminal and added to the provider's `accounts`, and a login that fails adds nothing. `− remove` asks `Remove <provider> and its models?`, `Keep` picked, and takes its models and its usage rows with it; the last provider stays. It also lists each subscription of a provider with several but the usual login, and `Remove Claude II?` takes only that one out of `accounts`. Removing never deletes a login: while its harness still accepts it, `+ add` offers a removed subscription, or a removed provider's usual login, as `Use <email>` (or the name its usage row had), and puts it back with no login step. A provider that lists `accounts` has one usage row per subscription in config order, numbered in roman numerals (`Claude I`, `Claude II`), each with its week's bar and its 5-hour window (`5h 40% left`, or `5h spent until 14:00` once spent). `Discord` shows who a card pings and where it goes, `@acme-owner · webhook …a1B2c3`: the name Discord gave that user id on the last delivered card (the id's last 4 digits until one has) and the webhook's last 6 characters, never more of it; Enter runs it (its two secrets are the only typing left). `Version` is agentkit's commit and its date, and does nothing. Esc goes back.

A session is one of three things, and nothing else:

```
! needs you   it asked you something, or it cannot go on without you
● working     a run of its own is going, or a turn is, or a session it waits on works
✓ done        it said so, and the row carries its summary
```

The word moves when the session's harness starts or ends a turn or asks something: at once on the session's own two-line tmux bar, which opens with the word and says who orchestrates (`● working  ak-verification  opus orchestrates   tasks ████░░░░ 4/8`), with the question or summary and `Ctrl-b m  menu` on the line under it, and within two seconds on an open menu. Runs update it at each step, round and ending, waiting at most one second for tmux; the next tick or step retries.

Notices with no state in the harness's manifest leave the last hook fact alone: a running turn stays working, and an ended turn stays at its prompt.

Press `n`, then Enter. `n` uses the same model names and provider headings as `c`, with what your last session was created with already chosen (the shipped models the first time):

```
         orch  exec  review
Claude
  fable   ○     □      □     claude · xhigh
› opus    ●     ■      ■     claude · xhigh
ChatGPT
  astra   ○     ■      ■     codex · xhigh
```

Every model has all three marks; the headings stay visible while the rows scroll. ↑↓ move between models, ←→ between roles, space or a click chooses, Enter starts from anywhere, Esc goes back. The session saves both role groups; each keeps at least one model, and only choices or starts no run could start from are refused in one line. If a role has no unspent defaults, its fallback takes another company's fresh model before the executor's company's, before the executor itself. A model whose provider is spent reads dim with `spent · resets Fri 14:00` and is never chosen for you. `n` first asks `Name:` two spaces in, with `auto` dim in the field and `esc back` below it; a bare `ak orch` asks `Name (Enter: auto):`. Type a name, or press Enter for `new`, then `new-2`: the orchestrator names it as soon as it knows the job, as briefly as possible in at most three words. To name it yourself and end auto naming, use `r` in its `Ctrl-b m` menu or `ak orch rename <name>`. The popup holds the rename confirmation and any warnings, including dry runs, until Enter or Esc. Claude's Remote Control title, Codex's thread name, Grok Build's manual session title and OpenCode's session title follow the seat's name. Muse sessions keep their own name: the installed Muse refuses `/rename` even after a turn and rejects `--name`, so ak never types a rename into Muse. Codex's index and database do not distinguish generated names from `/rename`, so Codex titles never rename the seat, even after an owner's `/rename`; use ak to rename it. ak confirms its name from the owned thread's login index and restores it if Codex replaces it after the first prompt, stopping after three unconfirmed tries until the seat's name changes; an acknowledged name is not retyped, and a mid-turn attempt without a receipt waits for the prompt before retrying. Grok waits for an empty prompt and confirms only the manual title in its own conversation; automatic titles never rename the seat. OpenCode's seat plugin sets and reads back its own session's title through the API, including new seats, ak renames and auto naming, without typing or touching drafts. OpenCode 2.0.14 gives owner and automatic titles the same field and event, so neither renames the seat; the plugin restores ak's name when either changes it. All four leave owner drafts alone. Claude waits past dialogs and drafts and counts only once it records the title (or the composer clears if its transcript is unreadable); it gives its held line Enter even when wrapped, after the third typing or a later rename, and types each name at most three times before giving up until the name changes. Superseded pending titles stay recorded as agentkit's within that conversation until the name is explicitly retaken, so a delayed title cannot rename the seat back; owner drafts are never touched. Each typed line, its brief pause and its first Enter share the seat's lock so senders cannot merge lines; confirmation waits release it. A manual rename in Claude or Grok Build renames the seat too, taking a free variant if the name is held (even its own former name); Claude's title readings resume after the last complete line, with one note that moves and is removed with its seat; title errors are logged for their seat without stopping health checks. That is all. As soon as the project is known, the orchestrator files its seat with `ak orch project <checkout>` (name or path), where it stays until filed again, and is shown what the project's other sessions have in flight (open plan lines, files their runs change); a seat never filed so is refiled by each launched run under the project most of its runs belong to, keeping its project on a tie.

After `/clear` in a Claude seat's launched pane, reopening and title changes follow its new conversation on its login. The watch tick binds older running seats to their own client pane without restarting them. If that pane is removed, restarting the seat uses its current pane. In-session `/resume` does not transfer seat ownership. Say what you want. The orchestrator asks until the goal is clear and checkable, then goes. Close the terminal.

`ak plan` lists [numbered outcomes with checks or your judgement](docs/guide.md#the-states-and-the-cards).

## While you are away

Agentkit does not stop until the work is merged, or until it truly needs you. Truly needs you means exactly two things: a question only you can answer, or a failure it has tried every way around. Everything else it handles itself: a provider running dry or down for hours, a crash, a reboot, main moving underneath, its own upgrade (the host moves only to a commit whose `tests/live.sh`, agentkit's checks that need the outside world, passed on it; a run takes the new code at its next round, saying `picked up agentkit <old>..<new>`), a reviewer that hesitates, a test budget that was too small, a stuck session.

A turn can end waiting on its job while the launcher is alive and any task is unsettled, even before the first run starts and after a seat rename. A job whose launcher is gone or whose tasks have all settled gives no wait.

A run recorded in the line to land holds no process and stays working however long it waits. Status and the menu show `waiting · 3rd in line to land on main`; only the lander moves it. Its job follows it to its ending.

Each Codex seat runs its own app server with Remote Control enabled; the pane connects over a private Unix socket. The seat trusts only the hooks agentkit installs; Codex still asks you to review other hooks. Its hooks, rulebook, launch receipt and synced name stay with that conversation. Startup waits as long as the live server needs while the seat is open; closing it during its history import leaves the next start working. The server stops when the pane exits and starts again on resume. Its remote computer and conversation use the seat name in the ChatGPT app. Resumes and account switches keep its installation; removing the seat removes its remote enrollment. If pairing is needed, one `Needs you` card gives the code and a command to refresh an expired code; only pairing or removing the seat closes that card. No daemon or separate Codex installation is needed; workers still use `codex exec`.

A session whose subscription runs out resumes its conversation on another account of the same provider whose seat login passes. Its harness's refusal is read off the seat's screen, with or without a status line under the composer. New sessions also check the login when choosing among configured accounts; accounts with only a worker token serve workers. A manual new session can open the configured usual login to sign in when none passes. If none is available during recovery, it reads `needs you` with the reset time and recovers when usage returns. A refilled account keeps its login without another auth check; without a proven conversation id, the seat continues in place. Opening it to look keeps recovery active; drafts, questions and closed seats are left alone, and idle prompts stay idle. Every provider's subscriptions work for seats, workers and meters; another one is added and removed on the Providers screen of `c`. Credits bought beside a subscription count as usage left: once its window is spent, ak keeps picking it for seats, workers and reviews after every subscription with window left, and its usage row says `62,469 credits left`. ak never spends a usage-limit reset by itself, and one held adds nothing to what it counts as usage left. Every Claude worker turn refreshes its account's session and weekly meters from its own stream, with no request. A billing refusal parks the worker's account and hands its round to another model, like spent usage.

The orchestrator builds, whatever the size; workers take only independent pieces that share no file with its work or each other, unless its session is solo; `s` on its menu row or `ak orch solo <session> on|off` saves that switch across restarts and model changes, refusing task launches while keeping its own PR reviews. Every change is checked by its tests and reviewed by a different model before it merges, from a different company where your model groups allow it, else by the executor's own model, marked self-reviewed; only wording you picked yourself merges on its tests alone. Session records and `[defaults]` in `config.toml` may name `reviewers = ["astra"]` beside `workers = ["opus"]`: executors come only from workers, reviewers only from reviewers, ranked by review tier then live budget. When a stalled worker turn changes provider, reviewers from providers that refused nothing go first, with refused reviewers as fallback; later picks use normal order. Past run success and speed never affect the pick. New sessions copy explicit default reviewers. Without `reviewers`, the shared worker list and legacy picks behave as before, including explicit PR reviewers outside workers. Runs show the saved launch groups in status and the preflight log and keep them through retries, handovers and PR reviews; `--exec` and `--review` cannot name a model outside a bound group. A seat's own PR joins the landing line on PASS and merges its tested tree with green checks; anyone else's asks the inbox. A task has at most three rounds: more rounds are refused before it starts, `--anyway` or not, and work its reviewer still fails after the third goes back to the orchestrator with the findings, to split or re-scope.

Every worker turn, proof replay and check runs in a bubblewrap box with empty GitHub login files and Git credential stores, and no GitHub token variables. Files, writes and network access otherwise stay the same. Every child dies when its turn or command ends, even after detaching or clearing its environment. A turn that leaves processes running is unfinished: ak logs their command lines and asks once to finish in the foreground. Loop helpers keep the run's directory marker, so separate ak homes cannot end each other's processes. The installer adds bubblewrap; `ak run` refuses at launch if this host cannot start nested boxes, naming the remedy. Workers receive the whole base commit's `AGENTS.md` body and project lessons. The lessons file's size never stops a run. A round that changes `AGENTS.md` fails its checks if the resulting body is past 8 KB, in every repository; an untouched file passes this check regardless of size.

Reviewers use `ak hand-in finding path:line "what" "why it matters" --run 'command'` (or `--quote 'lines'`), `ak hand-in follow-up` with `--run` and `--before`, then `ak hand-in done`. ak refuses missing files, invalid lines, absent quotes or evidence, and calls outside worker turns, in one sentence. A finding’s `--run` command must fail while the defect exists; exit 0 is refused with instructions to fix the proof or use `--quote`. After the turn ak replays each finding’s command in its own clean checkout, on the reviewed commit then on base with changed tests overlaid. A passing or unfinished proof on the commit is a note, as are exits 126/127. Other non-zero exits count as failures regardless of output, including missing scripts or data files. Proven defects block on changed lines or beside removals. Elsewhere a proof passing on base blocks, a failing base proof becomes a follow-up, and unfinished base proofs or exits 126/127 become notes. Quoted findings are checked again against the reviewed commit (the workspace for scratch): a missing file, invalid line or absent verbatim quote makes a note. Valid quotes block on changed lines and become notes elsewhere; without a base, every proven finding blocks. Command evidence keeps ak’s own exit status and bounded output from both commits. Only hand-in records decide a review: done means FAIL with any finding still blocking, otherwise PASS; without done the reviewer is asked once more in its session, then replaced, whatever its text says. Records survive retries and host interruptions on the same session; run.json keeps the weighed records for FAIL hand-backs. Published PR descriptions and reviews are bounded; the run retains the complete records.

Every worker rule says `[checked by ak: <test file>]` and what ak does, or `[worker judgement]`. ak commits uncommitted executor work before checks and review. Every executor and fixer turn closes with `ak hand-in done`, `ak hand-in blocked "<why>"` when the task cannot be done as written, or `ak hand-in not-needed "<why>"` when a fix run's first turn finds the defect gone or already being fixed. The closing record decides the outcome and establishes an answer regardless of the final text. Later records are refused. Reviewers cannot use blocked or not-needed; executors and fixers cannot use finding or follow-up. Without a closing record, the worker is asked once more in its session; a second turn without one proceeds as done to checks and review. The work summary is kept for result.md, including after a closing ask or restart.

A reviewer can block only with evidence: a command that fails, a reproduction, or quoted file lines showing the defect. Task reviewers may run whatever is needed to prove or dismiss a finding, except done-when commands whose output they already have, the repository's `tests:` suite (run once at landing on the commit to be merged), and checks marked deferred. Unknown task front-matter keys are refused before a receipt is written, naming the key and accepted keys in one line. Optional task `files:` lines list comma-separated Git pathspecs; changes outside them fail the gate and override reviewer PASS. Heavy suites start when live CPU and memory fit one more, or none run; a pinned `max_gates` caps suites without `AK_SHARD`. When a whole suite takes more than two minutes, ak starts one run per repository and line in its session to split it. A suite line that reads `AK_SHARD=k/N` runs its 1-based share, or everything when unset: ak sizes concurrent pieces from live headroom, the run's memory cap and measured cost, and retries red pieces alone. A round runs only the task's done-when commands and review. The full suite runs once at landing on the commit to be merged; a failure goes to the landing fixers. Agentkit’s own suite splits its checks and remaining test files across `AK_SHARD=k/N` (1-based), keeping dependent checks together and pieces in separate sandboxes; unset or `1/1` runs everything. The tmux safety guard runs in every piece. Its gate rejects test files that report no cases and Python imports outside the standard library and repository. Its file pool grows with live memory, past the core count for waiting files, and pauses starts while CPU pressure is high. Its landing suite reaches nothing beyond loopback where the host allows a network namespace, and fails on a skipped check. Its retry checks advance a test clock through the unchanged backoff schedule; `tests/live.sh` runs the checks that need the outside world (real models, GitHub, Discord, live meters, the shared browser and user systemd) before a host takes new agentkit code and when a harness upgrades. Its check 3 is `python3 tests/check_harness_contract.py [harness]`: every installed adapter with a login proves prompt delivery, `ak hand-in done`, final output and session recall, using the model and effort in its own manifest. A separate live Claude check proves events arrive before its result and the returned files match that result. Scratch and `--no-merge` runs execute every task check in each round, including `# once` and explicit suite lines; the declared suite is not added. `ak run status` and the result say where each check ran. Outside a landing line, a failing command parks on a red target only if it passes on the old target base of the last head whose checks and review passed; landing re-reviews that skip the suite keep that head. An unchanged base needs no second probe. A command failing on both different commits goes to the branch's fixer. Probes leave nothing behind outside a temporary directory. Scratch reviewers keep the deliverable workspace read-only. Repository reviewers, including reviewers of others' PRs, use a temporary copy with separate Git refs and no push remote. Only regular files and links are copied, into writable directories. Cleanup repairs read-only directories in that copy. Unreadable paths and other file types are skipped with a WARN naming the path; snapshot errors are also recorded in the patch. After every reviewer turn, retries included, ak saves any edits, new files or commits to `round-N/reviewer-changes.patch`, undoes them and logs a WARN naming what it restored. Files already present before review stay. Reviewers of others' PRs may run tests and commands. Follow-ups need the same severity, a command that fails on base, and `--before` naming the base, an ancestor commit (hash or ref), or verbatim lines in the named file at base. ak replays every follow-up and drops unproven ones, recording the reason and evidence in Notes. Notes appear under `## Notes` in result.md and the PR body and start no fix run. Only blocking findings, with ak’s proof outputs, go to the fixer. Only the final passing review's follow-up list, plus checks that passed only on re-run with their `flaky:` evidence, goes into `run.json` and the PR description; no shared follow-up file is read or written. Flaky excerpts compare lines with numbers, hex ids and absolute paths masked, and name a file in the run directory holding the whole failed output. A fixer uses `ak hand-in dispute path:line "why it is wrong" --run COMMAND` or `--quote LINES` for a blocking finding handed to its turn, and fixes every undisputed finding. Disputes are refused in review and first executor turns, for other locations, for commands that do not exit 0, or for quotes absent from the named file. ak gives the next reviewer each dispute beside its finding with ak’s own proof output. The reviewer upholds it by handing the finding in again, weighed normally, and drops it by not doing so. Dropped findings and their disputes appear under `## Disputes` in result.md.

A check stopped for silence or its ceiling names the last output and the commands still running, with their elapsed times. A failing done-when after a clean rebase gets up to three landing fixer rounds without spending task rounds. Landing re-review, including older saved reviews, runs at the current round even when the budget is spent: a PASS lands without spending a round; fixing a FAIL's findings spends a task round while any remain. An unreachable target parks a pending landing review as a retryable error; an exhausted conflict fixer keeps its pending review at the current round. Timed-out Git remote calls (`fetch`, `push`, `ls-remote`) and `gh` retry once after one second; checkout edits stop for cleanup, and a refused credential prompt stops at once. A PASS whose delivery stopped names `ak run merge <id>` to finish it. A delivery retry whose reviewer runs out of quota waits for the window to refill, then the tick resumes it.

When a session's run merges, its follow-ups immediately start ordinary runs of that same session, using its saved workers and the merged target branch. Each task carries the defect and evidence; an open fix at the same site in that session prevents a duplicate. The executor first checks the current target and other open runs: a defect already gone or being fixed ends with `ak hand-in not-needed "<why>"`, counted as done with no PR or review. Otherwise it adds a regression test that fails before and passes after. Once its checks pass, the loop runs its `regression.sh` on the base commit with changed tests overlaid (none when the fix changes only tests) and a fresh bytecode cache; a pass there fails the gate, and the checkout returns to HEAD. Every probe records its original checkout first; after a crash, the resumed run restores it before verifying or building. An owner-only decision ends with `ak hand-in blocked "<question>"`. The merged run's ending names the fixes it started; the session stays working until they end, and stopping or closing it stops them. Fix runs' own follow-ups work the same way. Runs without a session, scratch runs and reviews of other people's PRs start none. There is no setting or follow-up backlog.

After PASS, a writable run joins its repository’s landing line; its worker exits. The lander stacks reviewed members in join order, green deliveries first. Each pass checks as many new trees as whole suites fit side by side, front first; a tree already checked with the same commands answers at once; verdicts wake members as they come. Only a red member leaves to fix itself. The saved place and PASS survive worker stops, crashes, restarts and updates. Foreground `ak run`, `ak run resume` and `ak run merge` follow new log lines to the ending; jobs follow the record. Fork deliveries stay outside the line. Automatic `--review-pr` merges join it too: review rounds run no suite, and the lander checks their changes on top of the target and earlier members. Delivery updates the PR head to that tested tree with a lease protecting any newer seat push, then pins the merge to that head. The installed ak starts a fresh pass when membership or verdicts change, after each delivery, and from the tick. Passes and deliveries hold separate locks, so checks and merges overlap. Each pass has its own scope and the memory a landing suite needs; on supporting hosts, a test over the cap dies alone so the lander can report its failure. A stopped member leaves the line and is never woken. Members conflicting with the target tip wake to fix at once; conflicts only with earlier members wait. A woken member skips the slot queue, count cap and CPU gate but never the memory gate, `land` ahead of `fix`. It delivers only when its integrated tree matches the lander’s tested tree; a changed tree keeps its place. When the first stack fails and the target tree has no recorded pass, the lander checks the bare target’s own suite once. A red target gets one repair first; every other member keeps its place, unblamed, while the repair holds that tree. A PR gets no repair and waits on none: its seat is handed the target's failure, and its next head is checked on its own, so one that mends the target lands. A merged repair or `not needed` ending lets the line check the target again. A passing target leaves that member to fix itself. A task's red verdict or failed required PR check uses the landing fixers and re-review without a task round, then rejoins at the back. A PR's red verdict goes back to its seat as findings; the seat's next push gets review and rejoins the same line. A failed re-review ends with its findings; a fourth red hands back the last failure. Merges carry `Suite-Passed-Tree: <tree sha>` when the declared `tests:` suite passed on the delivered tree, so CI can skip a repeat on byte-identical code. If GitHub's default merge body cannot be read, ak merges without the trailer and CI runs as usual.

## New features in live projects

A hobby project ships straight to live. The first time a new feature comes up in a project, the orchestrator asks once whether it has real users, and the answer goes into the front matter of its `AGENTS.md`: `users: none` or `users: real`. In a `users: real` project a new feature merges round by round but stays hidden behind the project's own switch, on only for you until you turn it on for everyone; the reviewer fails a round that shows it to anyone else. A switch on for everyone for more than 14 days comes out of the code. The project names the one command that lists and flips its switches in the same front matter, `features: <command>`, which answers `<command> list` and `<command> set <id> you|everyone on|off`. The `ak` menu then lists the project whether or not a session sits in it, as `ACME · 2 hidden features`, and Enter on that heading opens its switches, `you` and `everyone` for each feature, flipped with the arrow keys and Enter; the project's own owner page flips the same ones.

## Hearing back

One Discord card when a session needs you. It waits 60 seconds; an attached terminal only suppresses it, or closes a sent card as `Answered`, if it has had input since the episode began. A terminal left untouched still gets the card. One when the whole job is done. Two words and the session name; a Codex pairing card also carries the exact pairing step, nothing else. Never for a session you closed yourself, never twice for the same done, and never after an upgrade for anything that stood before it. Open the host, press the session's number, read, answer. Your next prompt answers its question in the pane or over Remote Control, even after a rename: its card reads `Answered` and hand-backs can arrive again. Recording the answer runs in the background, so your prompt never waits for a notification. Only a prompt handled in the seat's own pane counts; slash commands, messages from sessions or tasks, and prompts from other panes answer nothing. Watcher alerts keep their own recovery rules. A hand-made tmux session with no interactive agent in it, such as a watcher loop running only ak workers and their descendants, has no row, card or count; its old card closes on the next tick, as for a session that is gone. The card of one you stop or close reads `Answered` at once.

Claude question dialogs stay `needs you` even during an open turn or while a message from another session is queued below them. Queued messages are never unsent drafts; text you type in the composer still is, with or without a status line under it.

## Never needed

Choosing a project. Editing config. Merging. Cleaning up: a stopped session leaves only its stop mark and locks until a daily pass takes them, and that pass takes every checkout (including landing checkouts left by a crash), seat file and harness trust entry nothing uses any more. Restarting anything. Reading a manual. The whole help fits on one screen.

The collector also removes your `/tmp` entries after two days without changes and ended Claude sessions' scratch folders after one day. A repository's `TMPDIR` directly under `/var/tmp` is collected the same way; any other value is skipped. Dot entries, `tmux-*`, `systemd-private-*`, other users' files and paths held open or used as a working directory stay. Both modification and inode-change times count toward age. Claude's live process records protect its current conversations; a client without a matching record keeps all scratch. Hidden process handles are inspected read-only with the host's noninteractive `sudo`; if that inspection fails, `/tmp` cleanup waits. `ak run gc --dry-run` previews removals; automatic removals appear in `~/.agentkit/state/gc.log`.

## Plugins

A model is a few lines in `~/.agentkit/config.toml`, or press `c` and add one. Every model can orchestrate and work; `n` starts from what the last session was created with. A harness is two files under `adapters/`, and says which models it runs and the efforts each takes (`adapters/<h>.sh models`); `ak doctor` names a model set to an effort it does not take. Claude Code, Codex, Muse, Grok Build, OpenCode and Google's Antigravity CLI (`gemini`) come wired in. One provider is enough to start: a harness that is not installed or not logged in is never picked, one model left reviews its own work, marked self-reviewed, and `ak run` refuses in one sentence when no worker can run; groups spanning two providers allow review by a different company.
